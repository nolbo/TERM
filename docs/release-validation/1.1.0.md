# 1.1.0 출시 검증 기록

작성일: 2026-10-20. 사용자가 정식 릴리즈와 프리릴리즈의 배포를 모두 요청했다. 배포 소스는 공유 dev 이력의 `6999b7acbed44a77f16e2a131e0251d807a79201`이며, 두 채널은 같은 소스·기본 버전을 사용한다. `main` 브랜치를 변경하거나 이력을 재작성하지 않고 수동 채널 게시를 사용한다.

## 버전과 변경 범위

비교 기준은 두 채널의 직전 `1.0.0` 소스 `f000f37425f149b3bee51106b7d952e8fb0a8e4e`다. 선택적인 AVF 앱 전용 공유 폴더와 게스트 업데이트·이미지 전환·복원 추가에 MINOR를 적용했다. 첫 실행 화면·업데이트 표시·예전 공유 폴더 메뉴 정리도 포함한다. 기존 데이터·백업 호환성·Native와 Userspace Linux의 무특권 경로, 패키지 ID·서명 키·공유 versionCode 정책은 유지한다. 사용자용 안내는 [1.1.0 패치 노트](../release-notes/1.1.0.md)에 있다.

## 검사와 CI

- 로컬 업데이트 도구 Python 테스트 49개와 이미지 Python 테스트 70개가 통과했다. `git diff --check`도 통과했다.
- 첫 정식 실행 [39392775513](https://github.com/nolbo/TERM/actions/runs/39392775513)은 Gradle 검사 이후 이미지 Python 테스트에서 실패했다. x86 CI의 `apt-mark`가 ARM64 fixture를 `term-fixture:arm64`로 출력했기 때문이다. 테스트의 격리된 APT 설정에 guest architecture를 명시했다. 제품·게스트 소스나 승인 이미지는 변경하지 않았다. 같은 소스의 첫 Preview 실행은 취소했다.
- 두 번째 정식 실행 [39393630187](https://github.com/nolbo/TERM/actions/runs/39393630187)은 포트 전달 요청·응답 이후 종료 검사에서 `SocketException`으로 실패했다. 닫히는 리스너에 접속하는 경쟁 대신 해당 포트 재바인딩으로 자원 해제를 검증하도록 테스트만 수정했다. 요청 반쪽 닫기·응답·연결 및 리스너 예산 검사는 유지한다. 같은 소스의 Preview는 취소했다.
- 로컬의 포트 전달 집중 Gradle 검사는 필요한 SDK platform 37.0·build-tools 36.0.0 및 라이선스 부재로 테스트 실행 전 실패했다. 도구를 추가 설치하지 않고 CI에서 검증한다.
- 최종 정식 [39394372991](https://github.com/nolbo/TERM/actions/runs/39394372991)과 Preview [39394375956](https://github.com/nolbo/TERM/actions/runs/39394375956)는 모두 성공했다. 두 실행에서 `:android-app:assembleDebug :android-app:testDebugUnitTest :android-runtime:testDebugUnitTest :image:test`, 이미지 Python 70개·업데이트 Python 49개, USB host safety gate, `:android-app:assembleRelease`, 서명·Rootless·승인 카탈로그 확인 및 게시가 통과했다. 로컬 SDK 제한을 CI 검증으로 보완했으며, 물리 USB나 기기 AVF 검증으로 해석하지 않는다.

| Ubuntu | `avf-ubuntu-20261020-r4` | `14f73c0b68eb55140aac9ff8381e8455e9d0d928b9f6bdad908bfd311282f3dc` | `64de80bb80ea134296b66bca78b97ca182045907` |

세 공개 이미지의 `manifest.properties`, `catalog.properties`, `provenance.json`, `SHA256SUMS`를 인증 없이 다운로드하고 승인 핀·메타데이터 체크섬·제작 이력·공유 폴더 normal-boot 기록을 기존 검증기로 대조했다. 세 manifest 모두 `maintenanceVersion=1`이며 제작 소스는 배포 소스의 조상이다. provenance는 각각 두 번의 normal-systemd 부팅과 RPC·패키지 초기화 포트 통과, 두 번째 부팅의 private-share 읽기·쓰기 및 owner-loss 통과를 기록한다.

Debian 제작 이후 게스트·프로토콜·제작 스크립트 변경은 없다. Ubuntu의 후속 변경은 공유 검사 완료 기록 대기 수정뿐이다. Arch의 후속 변경은 같은 검사 수정과 Debian·Ubuntu에만 적용되는 APT 캐시 조회 옵션이며 Arch 명령은 동일하다. 따라서 필요한 게스트 변경이 모두 포함된 기존 승인 이미지를 재사용한다. 이전 이미지 게시·승인에서 수행한 전체 산출물 검증은 재사용하며 이번에 대용량 이미지 전체를 다시 다운로드하거나 부팅하지 않았다. 이 근거를 실제 Android AVF 검증으로 확대하지 않는다.

## 공개 산출물과 기기

두 공개 APK·`update.json`·한국어 노트를 GitHub 다운로드 URL에서 인증 없이 받았다. APK의 패키지·런처 이름·provider authorities·버전과 매니페스트의 채널·소스·크기·SHA-256이 일치한다. 기존 인증서 핀 `7f639e70cc1969415beab27cfb10db6d10bf553b1f956a2f9d68d55ebf3785ba`의 서명 검증, 승인 이미지 카탈로그의 바이트 단위 일치와 고정 Rootless engine·loader·DSO 대조가 통과했다. 공개 한국어 노트도 배포 소스의 채널 노트와 일치한다.

| 채널 | 공개 버전 | APK 바이트 | APK SHA-256 |
| --- | --- | ---: | --- |
| 정식 TERM | `1.1.0+main.1000087.6999b7acbed4` | 15594744 | `fff5f39f82669def6fe9995275569df180d4c10800c9045fc64fc85fdacdc3f9` |
| TERM Preview | `1.1.0+dev.1000088.6999b7acbed4` | 15594768 | `66d61f9b3ce89b6a26a5971ff27696b5b9c328834023073f9ba19a79df8524a9` |

정식 [main-6999b7a](https://github.com/nolbo/TERM/releases/tag/main-6999b7acbed44a77f16e2a131e0251d807a79201)는 prerelease=false이고 GitHub stable latest다. [dev-6999b7a](https://github.com/nolbo/TERM/releases/tag/dev-6999b7acbed44a77f16e2a131e0251d807a79201)는 prerelease=true이며 `dev-latest/update.json`은 해당 불변 릴리즈의 매니페스트와 같다. 두 불변 태그의 소스 SHA도 위 배포 소스와 일치한다. 원격 main은 배포 전과 같은 `6b7207f64a22c74677951f71c62868de7122ec0d`다.

로컬 ARM64용 AAPT2 래퍼는 누락된 x86 로더 때문에 실행되지 않아, 이미 설치된 호스트 기본 `aapt2`와 `apksigner`로 대체했다. debug용 고정 클래스 검사를 release APK에 추가 적용했을 때 최적화 가능한 직접 호출 helper `AospAvfRuntime`이 없다는 결과가 나왔다. 제품 코드는 바꾸지 않고 release에 필요한 실제 `AospAvfPlatformDriver`·`TerminalApplication` 존재와 compile-only Android VM API 부재를 별도로 확인했다. CI의 debug APK 드라이버 검사는 그대로 통과했고 release 서명·카탈로그 검사도 통과했다.

API 35 ARM64 redroid에 공개 Preview APK를 새로 설치했다. Android MCP의 기본 monkey 시작은 실패했으나 APK의 시작 Activity를 명시한 실행은 성공했다. Replicant의 시작 버튼 텍스트 선택은 Compose 부모·자식의 중복 매치로 실패해 관찰된 버튼 좌표로 수정했다. 첫 실행 화면에서 시작해 알림 권한 없이 Native 세션을 만들고 `echo TERM_RELEASE_1_1_OK`를 입력했다. 화면에서 출력과 셸 프롬프트 복귀를 확인했으며 크래시 조회는 0건이었다. 기존 `dev.terminal.app`의 버전·갱신 시각은 전후 동일하다. 검증 세션은 종료했고 Preview는 별도 설치 상태로 남겼다. 기존 앱 교체나 실제 서명 업데이트 보존 검증을 한 것은 아니다.

한국어 노트는 [정식 불변 기록](../release-notes/main-6999b7acbed44a77f16e2a131e0251d807a79201.md)과 [Preview 불변 기록](../release-notes/dev-6999b7acbed44a77f16e2a131e0251d807a79201.md)에도 보관한다. 원시 근거는 공개 CI 로그와 로컬 `/tmp/term-1.1-release/`의 채널별 verification-summary·APK 검사 로그·publication-summary·image-verification·device-validation이다. APK·스크린샷·기기 식별자는 커밋하지 않는다.

MCP는 GitHub 연결 앱으로 공개 저장소·권한 정보를 확인했고 Android로 기기·패키지·설치·시작·크래시를, Replicant로 화면 조작·Native 입출력을 확인했다. Jev는 출시 준비 및 최종 변경·완료 근거를 보조 검토했다. 초기 준비 검토는 아직 없던 최종 CI 근거와 이미지 메타데이터 증거 표현의 부족을 지적했으며 실제 최종 CI·공개 산출물 검증으로 보완했다. Context7은 외부 API 변경이 없어 사용하지 않았다.

최종 Jev는 배포·CI·공개 APK·안내에 관한 완료 주장 네 개를 모두 verified(신뢰도 0.97~1.00)로 판단했다. 변경 검토는 test_gap 신뢰도 0.31, safe_to_apply 0.50으로 자동 승인하지 않았다. 이를 통과 판정으로 바꾸지 않는다. 두 테스트 수정이 제품 동작을 바꾸지 않고 기존 전송·자원 예산 검사를 유지하는지 직접 검토했으며, 최종 CI 통과와 아래 기기 검증 한계를 구분해 배포 근거로 사용했다. Jev 결과는 보조 근거이며 실제 검사나 미실행 기기 검증을 대신하지 않는다.

## 검증 한계

Android MCP가 확인한 실행 대상은 API 35 ARM64 redroid 한 대다. 최소 API 31·최신 지원 API·일반 물리 기기의 Rootless 새 설치·패키지 사용, 이전 서명 APK 위 정식 업데이트와 데이터 보존, 실제 소유 프로세스 죽음의 종단 간 검증은 이번에 수행하지 않는다. 이전 1.0.0 기록의 미검증 범위를 이번 배포로 통과 처리하지 않는다.

실제 특권 Android AVF의 부팅·vsock·공유 파일 I/O·네트워크·게스트 관리 부팅·중단 복구·이미지 복원 및 물리 USB/iPhone은 미검증이다. 기존 설치 앱과 환경은 자동 교체하지 않는다. 새 AVF 기능은 지원 카탈로그를 가진 앱에서 사용자가 환경 업데이트 또는 새 설치를 명시적으로 선택해야 한다.
