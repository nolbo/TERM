# 1.3.1 출시 검증 기록

작성일: 2026-10-22. 1.3.0 배포 후 사용자가 Ubuntu 전체 이미지 업데이트 중 `/etc/group` 설정 충돌을 보고했다. 패키지 설치는 완료됐고 기존 환경을 보존한 채 설정 병합에서 중단됐다. 사용자가 제공한 그룹 차이는 `_ssh:x:102:`와 `docker:x:103:` 두 항목의 추가다. 기존 공개 Ubuntu 이미지에는 `_ssh:x:102:`가 다른 위치에 이미 있으며 GID 103은 다른 그룹에 사용되지 않았다. 줄 순서와 독립적인 그룹 추가를 전체 파일 충돌로 처리한 경우에 해당한다.

## 원인과 구현

전체 파일 단위의 세 방향 비교는 기존 환경의 사용자 그룹 추가와 새 이미지의 독립적인 그룹 추가도 충돌로 처리했다. 기존 코드에 합성 fixture를 적용해 동일한 `Configuration conflict; old environment retained: /etc/group` 오류를 재현했다. 수정은 passwd/group/shadow/gshadow를 계정 이름·필드별로 병합하고 멤버십 추가·삭제를 함께 반영한다. UID/GID 충돌·재배정, 삭제와 편집의 충돌, 비밀번호 필드 충돌, shadow 불일치와 심볼릭 링크는 거부한다. 계정 번호를 자동 변경하거나 파일 소유자를 추정하지 않는다. 네 데이터베이스를 모두 검증한 뒤 후보 파일만 교체하고 원본 세대는 수정하지 않는다. 생성된 백업 파일과 잠금 파일은 이전 사용자 설정으로 재생하지 않는다.

공유 dev의 기존 두 UI 커밋 `a6b0cc3`, `43572b4`를 보존했다. 이미지 수정·패치 노트 소스는 `6dd30332eacdb0c64bee00259fee62eaaf64d2a1`이며 정상 fast-forward로 origin/dev에 반영했다. main 병합이나 이력 재작성은 없다.

## 현재 검증

- `python3 -m unittest discover -s tests/image -p 'test_*.py'`: 114개 통과. 신규 계정 병합 12개를 포함한다.
- 기존 코드에 동일 fixture 적용: `/etc/group` 실패 재현. 수정된 코드는 독립 그룹 추가·멤버십 삭제 및 추가·계정 추가·권한 유지·원본 보존·반복 적용을 검증했다.
- 기존 공개 Ubuntu system.img에서 네 계정 데이터베이스를 읽기 전용으로 추출한 fixture: 사용자 23개, 기본 그룹 49개를 유지하면서 양쪽 그룹 추가 병합 성공. 실제 Android 관리 부팅 검증으로 간주하지 않는다.
- 사용자 제공 `_ssh` 102·`docker` 103 및 줄 순서 차이를 반영한 회귀 테스트를 추가한 뒤 계정/업데이트 테스트 21개가 통과했다. 기존 공개 Ubuntu 파일에 이 변경을 적용한 재현도 기존 코드에서 실패하고 수정 코드에서 원본을 보존하며 성공했다. 이미지 제작 이후 추가된 것은 이 회귀 테스트와 문서이며 게스트 구현은 동일하다.
- `git diff --check`, `sh -n image/scripts/image-update-selftest`: 통과.
- Jev 게이트는 자동 승인을 하지 않았다(safe_to_apply 0.12, correctness confidence 0.35, test_gap confidence 0.28). 구체적인 결함이나 모순은 제시하지 않았고 네 주장을 unsupported로 분류했다. 이를 통과 판정으로 사용하지 않는다. 실제 테스트 결과와 소스 검토를 근거로 하며 이미지 부팅 및 사용자 AVF 검증 한계를 별도로 기록한다.
- GitHub 연결 도구의 워크플로별 실행 목록 URL은 INVALID_ARGUMENT으로 거부돼 gh 실행 목록으로 대체했다. 작업 상태·로그는 지원되는 GitHub MCP 도구로 조회한다.

## 이미지 및 앱 배포

세 이미지 모두 카탈로그 포함 Debug APK 검증과 공식 공개 작업까지 성공했다. 공개 릴리즈는 draft=false, prerelease=true이며 알림 작업은 notify=false로 생략됐다. 각 공개 manifest와 다섯 압축 이미지의 인증 없는 전체 다운로드·해시 검증을 마친 후 `verify-avf-release.py --approve`로 세 핀을 기본 카탈로그에 반영했다. 미공개 후보의 메타데이터만으로 승격하지 않았다.

최종 앱 소스는 `b0c6e5c1fa6eec8ce515c4e8396836e89e5415e6`이며 정상 fast-forward push를 확인했다. Preview [39720580375](https://github.com/nolbo/TERM/actions/runs/39720580375), 정식 [39720582958](https://github.com/nolbo/TERM/actions/runs/39720582958)의 서명·공개 CI가 모두 성공했다. 두 채널의 실제 태그 패치 노트도 공유 dev 이력에 보관한다. 공개 APK 검증까지 완료했으며 main 브랜치 병합은 수행하지 않았다.

두 APK의 서명 인증서는 기존과 같은 `7f639e70cc1969415beab27cfb10db6d10bf553b1f956a2f9d68d55ebf3785ba`다. 인증 없는 공개 APK·메타데이터·한국어 패치 노트 다운로드를 검증했다. 서명, 크기와 해시, 정확한 세 이미지 승인 카탈로그, Rootless·Native payload, AVF 드라이버, 패키지 ID·런처·provider authorities 및 non-debuggable 설정이 일치했다. 공개 패치 노트는 소스와 같으며 dev-latest와 정식 latest의 update.json도 각 불변 릴리즈의 메타데이터와 일치한다. Release는 최적화하므로 보존된 AVF 플랫폼 드라이버와 Application 클래스 및 Android VM API 미포함을 검사했고, 비최적화 런타임 클래스 이름 검사는 Debug CI에서 수행했다.

Android MCP로 기존 `1.3.0+dev.1000091.3a54d874955c` 위에 replace 설치했다. 최초 설치 시각은 유지됐고 Replicant로 Native·Debian·Ubuntu·Arch 프로필 보존을 확인했다. 설치 전에 Native 홈에 만든 전용 시험 파일을 새 버전의 Native 세션에서 읽어 `TERM_131_UPDATE_PRESERVED`를 확인한 뒤 시험 파일을 제거하고 세션을 종료했다. 앱 데이터 보존·실행 검증이며 AVF 게스트 전환 검증은 아니다.

정식 패키지와 같은 ID로 과거 Debug 서명 앱이 시험 기기에 설치돼 있어 정식판의 덮어 설치는 검증할 수 없다. 서명이 다른 기존 앱을 삭제하지 않는다. 실제 AVF를 지원하는 연결 대상도 없으므로 사용자 Ubuntu 환경의 이미지 전환 재시도는 별도 확인이 필요하다.

GitHub MCP는 CI 작업·로그·공개 릴리즈 상태 확인에, Android MCP와 Replicant는 실제 APK 교체·앱 시작·프로필 및 Native 파일 보존 확인에 사용했다. 외부 API 변경이 없어 Context7은 사용하지 않았다. 전체 이미지 전환에서는 시험용 Docker 데이터 경로 `/.droid/state/term-redroid-test`가 자동 이전 대상에 포함되지 않는다. 원본 세대에 남지만 새 환경에서 사용하려면 별도 백업·복원이 필요하므로 사용자 안내에 이를 명시했다.

## 호환 Debug APK

표준 `:android-app:assembleDebug :android-runtime:testDebugUnitTest :image:test` 검사가 42초에 성공했다(185 tasks, 41 executed). 기존 ARM64 호스트의 AAPT2와 검증된 Rootless payload 경로를 명령 인자로 사용했으며 호스트 설정 파일은 변경하지 않았다. APK의 정확한 세 이미지 카탈로그·AVF 드라이버·Rootless·Native payload 검증도 통과했다.

공개 [호환 Debug APK](https://github.com/nolbo/TERM/releases/download/avf-ubuntu-maintenance-20261022-r1/TERM-Debug-AVF-maintenance-20261022.apk)는 `1.3.1+dev.214805092.b0c6e5c1fa6e-debug`, 68,413,060바이트이며 SHA-256은 `6d5d7c8bce1980ba445260f6e28a2fa3e70a78d4c88220e5a2045fa8dfc9face`다. 서명 인증서 `2ea8b58dfd147494e0810949c75db554519efa55b762cb7014119f9abdafb7e0`가 이전 호환 Debug와 같고 버전 코드가 증가했다. 인증 없는 공개 APK 다운로드와 SHA-256 파일이 로컬 검증 산출물과 일치한다.

Android MCP로 기존 `214791050` 위에 replace 설치해 성공했고, 설치 전 만든 전용 시험 파일의 내용이 보존됨을 확인한 뒤 제거했다. 앱 시작과 Replicant의 화면 요소 확인도 통과했다. 첫 UI 조회는 로딩 중 빈 결과였고 준비 후 재조회에서 정상 화면이 확인됐다. 연결 대상은 Android 15·4KB·SELinux Disabled이며 AVF가 없다. 따라서 이 결과를 실제 AVF 이미지 전환 검증으로 해석하지 않는다. 사용자에게 공개 Debug APK와 재시도 방법을 전달했으며, 실패했던 AVF Ubuntu 환경에서의 최종 결과는 아직 받지 못했다.
