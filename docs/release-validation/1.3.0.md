# 1.3.0 출시 검증 기록

작성일: 2026-10-22. 사용자가 이미지와 정식 릴리즈·프리릴리즈 배포를 요청했다. 공유 dev 소스 `3a54d874955cfd76db9841848fd2b613c7b23d4c`에서 두 앱 채널을 게시했다. main 병합과 이력 재작성 없이 정식·Preview 서명 CI와 공개 APK 검증을 완료했다. 기기 업데이트 검증은 Preview에 한정한다.

## 범위와 버전

직전 정식 `1.2.0+main.1000090.d3df0da5a6af`와 Preview `1.2.0+dev.1000089.d3df0da5a6af`의 공통 소스 `d3df0da5a6af8eadab38d205e57e8cd9f1637405` 이후 전체 공유 dev 범위를 검토했다. 세 AVF 배포판의 컨테이너 실행 기능을 추가하므로 MINOR 1.3.0을 적용한다. 그 외 변경은 커널/이미지 생산·검증, 선택 설치 ReDroid 도구와 테스트 안내, Debug APK 호환 안내다. Native·Rootless 앱 동작과 기존 사용자 데이터는 유지한다. 수동 앱 배포의 Discord 알림은 명시적인 notify=true에만 실행되도록 하며 이번 배포는 false를 사용한다.

세 제작 커밋은 공유 dev의 조상이다. 최종 커널 설정과 커널/모듈 일치, 두 차례 오프라인 컨테이너 기능 검사와 두 차례 일반 systemd/vsock 부팅·공유 폴더/owner-loss 기록은 [커널 검증 기록](../AVF_CONTAINER_KERNEL.md)에 있다. Ubuntu 제작 이후 게스트 관련 차이는 Debian/Arch의 필수 번들 적용, Arch 의존성 추가와 공통 도구 존재 검사다. Ubuntu는 이미 iproute2·iptables와 두 backend 기능을 포함하며 관련 부팅 검사를 통과했다. 후속 ReDroid 실행 도구는 선택 다운로드하므로 기존 게스트 디스크에 넣을 변경이 아니다. Debian/Arch 제작 이후 게스트 실행 파일·설정·커널 입력은 변경되지 않았으며 후속 변경은 문서와 이번 앱 배포 설정이다. 따라서 세 공개 산출물의 동일 바이트를 재사용한다.

기본 카탈로그 승격은 verify-avf-release.py의 제작 커밋·manifest 핀·컨테이너/공유 부팅 요구와 인증 없는 전체 이미지 다운로드 검사를 통과했다. 각 배포판의 공개 manifest와 다섯 압축 이미지의 해시를 확인한 뒤 기본 핀을 원자적으로 병합했다. 두 최종 공개 서명 APK 모두 이 기본 카탈로그를 정확히 포함한다. 기존 설치 환경을 자동 교체하지 않으며 새 커널 적용은 새 환경 또는 전체 이미지 전환이 필요하다.

## 검증 상태와 한계

앞선 구현에서 이미지 Python 102개와 저장소 표준 Debug/runtime/image 검사가 통과했다. Debian·Arch 이미지 CI 및 통합 Debug APK의 공개 다운로드·카탈로그·서명, Android 15 테스트 대상의 덮어쓰기 설치와 시험 데이터 보존도 확인했다. 이전 Debug 결과를 이번 1.3.0 서명 APK의 게시/설치 검증으로 간주하지 않고 아래와 같이 별도로 검증했다.

실제 Ubuntu AVF의 ReDroid Running=true, sys.boot_completed=1, activity/package/display와 Settings 정상 결과는 사용자가 제공했다. Debian·Arch 실제 AVF, LXC 워크로드, 외부 네트워크 전달, 장시간 안정성과 재부팅, Android AVF 이미지 전환/복원은 미검증이다. 연결된 Android 테스트 대상은 AVF를 제공하지 않는다. 실제 16 KiB Android·다른 API·SELinux enforcing·물리 USB 등의 기존 제한도 유지한다. 이를 CI/QEMU 통과로 확대하지 않는다.

## Preview 서명 CI와 공개 검증

Preview [39703453861](https://github.com/nolbo/TERM/actions/runs/39703453861)가 성공했다. Debug/app/runtime/image Gradle 검사와 Python 이미지 102개·업데이트 53개, USB host safety gate, Release 서명 빌드와 고정 인증서·카탈로그·Rootless·Native 검사 및 게시가 통과했다. 알림 작업은 notify=false로 skipped다. 수동 배포 선택과 서명/게시 경로는 유지했고 main 브랜치는 변경하지 않았다.

공개 `TERM.apk`, `update.json`, 한국어 노트를 인증 없이 내려받아 APK 크기·SHA-256·버전·패키지·런처 이름·provider authorities, 기존 배포 인증서와 정확한 새 AVF 기본 카탈로그를 확인했다. Rootless engine/loader/DSO와 Native ELF/runtime/license 검사도 통과했다. 한국어 노트는 배포 소스의 채널 노트와 바이트 단위로 같고, dev-latest 포인터는 불변 릴리즈 매니페스트와 같다. 대응 Native 소스 묶음은 직전 배포와 같은 SHA-256 `7965254907ce2ae4950100d4629b380b7334e1a20bdf2df4f992f37f778615ed`로 게시됐다.

검사 도구의 초기 실패 두 건을 구분한다. 원본 AospAvfRuntime 클래스 이름을 요구하는 verify-driver-apk.py를 최적화된 Release에 적용하면 해당 이름이 없어 실패한다. 직전 1.2.0 공개 Release에도 같은 현상이 있으며 이번 CI의 Debug 드라이버 검사는 통과했다. 두 Release 모두 AospAvfPlatformDriver·TerminalApplication 정의를 포함하고 플랫폼 API 선언을 내장하지 않는 것을 확인했다. Release 설정은 코드 최적화를 사용한다. 이를 실제 AVF 실행의 검증으로 해석하지 않는다. 또한 aapt2의 launcher label은 빈 값이고 application label TERM Preview를 상속한다. 명시된 activity label을 요구하던 임시 검증 코드를 실제 상속 규칙에 맞춰 수정하고 패키지·provider·공개 포인터 검사를 마쳤다. 실제 앱/이미지의 실패로 처리하지 않았으며 제품 검사를 제거하거나 소스를 변경하지 않았다.

## Preview 기기 업데이트

Android 15 ARM64 4 KiB 테스트 대상에서 기존 공개 서명 Preview 1.2.0 위에 새 공개 APK를 replace 설치했다. firstInstallTime, Native HOME의 작업 소유 시험 파일, Native·Debian·Ubuntu·Arch 프로필 목록이 보존됐고 새 Native 세션에서 시험 파일을 읽었다. 시험 파일과 새 시험 세션을 정리했다. 설치된 Linux 환경 내부 파일 전체의 무결성을 확인한 것은 아니다.

이 대상의 dev.terminal.app은 다른 Android Debug 인증서로 서명된 과거 0.2.0 개발 빌드다. 정식 APK를 덮어쓰거나 기존 앱을 제거하지 않았고 전후 버전·설치 시각이 그대로임을 확인했다. 따라서 정식 APK의 서명/패키징 검증과 기기의 정식 업데이트 검증을 구분한다. 대상은 AVF를 지원하지 않으며 실제 16 KiB/SELinux enforcing/다른 API 검증을 대신하지 않는다.

Android MCP의 기본 monkey 실행이 물리 키 오류를 반환하여 공개 SetupActivity를 직접 실행했다. release 앱의 run-as는 non-debuggable로 거부되어 자체 Native 세션에서 시험 파일을 만들고 읽었다. Replicant UI 조회 한 번은 전환 중 노드가 없었고, 전환 후 목록을 확인했다. Android 입력 경로에서 printf의 %s가 공백으로 처리되어 생성된 작업 소유 시험 파일만 echo로 다시 썼다. 이 도구 호출 문제들은 저장소의 기능 수정으로 확장하지 않았다.

## 정식 CI와 최종 공개 산출물

정식 [39703481977](https://github.com/nolbo/TERM/actions/runs/39703481977)도 성공했다. Preview와 같은 소스에서 `:android-app:assembleDebug :android-app:testDebugUnitTest :android-runtime:testDebugUnitTest :image:test`, 이미지 Python 102개·업데이트 Python 53개, USB host safety gate, `:android-app:assembleRelease` 및 서명/런타임/카탈로그 검사와 게시가 통과했다. 두 채널 모두 알림 작업은 skipped이며 Discord 메시지를 보내지 않았다. 로컬 준비 단계의 업데이트 Python 53개, 워크플로 YAML·10개 shell 블록 문법과 diff 검사도 통과했다.

정식 APK의 공개 다운로드와 정확한 크기·해시·서명, 패키지·런처·provider authorities, 기본 AVF 카탈로그, Rootless·Native payload 검사를 통과했다. 두 채널의 한국어 노트는 배포 소스와 같고 stable latest 및 dev-latest의 공개 update.json은 각 불변 릴리즈 매니페스트와 바이트 단위로 일치한다. 정식은 prerelease=false로 stable latest이며 Preview는 prerelease=true다.

직전 공개 1.2.0 대비 정식 APK는 20바이트, Preview는 16바이트 증가해 각각 약 26.82 MB다. 커널과 Docker/LXC/ReDroid 이미지는 APK에 내장하지 않는다. 공개 이미지 세 개는 기존 불변 태그·바이트를 유지하며 필수 자산과 갱신된 한국어 노트가 공개되어 있고 커밋된 노트와 일치함을 확인했다.

정식 [main-3a54d87](https://github.com/nolbo/TERM/releases/tag/main-3a54d874955cfd76db9841848fd2b613c7b23d4c), Preview [dev-3a54d87](https://github.com/nolbo/TERM/releases/tag/dev-3a54d874955cfd76db9841848fd2b613c7b23d4c)를 게시했다. 한국어 노트는 [1.3.0](../release-notes/1.3.0.md), [정식 불변 기록](../release-notes/main-3a54d874955cfd76db9841848fd2b613c7b23d4c.md), [Preview 불변 기록](../release-notes/dev-3a54d874955cfd76db9841848fd2b613c7b23d4c.md)에 있다. 실제 릴리즈 ID별 노트도 게시 전에 공유 dev에 커밋·push했다.

GitHub MCP로 CI 단계·로그와 공개 릴리즈/자산 상태를, Android MCP와 Replicant로 Preview 설치·실행·시험 데이터/프로필 보존을 확인했다. GitHub 연결 도구에 dispatch·바이너리 게시 기능이 없어 기존 gh 경로를 사용했다. 외부 API 변경이 없어 context7은 사용하지 않았다. 공개 APK/메타데이터·도구 검사·기기 관찰 기록은 로컬 `/tmp/term-1.3-release/`에 보관하며 APK·개인 데이터·기기 식별자를 커밋하지 않는다.

최종 Jev gate는 배포·이미지 승격·Preview 업데이트의 완료 주장 세 개를 모두 verified(신뢰도 0.88~0.98), verification=auto로 반환했다. 변경 검토는 test_gap 신뢰도 0.32와 safe_to_apply=0.35로 전체 action=escalate였다. 구체적인 모순이나 unsupported 주장은 없었다. 실제 CI·공개 APK 검사와 명시된 기기 검증 범위를 직접 대조했으며, 부족한 실제 AVF/정식 설치 범위를 통과 처리하지 않았다. Jev 결과를 자동 승인이나 실제 시험의 대체로 사용하지 않았다.
