# 1.3.0 출시 검증 기록

작성일: 2026-10-22. 사용자가 이미지와 정식 릴리즈·프리릴리즈 배포를 요청했다. 공유 dev 이력에서 두 앱 채널을 준비하며 main 병합과 이력 재작성은 하지 않는다. 이 준비 시점에는 서명 CI와 최종 공개 APK 검증이 남아 있다.

## 범위와 버전

직전 정식 `1.2.0+main.1000090.d3df0da5a6af`와 Preview `1.2.0+dev.1000089.d3df0da5a6af`의 공통 소스 `d3df0da5a6af8eadab38d205e57e8cd9f1637405` 이후 전체 공유 dev 범위를 검토했다. 세 AVF 배포판의 컨테이너 실행 기능을 추가하므로 MINOR 1.3.0을 적용한다. 그 외 변경은 커널/이미지 생산·검증, 선택 설치 ReDroid 도구와 테스트 안내, Debug APK 호환 안내다. Native·Rootless 앱 동작과 기존 사용자 데이터는 유지한다. 수동 앱 배포의 Discord 알림은 명시적인 notify=true에만 실행되도록 하며 이번 배포는 false를 사용한다.

세 제작 커밋은 공유 dev의 조상이다. 최종 커널 설정과 커널/모듈 일치, 두 차례 오프라인 컨테이너 기능 검사와 두 차례 일반 systemd/vsock 부팅·공유 폴더/owner-loss 기록은 [커널 검증 기록](../AVF_CONTAINER_KERNEL.md)에 있다. Ubuntu 제작 이후 게스트 관련 차이는 Debian/Arch의 필수 번들 적용, Arch 의존성 추가와 공통 도구 존재 검사다. Ubuntu는 이미 iproute2·iptables와 두 backend 기능을 포함하며 관련 부팅 검사를 통과했다. 후속 ReDroid 실행 도구는 선택 다운로드하므로 기존 게스트 디스크에 넣을 변경이 아니다. Debian/Arch 제작 이후에는 문서만 변경됐다. 따라서 세 공개 산출물의 동일 바이트를 재사용한다.

기본 카탈로그 승격은 verify-avf-release.py의 제작 커밋·manifest 핀·컨테이너/공유 부팅 요구와 인증 없는 전체 이미지 다운로드 검사를 사용한다. 각 배포판의 공개 manifest와 다섯 압축 이미지의 해시를 확인한 뒤 기본 핀을 원자적으로 병합한다. 최종 서명 APK에는 이 기본 카탈로그가 정확히 포함되어야 한다. 기존 설치 환경을 자동 교체하지 않으며 새 커널 적용은 새 환경 또는 전체 이미지 전환이 필요하다.

## 검증 상태와 한계

앞선 구현에서 이미지 Python 102개와 저장소 표준 Debug/runtime/image 검사가 통과했다. Debian·Arch 이미지 CI 및 통합 Debug APK의 공개 다운로드·카탈로그·서명, Android 15 테스트 대상의 덮어쓰기 설치와 시험 데이터 보존도 확인했다. 이것은 이번 1.3.0 서명 APK의 게시/설치 검증을 대신하지 않는다. 두 채널의 서명 CI와 공개 산출물 검사는 완료 후 여기에 기록한다.

실제 Ubuntu AVF의 ReDroid Running=true, sys.boot_completed=1, activity/package/display와 Settings 정상 결과는 사용자가 제공했다. Debian·Arch 실제 AVF, LXC 워크로드, 외부 네트워크 전달, 장시간 안정성과 재부팅, Android AVF 이미지 전환/복원은 미검증이다. 연결된 Android 테스트 대상은 AVF를 제공하지 않는다. 실제 16 KiB Android·다른 API·SELinux enforcing·물리 USB 등의 기존 제한도 유지한다. 이를 CI/QEMU 통과로 확대하지 않는다.
