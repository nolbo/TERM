# 2.0.0 출시 검증 기록

준비일: 2026-10-28. 사용자의 정식 릴리즈 공개 요청에 따라 공유 dev 이력에서 TERM을 공개한다. main 병합·이력 재작성·Preview 게시 없이 정식만 dispatch하며, 별도 메시지 전송 요청이 없어 앱·이미지 notify=false를 사용한다.

## 비교 범위와 버전

인증 없는 공개 update.json으로 직전 정식 1.6.0+main.1000104.1f8552ee455c와 소스 1f8552ee455c9902d696857e7910205063e8ee34를 확인했다. 이후 0ded715, 079d0a5, 6b48643, 6042b83, f59ae12, 611bf78, 9877bf8, 786a2dc 전체를 포함한다. AVF 공유 디렉토리·Android 저장소 내보내기와 폴더별 VM 복사를 제거하므로 지원 기능 호환성이 바뀌며 MAJOR 2.0.0을 적용한다. origin/dev를 fetch한 결과 로컬 여덟 커밋만 앞서 있고 분기는 없다. 준비·카탈로그·검증 기록은 [skip ci]로 커밋해 의도하지 않은 Preview 자동 게시를 막는다.

## 필수 이미지와 커널

현재 승인 resources-20261025-r1의 제작 소스 145662485bd7be693cbce830e75e22debf427e76 이후 게스트 세션 정리·출력 처리와 공유 서비스 제거가 변경됐다. Debian·Ubuntu·Arch의 unshared-20261028-r1 이미지를 새로 제작·검증·공개하고 승인 카탈로그를 정식 APK에 포함해야 한다. 기존 설치 디스크는 자동 교체하지 않는다.

검증 명령만 추가된 avf_kernel.py를 라이브러리와 verify-avf-kernel.py CLI로 분리해 커널 제작 레시피를 보존한다. 검증된 kernel producer 39715151260의 실제 커널 해시와 현재 승인 핀을 대조하고 입력이 동일한 번들을 재사용한다. 캐시 검증의 파일·해시·설정 검사와 실패 처리는 유지한다. sourceSha256은 기존에 검증한 Google 원본 765cec51cd3e16ea1745b7ac8f9b3816d21ab3ed069bea355a59e3ade6bdfc41을 지정한다.

## 검증 범위

앞선 탭 수정에서 Android 15 기기 회귀 네 개가 통과했고 표준 debug·runtime·image 검사도 성공했다. 이번 배포는 CLI 회귀와 이미지·앱 공식 CI 및 실제 공개 파일 검증으로 완료한다. 실제 특권 AVF의 공유 제거 후 중지·재시작, 장시간 백그라운드·Doze·CPU/열 측정은 ReDroid UI 또는 QEMU/Linux 이미지 부팅으로 입증할 수 없다. 그 기기 전용 검증은 미실시로 보고한다.

## 제작 시작과 추가 검증

제작 소스 `5e9992ad9a27650db5adf9b84e57131e9150e12f`를 origin/dev에 정상 fast-forward로 푸시하고 원격 일치를 확인했다. 이미지 3종의 불변 `unshared-20261028-r1` 태그를 같은 커밋에 고정했다. kernel producer `39715151260`의 전체 워크플로 성공, 미만료 산출물, 현재와 동일한 제작 레시피와 기존 승인 커널 SHA-256 `fa4f0fc22c316d24a417e5620e915c626ab246ef5c190b557d38c136955357ee`를 확인했다.

커널 CLI 회귀 14개, 전체 Python 이미지 회귀 129개와 게스트 droid-sessiond Rust 회귀 30개가 통과했다. Python의 첫 실행은 샌드박스 로컬 소켓 권한 때문에 실패했고 권한을 허용한 동일 검사에서 통과했다. Cargo는 PATH에 없어 기존 설치된 절대 경로를 사용했다. 추가 Gradle의 protocol 56개·AVF runtime 25개는 실패 없이 완료했으며 AVF compat의 제거된 공유 테스트는 NO-SOURCE다. 이 검사는 CI의 앱·런타임·이미지·터미널 모듈 검사와 별개다.

공식 제작 실행은 [Debian 40608464115](https://github.com/nolbo/TERM/actions/runs/40608464115), [Ubuntu 40608468172](https://github.com/nolbo/TERM/actions/runs/40608468172), [Arch 40608471130](https://github.com/nolbo/TERM/actions/runs/40608471130)이다. Arch 첫 시도는 rootfs 패키지 구성 완료 후 임시 GPG 소켓 정리 중 `FileNotFoundError: S.gpg-agent.ssh`로 중단됐다. 공개 이전 단계이며 GitHub MCP로 실패 작업만 같은 소스·입력에서 재실행했다. 최종 결과는 이후 검증 기록에 남긴다.

Android 15 ReDroid에서 `:android-runtime:connectedDebugAndroidTest`를 두 클래스에 한정해 실행했고 두 개 모두 통과했다. `RuntimeWakeControllerDeviceTest`는 실제 화면 꺼짐과 Android wake lock 콜백으로 갱신 중 보호 유지·정지 후 재획득 방지를 검증했다. `AvfExitReconciliationDeviceTest`는 Android 소켓에서 종료 이벤트와 다른 세션 출력 512개가 동시에 처리돼도 읽기·목록 갱신이 멈추지 않음을 검증했다. 후자는 실제 특권 AVF VM 검증을 대체하지 않는다. Replicant의 연결 테스트 필터가 지원하지 않는 `--tests`를 추가하는 기존 도구 제약 때문에 정확한 instrumentation 클래스 인자를 지원하는 Gradle 명령을 사용했다.

Jev의 준비 변경 gate는 두 검증 주장을 verified로 분류했지만 커널 레시피 동일성과 테스트 범위의 신뢰도가 낮아 자동 수락하지 않았다. 구체적인 모순이나 결함은 제시하지 않았다. 대응으로 이전 kernel producer와 현재 제작 커밋 사이의 레시피 diff가 비어 있음을 직접 확인했고, CLI 회귀가 정상 번들 성공뿐 아니라 손상된 initrd의 실패도 검증함을 확인했다. Jev는 보조 근거로만 사용한다.

## 이미지 공개와 승인

세 제작 실행 모두 image·apk·publish 작업이 최종 성공했다. 각 이미지의 오프라인 부팅·영속성·컨테이너 검사와 정상 systemd 부팅 두 번의 session-resume 검증이 통과했다. notify-release는 요청 범위에 맞게 건너뛰었다. Arch의 최초 임시 소켓 정리 실패는 같은 소스 재실행에서 해소됐다. Ubuntu APK 첫 검사에서는 기존 `AvfPortObserverTest.disconnectReconnectAndOwnerStopOnlyReleaseTheirOwnListeners`의 3초 대기가 시간 초과했다. 해당 구현과 테스트가 이번 범위에서 변경되지 않았음을 확인하고 실패한 APK 작업만 재실행해 통과했다. 이미 검증된 이미지 바이트는 재제작하거나 변경하지 않았다.

공식 제작 로그에서 얻은 manifest 핀은 다음과 같다. 공개 메타데이터의 제작 커밋·Google 원본 해시·동일 커널·정상 부팅 근거와 비교하며, 공유 기능 필드가 없고 sessionResumeVersion·maintenanceVersion이 각각 1임을 검사한다.

공개 이후 인증 없는 HTTPS로 세 배포판의 메타데이터와 압축 산출물 다섯 개씩을 모두 다시 내려받았다. `verify-avf-release.py`의 `verify_directory`·`approve`로 위 제작 핀, 압축 파일과 압축 해제된 원본의 크기·SHA-256을 검증했고 모두 통과했다. 그 검증 결과로 생성한 카탈로그만 `image/catalog-approved.properties`로 승격했다. `--require-normal-boot`·`--require-container-kernel`에 해당하는 검사를 모두 적용했으며 기존 설치 환경은 변경하지 않았다.
