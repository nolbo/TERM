# 1.6.0 출시 검증 기록

준비일: 2026-10-25. 사용자의 정식 릴리즈 배포 요청에 따라 공유 dev 이력에서 TERM을 공개한다. main 병합·이력 재작성·Preview 게시를 수행하지 않는다. 별도 메시지 전송 요청이 없어 앱·이미지 Discord 알림은 notify=false로 지정한다.

## 비교 범위와 버전

인증 없는 공개 update.json에서 직전 정식 `1.5.3+main.1000103.d14ea689c3b0`와 소스 `d14ea689c3b03d28d63e5889e58f0cd662d83eb3`를 확인했다. 이후 `7bb76af`, `29b7b7a`, `559f760`, `5c17404` 전체를 포함한다. 자동 메모리와 게스트 자원 진단이 사용자 기능 추가이므로 MINOR 1.6.0을 적용한다. origin/dev를 fetch하고 원격에 없는 네 커밋만 로컬에 있으며 분기되지 않았음을 확인했다. 준비·카탈로그 승격 커밋은 [skip ci]로 불필요한 Preview 자동 게시를 막고 정식만 명시적으로 dispatch한다.

## 필수 이미지

기존 승인 recovery-r4의 제작 소스 `c2c0f06d5175d94c8002ac3efd8eb03f5560ad22` 이후 guest/droid-sessiond, guest/droid-port-agent, image/scripts/private-share-transport.py가 변경됐다. 따라서 Debian·Ubuntu·Arch resources-20261025-r1을 제작·공개하고 정식 APK의 승인 카탈로그를 대조해야 한다. kernel producer `39715151260`의 성공과 현재 레시피 동일성을 확인했다. 이미지별 두 정상 부팅·공유/복구 검사·카탈로그 포함 APK 게이트·인증 없는 전체 공개 다운로드 검증을 완료한 뒤 카탈로그를 승격한다. 설치된 사용자 환경을 자동 교체하지 않는다.

## 기존 구현 검증과 제한

배포 준비 직전 동일 구현의 정규 debug 빌드·런타임·이미지 검증이 통과했다. 런타임은 464개 중 463개 통과·1개 skip, 이미지는 69개 통과다. 세션 완료 알림 기기 테스트 두 개가 최종 통과했고 두 번째는 POST_NOTIFICATION app-op을 ignore로 지정해 핸들 확장·복원, 포커스 억제, 화면 재생성, 설정 화면 복귀와 끌 때 제거를 확인했다. Replicant로 완료 메시지 화면과 일반 핸들 탭 확장을 확인했다. 임시 app-op은 원래 default로 복구했다. 앞선 테스트 도구의 언어·화면 재생성 대기·Activity 흐름을 조정한 최종 결과이며, 실패한 중간 실행을 통과로 계산하지 않았다.

Jev는 구현 완료 주장 5개를 verified로 판단했으나 테스트 범위 확신 0.40·safe_to_apply 0.54로 자동 통과를 내리지 않았고 구체적 결함을 제시하지 않았다. 로컬 diff와 실제 검사 결과로 검토했으며 Jev를 증명으로 취급하지 않는다. 실제 연결 기기는 AVF를 지원하지 않는 ReDroid15 ARM64이므로 실제 특권 AVF의 CPU·열·장시간 백그라운드·Doze 검증은 수행하지 않았다. protocol·AVF 모듈의 로컬 검사, 정식 CI의 앱·런타임·이미지·Python/USB·release lint·서명 검사와 공개 파일 검증은 완료 후 기록한다.

## 준비 커밋과 추가 검증

제작 소스 `145662485bd7be693cbce830e75e22debf427e76`를 origin/dev에 정상 fast-forward로 푸시하고 원격 SHA가 일치함을 확인했다. Debian·Ubuntu·Arch의 resources-20261025-r1 불변 태그를 같은 소스에 고정했다. sourceSha256 `765cec51cd3e16ea1745b7ac8f9b3816d21ab3ed069bea355a59e3ade6bdfc41`과 검증된 kernel producer `39715151260`을 지정했다.

업데이트 회귀 검사 53개, protocol 56개, AVF 모듈 44개가 모두 통과했다. 동일 구현의 기기 추가 검사 4개도 통과했다. 두 단축키 검사는 가로 도구 전환·세로 스크롤 잠금과 이동 중 반복 입력·해제 후 입력 종료를, AVF CPU 검사는 저장·취소 동작을, 게스트 메모리 검사는 앱 PSS와 별도의 측정 기준 표시를 확인했다. 실제 AVF VM을 시작한 검사는 아니다. 앞선 세션 완료 검사 두 개와 합쳐 이번 구현에 대해 확인한 기기 검사는 6개다.

이미지 CI는 [Debian 40160748486](https://github.com/nolbo/TERM/actions/runs/40160748486), [Ubuntu 40160750126](https://github.com/nolbo/TERM/actions/runs/40160750126), [Arch 40160751718](https://github.com/nolbo/TERM/actions/runs/40160751718)로 실행했다. 세 작업 모두 image·apk·publish가 success이며, 동일한 검증 커널을 재사용해 kernel 작업은 skipped였다. 별도 알림은 의도대로 skipped다.

인증 없는 공개 다운로드로 APK 크기·해시, 패키지·TERM 라벨·minSdk 31·채널별 Provider authority, 기존 공식 서명과 새 승인 카탈로그의 정확한 ZIP 바이트 일치를 확인했다. 커밋된 1.6.0 노트, main-latest, 공개 RELEASE_NOTES.ko.md와 실제 게시 본문이 일치한다. 실제 태그 이름의 한국어 노트 파일도 같은 내용으로 보관했다. GitHub stable latest 발견 manifest는 같은 1.6.0이며 draft=false·prerelease=false다. Preview 발견 포인터는 1.5.2+dev.1000101.00c592c96aba로 유지됨을 대조했다.

최종 Jev 사실 검증은 공개 버전/CI·APK 해시와 서명/카탈로그·세 이미지의 출처/부팅 근거·발견 포인터에 관한 4개 주장을 모두 verified로 판정했다(확신 0.94–1.00). 이는 실제 검사·서명·다운로드 대조를 대체하는 증명이 아니며 앞선 구현 gate의 낮은 테스트 범위 확신과 구분한다.

GitHub MCP는 커널·이미지·앱 CI의 작업과 단계 및 공개 검증 로그 확인에 사용했다. 제공하지 않는 dispatch·새 태그·릴리즈 조회는 gh로 실행했고 실제 공개 파일은 인증 없이 내려받았다. Android MCP로 추가 기기 검사 4개를 실행했으며 앞선 완료 알림 검사 2개와 Replicant의 화면·핸들 동작 확인을 재사용했다. Context7은 앞선 구현 때 월간 한도로 사용할 수 없었으며 이번 배포 준비에는 새 외부 API를 도입하지 않았다. 이미지 제작의 상세 로그는 수십 MiB여서 단계 상태와 작은 게시 검증 로그를 사용했고 전체 로그를 반복해서 읽지 않았다.

실제 특권 AVF 기기 설치·장시간 백그라운드·Doze·CPU/열 측정과 기존 정식 앱의 기기 내 업데이트 설치는 수행하지 않았다. 자동 QEMU/Linux 이미지 검사와 ReDroid UI 검사를 그 검증으로 확대하지 않는다. 기존 사용자 환경을 자동 교체하지 않으며 게스트 변경은 작업 저장·세션 종료·VM 중지 후 호환 구성요소 업데이트 또는 지원 전체 이미지 전환으로 적용한다. 게시·업데이트·이미지 검증에 남은 일반 TODO는 없다.
