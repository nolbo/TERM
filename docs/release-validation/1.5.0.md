# 1.5.0 출시 검증 기록

작성일: 2026-10-24. 사용자는 AVF 복구·진단 로그 작업 이후 정식 TERM과 TERM Preview 두 채널의 배포를 요청했다. 공유 dev 이력을 유지하고 main 병합이나 이력 재작성은 수행하지 않는다. Discord 알림은 요청되지 않아 수동 게시의 notify=false를 유지한다.

## 범위와 이미지 판단

직전 두 채널의 소스는 `9f9381c5637e2569c0716ec323faebc8ca235581`이다. 이후 AVF 소켓 복구, 기본 실행방식에 독립적인 AVF 재연결, UI 콜백 지연 격리, 진단 로그 기록 옵션과 하단 툴바의 열람·검색·복사·삭제를 포함한다. 새 사용자 기능에 MINOR 1.5.0을 적용한다.

필요한 세 배포판의 recovery-r3 이미지는 이미 제작·공개·기본 승인되었다. 제작 소스 `e730980a2ef77b50edf0101c2647932bbd2d1807` 이후 `guest`, `image/scripts`, `image/src/main`에는 변경이 없다. 후속 로그 기록과 UI는 새 게스트 지원이 필요하지 않으므로 새 이미지를 제작하지 않는다. 기존 카탈로그를 두 APK에 정확히 포함하는 것이 배포 조건이다.

GitHub MCP에서 Ubuntu [40048874959](https://github.com/nolbo/TERM/actions/runs/40048874959), Debian [40048879959](https://github.com/nolbo/TERM/actions/runs/40048879959), Arch [40048884964](https://github.com/nolbo/TERM/actions/runs/40048884964)의 성공과 동일 제작 소스를 재확인했다. 최초 제작 시의 두 정상 부팅·공유와 세션 복구·공개 산출물 전체 다운로드 검증은 [복구 이미지 기록](avf-recovery-20261024.md)에 보존한다. 동일 산출물의 전체 다운로드를 반복하지 않고 공개 메타데이터와 승인 핀을 확인한다.

세 공개 이미지의 catalog·manifest·provenance·SHA256SUMS를 무인증으로 내려받아 기존 검증기의 metadata-only 검사에 통과했다. 현재 승인 manifest 핀, 제작 소스, 커널 `fa4f0fc22c316d24a417e5620e915c626ab246ef5c190b557d38c136955357ee`, 두 차례 정상 부팅의 세션 복구와 공유 재연결·가드 증거가 일치하며 `shareBrokerVersion=2`, `sessionResumeVersion=1`을 확인했다. 전체 이미지 다운로드 재검증이나 실제 기기 검증으로 확대해 주장하지 않는다.

## 사전 검증

현재 세션에서 정규 `:android-app:assembleDebug :android-runtime:testDebugUnitTest :image:test`와 앱·AVF 모듈 단위 테스트가 통과했다. 최종 툴바·IME 변경 후 앱과 테스트 APK 빌드가 통과했고, Android MCP의 AvfLogsUiTest 2개가 기록 설정 복원·검색 결과 복사·VM 프로세스 미생성·새로고침·삭제 확인과 취소·빈 목록의 비활성 상태를 검증했다. Replicant로 실제 하단 툴바와 키보드 위 배치를 확인했다.

ARM64 호스트의 기존 AAPT2 실행 경로를 임시 Gradle override로 지정했으며 저장소의 호스트 설정이나 SDK 버전은 바꾸지 않았다. 게시 CI는 JDK 17 검증과 JDK 21 release lint·서명, Rootless·Native 도구·USB 안전 게이트 및 승인 카탈로그 검사를 수행해야 한다.

## 검증 범위

연결된 기기는 ReDroid15 ARM64이며 실제 AVF 지원 기기는 없다. Android UI/JNI 검사와 QEMU 이미지 부팅을 특권 Android AVF의 실제 vsock·백그라운드·전원 정책·장시간 복구 검증으로 간주하지 않는다. 설치된 환경과 디스크를 자동 교체하지 않는다. 새 앱의 공식 배포와 실제 기기 설치는 구분한다.

## 배포 결과

배포 준비 중. 두 채널의 실제 CI·공개 APK·manifest·서명·카탈로그·패치 노트와 게시 상태 검증 후 이 절을 확정한다.
