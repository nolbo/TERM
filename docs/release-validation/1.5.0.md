# 1.5.0 출시 검증 기록

작성일: 2026-10-24. 사용자는 AVF 복구·진단 로그 작업 이후 정식 TERM과 TERM Preview 두 채널의 배포를 요청했다. 공유 dev 이력을 유지하고 main 병합이나 이력 재작성은 수행하지 않는다. Discord 알림은 요청되지 않아 수동 게시의 notify=false를 유지한다.

## 범위와 이미지 판단

직전 두 채널의 소스는 `9f9381c5637e2569c0716ec323faebc8ca235581`이다. 이후 AVF 소켓 복구, 기본 실행방식에 독립적인 AVF 재연결, UI 콜백 지연 격리, 진단 로그 기록 옵션과 하단 툴바의 열람·검색·복사·삭제를 포함한다. 새 사용자 기능에 MINOR 1.5.0을 적용한다.

필요한 세 배포판의 recovery-r3 이미지는 이미 제작·공개·기본 승인되었다. 제작 소스 `e730980a2ef77b50edf0101c2647932bbd2d1807` 이후 `guest`, `image/scripts`, `image/src/main`에는 변경이 없다. 후속 로그 기록과 UI는 새 게스트 지원이 필요하지 않으므로 새 이미지를 제작하지 않는다. 기존 카탈로그를 두 APK에 정확히 포함하는 것이 배포 조건이다.

GitHub MCP에서 Ubuntu [40048874959](https://github.com/nolbo/TERM/actions/runs/40048874959), Debian [40048879959](https://github.com/nolbo/TERM/actions/runs/40048879959), Arch [40048884964](https://github.com/nolbo/TERM/actions/runs/40048884964)의 성공과 동일 제작 소스를 재확인했다. 최초 제작 시의 두 정상 부팅·공유와 세션 복구·공개 산출물 전체 다운로드 검증은 [복구 이미지 기록](avf-recovery-20261024.md)에 보존한다. 동일 산출물의 전체 다운로드를 반복하지 않고 공개 메타데이터와 승인 핀을 확인한다.

세 공개 이미지의 catalog·manifest·provenance·SHA256SUMS를 무인증으로 내려받아 기존 검증기의 metadata-only 검사에 통과했다. 현재 승인 manifest 핀, 제작 소스, 커널 `fa4f0fc22c316d24a417e5620e915c626ab246ef5c190b557d38c136955357ee`, 두 차례 정상 부팅의 세션 복구와 공유 재연결·가드 증거가 일치하며 `shareBrokerVersion=2`, `sessionResumeVersion=1`을 확인했다. 전체 이미지 다운로드 재검증이나 실제 기기 검증으로 확대해 주장하지 않는다.

## 사전 검증

현재 세션에서 정규 `:android-app:assembleDebug :android-runtime:testDebugUnitTest :image:test`와 앱·AVF 모듈 단위 테스트가 통과했다. 최종 툴바·IME 변경 후 앱과 테스트 APK 빌드가 통과했고, Android MCP의 AvfLogsUiTest 2개가 기록 설정 복원·검색 결과 복사·VM 프로세스 미생성·새로고침·삭제 확인과 취소·빈 목록의 비활성 상태를 검증했다. Replicant로 실제 하단 툴바와 키보드 위 배치를 확인했다.

ARM64 호스트의 기존 AAPT2 실행 경로를 임시 Gradle override로 지정했으며 저장소의 호스트 설정이나 SDK 버전은 바꾸지 않았다. 게시 CI는 JDK 17 검증과 JDK 21 release lint·서명, Rootless·Native 도구·USB 안전 게이트 및 승인 카탈로그 검사를 수행해야 한다.

## 검증 범위

연결된 기기는 ReDroid15 ARM64이며 실제 AVF 지원 기기는 없다. Android UI/JNI 검사와 QEMU 이미지 부팅을 특권 Android AVF의 실제 vsock·백그라운드·전원 정책·장시간 복구 검증으로 간주하지 않는다. 설치된 환경과 디스크를 자동 교체하지 않는다. 새 앱의 공식 배포와 실제 기기 설치는 구분한다.

## 배포 결과

배포 소스는 `d1a3e17cde135adea6f0d1e41bb424348bf6af9e`다. origin/dev와의 동일성을 확인한 뒤 수동 채널 게시를 실행했다.

TERM Preview의 공식 실행 [40056035661](https://github.com/nolbo/TERM/actions/runs/40056035661)이 성공했다. [dev-d1a3e17cde135adea6f0d1e41bb424348bf6af9e](https://github.com/nolbo/TERM/releases/tag/dev-d1a3e17cde135adea6f0d1e41bb424348bf6af9e)는 `draft=false`, `prerelease=true`다. 공개 버전은 `1.5.0+dev.1000097.d1a3e17cde13`(1000097)이다.

무인증 공개 다운로드에서 Preview APK의 26,873,272 bytes와 SHA-256 `cbe68f02f13ff1b3bf25fcf281029ddf7bde401a122d6c8b00328f3871293aa2`를 확인했다. 실제 APK의 패키지는 `dev.terminal.app.prerelease`, 앱 이름은 TERM Preview, minSdk는 31이며 두 Provider authority도 Preview 패키지에 속한다. 기존 공식 인증서 `7f639e70cc1969415beab27cfb10db6d10bf553b1f956a2f9d68d55ebf3785ba`, 세 r3 승인 카탈로그의 정확한 바이트 일치, 커밋된 한국어 노트 및 dev-latest 발견 manifest와의 일치가 모두 확인됐다.

정식판 실행 [40056994644](https://github.com/nolbo/TERM/actions/runs/40056994644)도 같은 소스에서 성공했다. [main-d1a3e17cde135adea6f0d1e41bb424348bf6af9e](https://github.com/nolbo/TERM/releases/tag/main-d1a3e17cde135adea6f0d1e41bb424348bf6af9e)는 `draft=false`, `prerelease=false`이며 정식 latest다. 공개 버전은 `1.5.0+main.1000098.d1a3e17cde13`(1000098)이다.

정식 APK의 무인증 공개 다운로드에서 26,873,136 bytes와 SHA-256 `18d87b4a8811e3258cd4779c3e967fa4c6df6209db644e0a9adbb50961330bc4`를 확인했다. 실제 패키지는 `dev.terminal.app`, 앱 이름은 TERM, minSdk는 31이며 두 Provider authority는 정식 패키지에 속한다. 기존 공식 인증서, 세 r3 카탈로그, 한국어 노트 및 정식 latest 발견 manifest의 정확한 일치가 모두 통과했다.

두 CI 모두 정규 APK·앱/런타임/이미지 단위 테스트, Python 이미지·업데이트 검사, USB host 안전 게이트, release lint·서명, Rootless·Native CLI·AVF 드라이버 및 승인 카탈로그 검사가 통과했다. 두 공개 앱은 같은 공유 dev 소스를 사용하고 각 패키지 안에서 직전 배포보다 높은 versionCode를 갖는다. Preview는 prerelease, 정식은 stable latest로 확인했다. 서명 앱의 기기 설치나 실제 AVF 재현은 수행하지 않았다. 최종 한국어 노트는 공개 asset과 동일한 바이트로 채널별 태그 이름의 파일에도 보존한다.

최종 Jev 게이트는 두 채널 게시, 공개 APK 검증, 이미지 재사용·포함 및 실제 기기 검증 한계의 네 주장을 모두 verified로 분류했다(contradicted=0, unsupported=0). composite 0.7265·safe_to_apply 0.60과 test_gap 확신도 때문에 자동 승인되지 않았다. 실제 CI 상태·공개 다운로드·서명·카탈로그·출처 비교를 직접 재검토했고, 이를 실제 AVF 기기 검증의 대체 증거로 사용하지 않았다.

GitHub MCP로 공개 릴리스·원격 dev·CI 상태를 조회했다. workflow별 runs 경로는 연결 도구에서 거절되어 허용된 저장소 actions/runs 경로로 한 번 정정했다. 연결 도구가 지원하지 않는 workflow dispatch는 기존 Git credential을 출력하지 않는 gh 래퍼로 실행했다. 공개 파일은 인증 없이 검증했다. 로컬 검증 보조 스크립트의 SDK 디렉토리 선택과 AAPT2 minSdkVersion 출력 파싱은 현재 도구 형식에 맞춰 정정했으며 앱 소스나 SDK는 변경하지 않았다.
