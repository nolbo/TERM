# 1.2.0 출시 검증 기록

작성일: 2026-10-21. 사용자가 정식 릴리즈와 프리릴리즈를 모두 요청했다. 같은 공유 dev 소스를 두 채널로 게시하며 main 브랜치를 변경하거나 기존 이력을 재작성하지 않는다.

## 범위와 버전

직전 두 채널의 1.1.0 공통 소스 `6999b7acbed44a77f16e2a131e0251d807a79201` 이후 전체 범위를 포함한다. Native 도구·설정·진단 추가에 MINOR를 적용한다. 사용자 안내는 [1.2.0 노트](../release-notes/1.2.0.md), 구현 및 기기 검증은 [Native 검증 기록](../NATIVE_VALIDATION.md)을 따른다. 기존 설정·파일·설치 환경을 보존하며 두 앱의 패키지·서명·공유 versionCode 정책을 유지한다.

## 승인 이미지

직전 앱 배포 이후 게스트·이미지 제작 파일과 승인 카탈로그의 변경이 없고 새 호스트 기능에 추가 게스트 지원이 필요하지 않다. [1.1.0 출시 기록](1.1.0.md)의 검증된 Debian r5·Ubuntu r4·Arch r3를 재사용한다. 공개 manifest·provenance를 재대조하고 최종 서명 APK가 승인 카탈로그와 일치하는지 확인한다. 기존 설치 이미지와 환경을 자동 교체하지 않는다.

## 배포 검증 진행

릴리즈 준비 단계이며 서명 CI·공개 산출물 검증 결과는 완료 후 이 기록에 추가한다. 기존 Native 검증의 16 KiB·다른 API·SELinux enforcing, 물리 USB·SAF 및 특권 AVF 미검증 범위를 이번 배포로 통과 처리하지 않는다.

## 배포 준비 검사

업데이트 Python 시험 53개, Python 문법 검사와 `git diff --check`가 통과했다. Native 대응 소스 묶음은 7개 원본 아카이브를 lock SHA-256과 대조하고 로컬 레시피·패치·49개 Cargo 패키지 소스를 포함한다. 생성된 95,475,141바이트/2,866파일 묶음의 레시피 바이트를 원본과 확인했다. 임시 검사에서 `/target/`를 빌드 출력으로 일괄 거부한 것은 Cargo `cc`의 `src/target/*.rs` 원본 네 파일을 오탐한 것으로 확인했으며 제품/묶음 변경 없이 검사를 바로잡았다.

세 공개 이미지의 manifest·catalog·provenance·SHA256SUMS를 인증 없이 다시 다운로드했다. 승인 manifest 핀과 메타데이터 체크섬, 제작 소스의 dev 조상 관계, 두 normal-systemd 부팅 및 private-share/owner-loss 기록을 확인했다. 게스트·제작 스크립트·승인 카탈로그에 변경이 없어 대용량 이미지의 재다운로드/재제작은 하지 않는다. APK의 카탈로그 검증은 CI와 최종 공개 파일에서 수행한다. 배포 전 원격 main은 `84b06c8c41d5b9f0d3cfc63757315644e33dbaec`였다.

Jev 준비 gate는 전체 `action=escalate`, `safe_to_apply=0.39`로 자동 승인하지 않았다. CI·소스 묶음·버전 변경의 test_gap/confidence가 낮았고 대응 소스 주장을 unsupported로 반환했다. 실제 아카이브 생성/원본 대조와 Python 시험, 레시피·게시 디렉터리 연결을 직접 확인했다. 서명 CI와 공개 산출물은 아직 미완료이므로 이를 준비 단계 통과와 구분한다.
