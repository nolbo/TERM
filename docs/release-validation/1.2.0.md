# 1.2.0 출시 검증 기록

작성일: 2026-10-21. 사용자가 정식 릴리즈와 프리릴리즈를 모두 요청했다. 공유 dev 소스 `d3df0da5a6af8eadab38d205e57e8cd9f1637405`를 두 채널로 게시했다. main 브랜치를 변경하거나 기존 이력을 재작성하지 않았다.

## 범위와 버전

직전 두 채널의 1.1.0 공통 소스 `6999b7acbed44a77f16e2a131e0251d807a79201` 이후 전체 범위를 포함한다. Native 도구·설정·진단 추가에 MINOR를 적용한다. 사용자 안내는 [1.2.0 노트](../release-notes/1.2.0.md), 구현 및 기기 검증은 [Native 검증 기록](../NATIVE_VALIDATION.md)을 따른다. 기존 설정·파일·설치 환경을 보존하며 두 앱의 패키지·서명·공유 versionCode 정책을 유지한다.

## 승인 이미지

직전 앱 배포 이후 게스트·이미지 제작 파일과 승인 카탈로그의 변경이 없고 새 호스트 기능에 추가 게스트 지원이 필요하지 않다. [1.1.0 출시 기록](1.1.0.md)의 검증된 Debian r5·Ubuntu r4·Arch r3를 재사용한다. 공개 manifest·provenance를 재대조하고 최종 서명 APK가 승인 카탈로그와 일치하는지 확인한다. 기존 설치 이미지와 환경을 자동 교체하지 않는다.

## 서명 CI와 게시

Preview [39544797701](https://github.com/nolbo/TERM/actions/runs/39544797701)와 정식 [39545088950](https://github.com/nolbo/TERM/actions/runs/39545088950)가 같은 dev 소스에서 성공했다. 두 실행에서 JDK17의 `:android-app:assembleDebug :android-app:testDebugUnitTest :android-runtime:testDebugUnitTest :image:test`, 이미지 Python 70개·업데이트 Python 53개, USB host safety gate, JDK21의 `:android-app:assembleRelease`, 서명·Rootless·승인 카탈로그·새 Native APK 검사 및 게시가 통과했다. 로컬의 초기 구현 검증과 CI의 x86 NDK 빌드를 구분한다. ARM64 호스트의 재빌드 8개 ELF 동일 해시 기록을 서로 다른 호스트의 바이너리 동일성으로 확대하지 않는다.

기존 Native 검증의 16 KiB·다른 API·SELinux enforcing, 물리 USB·SAF 및 특권 AVF 미검증 범위를 이번 배포로 통과 처리하지 않는다.

## 배포 준비 검사

업데이트 Python 시험 53개, Python 문법 검사와 `git diff --check`가 통과했다. Native 대응 소스 묶음은 7개 원본 아카이브를 lock SHA-256과 대조하고 로컬 레시피·패치·49개 Cargo 패키지 소스를 포함한다. 최종 공개 묶음 95,475,142바이트/2,866파일의 레시피 바이트를 배포 커밋과 확인했다. 임시 검사에서 빌드 출력으로 오탐한 Cargo `cc`의 `src/target/*.rs` 원본 네 파일도 직접 확인했다.

세 공개 이미지의 manifest·catalog·provenance·SHA256SUMS를 인증 없이 다시 다운로드했다. 승인 manifest 핀과 메타데이터 체크섬, 제작 소스의 dev 조상 관계, 두 normal-systemd 부팅 및 private-share/owner-loss 기록을 확인했다. 게스트·제작 스크립트·승인 카탈로그에 변경이 없어 대용량 이미지의 재다운로드/재제작은 하지 않는다. APK의 카탈로그 검증도 CI와 최종 공개 파일에서 통과했다. 배포 전 원격 main은 `84b06c8c41d5b9f0d3cfc63757315644e33dbaec`였다.

Jev 준비 gate는 전체 `action=escalate`, `safe_to_apply=0.39`로 자동 승인하지 않았다. CI·소스 묶음·버전 변경의 test_gap/confidence가 낮았고 대응 소스 주장을 unsupported로 반환했다. 실제 아카이브 생성/원본 대조와 Python 시험, 레시피·게시 디렉터리 연결을 직접 확인했다. 당시 서명 CI와 공개 산출물은 미완료였으며, 이후 실제 CI·공개 파일 검사로 보완했다. Jev를 자동 승인이나 실제 시험의 대체물로 취급하지 않는다.

## 공개 산출물

두 불변 릴리즈의 APK·update.json·한국어 노트를 GitHub 공개 URL에서 인증 없이 다운로드했다. APK의 패키지·런처 이름·provider authorities·버전, update.json의 채널·소스·정확한 크기·SHA-256과 노트의 배포 커밋 원문 일치가 통과했다. 서명 인증서는 기존 `7f639e70cc1969415beab27cfb10db6d10bf553b1f956a2f9d68d55ebf3785ba`이며, APK에 포함된 승인 AVF 카탈로그·고정 Rootless engine/loader/DSO·Native ELF 8개와 runtime/라이선스 해시를 재확인했다. Native 라이선스/출처 문서는 123개다.

| 채널 | 버전 | APK 바이트 | SHA-256 |
| --- | --- | ---: | --- |
| 정식 TERM | `1.2.0+main.1000090.d3df0da5a6af` | 26,815,720 | `e36d5efaec35822ec84f84df680276275715ae17664cf9d472e7bdb3b8f76d2f` |
| TERM Preview | `1.2.0+dev.1000089.d3df0da5a6af` | 26,815,744 | `5d29de5d0c5c62ad8ea9e35450e69b07bbbbdb8d9d94b91bfc141790491c705e` |

정식 [main-d3df0da](https://github.com/nolbo/TERM/releases/tag/main-d3df0da5a6af8eadab38d205e57e8cd9f1637405)는 prerelease=false이고 GitHub stable latest다. [dev-d3df0da](https://github.com/nolbo/TERM/releases/tag/dev-d3df0da5a6af8eadab38d205e57e8cd9f1637405)는 prerelease=true다. stable `/releases/latest/download/update.json`과 Preview `dev-latest/update.json`이 각각 해당 불변 릴리즈 매니페스트와 바이트 단위로 같다. 게시 검증 시 원격 dev는 배포 소스와 일치했고 main은 배포 전 `84b06c8c41d5b9f0d3cfc63757315644e33dbaec`를 유지했다.

두 채널의 `native-cli-source.tar.gz`도 공개 URL에서 인증 없이 읽어 동일한 95,475,142바이트·SHA-256 `7965254907ce2ae4950100d4629b380b7334e1a20bdf2df4f992f37f778615ed`를 확인했다. 원본 7개 고정 SHA-256·배포 커밋의 레시피/패치·Cargo vendor 소스 49개가 포함되어 있다. APK 안에 원본 소스 아카이브를 넣지 않았다.

## 배포 APK 용량

아래 비교는 직전 **공개 서명 1.1.0 APK**와 새 공개 서명 1.2.0 APK다. [Native 구현 검증](../NATIVE_VALIDATION.md)의 같은 dev 소스 unsigned 비교와 기준이 다르다.

| 채널 | 1.1.0 바이트 | 1.2.0 바이트 | 증가 |
| --- | ---: | ---: | ---: |
| 정식 | 15,594,744 | 26,815,720 | 11,220,976 (+71.95%) |
| Preview | 15,594,768 | 26,815,744 | 11,220,976 (+71.95%) |

두 채널 모두 약 15.59 → 26.82 MB(10⁶바이트), +11.22 MB다. 공개 APK에서 압축된 추가 구성은 jq 0.29 MB, curl+CA 0.49 MB, SSH+keygen 0.52 MB, rg 1.57 MB, Vim+runtime 4.97 MB, 공용 OpenSSL 2.83 MB다. strip·비필수 프로토콜/GUI/번역/사전/도움말 제거와 공용 라이브러리 사용을 적용했다. Git 실행 파일·전용 의존성은 포함하지 않는다.

## 서명 Preview 업데이트 검증

Android 15 API35 ARM64 redroid(4 KiB, SELinux Disabled)의 기존 서명 Preview `1.1.0+dev.1000088.6999b7acbed4` 위에 **공개 APK**를 replace 설치했다. 업데이트 전 Native HOME에 만든 고유 시험 파일이 보존되었고 firstInstallTime도 유지되었다. 기존 Native·Debian·Ubuntu·Arch 프로필 목록을 확인했다. 이 검사는 설치된 Linux 환경 내부 파일 전체의 무결성 검증은 아니다.

새 Native 세션에서 보존된 marker, jq의 `1+1=2`, 내장 기본 CA를 사용한 curl의 `https://curl.se/` 다운로드, OpenSSH 10.6p1 실행, Vim의 파일 저장과 rg 정규식 검색을 확인했다. 별도의 Vim 배치 실행은 `g:syntax_on`과 `&syntax=sh`를 검사하고 정상 종료한 경우만 `VIM_RUNTIME_OK`를 출력했으며 실제 화면에서 확인했다. SSH 인증/known_hosts/포워딩·Vim IME/resize·세션 회귀의 상세 검증은 앞선 [Native 기록](../NATIVE_VALIDATION.md)을 따른다. 서명판에서 그 모든 시나리오를 반복한 것으로 보고하지 않는다.

기기 크래시는 0건이었다. 만든 시험 파일 세 개와 해당 Native 세션을 정리했다. 정식 설치 앱의 버전·갱신/최초 설치 시각은 전후 동일했으며 정식 앱을 기기에 덮어쓰지 않았다. 두 APK의 채널·서명 검증은 모두 수행했지만 기기 업데이트 검증은 Preview에 한정한다.

## MCP와 남은 검증

GitHub 연결 앱으로 공개 릴리즈·자산 메타데이터와 stable latest를 확인했다. 연결 앱에 workflow dispatch 기능이 없어 승인된 저장소의 `gh` 절차로 두 CI 실행·정상 push를 수행했다. Android MCP로 기기·설치·시작·입력을, Replicant로 UI·버전/시각·키 입력을 확인했다. MainActivity 직접 시작은 not-exported 보안 오류로 실패하여 실제 공개 launcher인 SetupActivity로 수정했다. Replicant의 셸/텍스트 메타문자 차단은 단순 명령으로 수정하고 터미널 명령 텍스트는 escaping을 지원하는 Android input_text로 입력했다. 외부 API 변경이 없어 context7을 추가 호출하지 않았다.

다른 Android/API 및 실제 16 KiB·SELinux enforcing, 기존 정식 앱의 서명 업데이트와 전체 데이터 보존, 실제 특권 AVF 부팅/공유/네트워크/관리 부팅/복구, 물리 USB·탈착식 저장소/SAF는 미검증이다. 기존 이미지는 자동 교체하지 않으며, AOSP mksh의 영구 셸 기록 제한은 사용자 노트에 안내했다. 일반 구현 TODO를 이 기기 검증 한계와 혼동하지 않는다.

최종 Jev는 완료 주장 세 개를 모두 verified(신뢰도 0.89~0.98), verification=auto로 반환했다. 변경 검토는 blast_radius 신뢰도 0, safe_to_apply=0.60으로 전체 action=escalate였다. 문서만의 최종 변경과 공개 검사 근거를 직접 대조했으며 자동 승인으로 보고하지 않는다.

한국어 노트는 [1.2.0](../release-notes/1.2.0.md), [정식 불변 기록](../release-notes/main-d3df0da5a6af8eadab38d205e57e8cd9f1637405.md), [Preview 불변 기록](../release-notes/dev-d3df0da5a6af8eadab38d205e57e8cd9f1637405.md)에 보관한다. 원시 CI·공개 APK 검사·이미지 메타데이터·기기 검증 근거는 공개 Actions 로그와 로컬 `/tmp/term-1.2-release/`에 있다. APK·기기 식별자·스크린샷은 커밋하지 않는다.
