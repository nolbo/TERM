# proc FD 디렉터리 유지 후보 — 2026-09-20

앞선 FD 호출 분석에서 발견한 readlinkat 비용을 줄이기 위해, `/proc/self/fd`를
O_PATH로 열어 두고 숫자 이름만 상대 조회하는 후보를 시험했다. `probe.c`를
faststat.c의 임시 복사본 끝에 추가하고 기존 combined DSO 옵션으로 빌드했다.
실제 fstat 구현은 바꾸지 않았으며 시험 함수만 추가했다. run.py를 기존 시험
runner의 restricted 모드 표준 입력으로 실행했다.

API 35 ARM64 redroid의 앱 UID·Ubuntu·openat2 거부 조건에서 10,000회씩 세 순서를
순환했다. 각 반복에서 조회 결과가 원래 전체 경로와 같은지도 검사했다.
초기 directory open, 최초 stat/readlink, 마지막 close는 측정 구간 밖이다.

| 후보 | 10,000회 중앙값 | 기존 대비 시간 감소 |
| --- | ---: | ---: |
| 전체 /proc/self/fd/N 경로 조회 | 16.008ms | 기준 |
| 디렉터리 FD 유지, 검증 없는 상대 조회 | 10.657ms | 33.4% |
| 매회 fstat로 FD 동일성 확인 후 상대 조회 | 15.450ms | 3.5% |

검증 없는 후보는 FD 재사용 때문에 생산 코드에 사용할 수 없다. fstat 확인도
신호 처리기·공유 FD 테이블의 동시 교체를 단독으로 해결하지 못하므로 추가 자격
확인이나 신호 차단이 필요하다. 두 번째 후보의 수치는 안전한 완성 구현의 성능이
아닌 상한 탐색이며, 세 번째도 동시성 검증까지 마친 구현이 아니다.

확인 비용을 넣으면 조회당 약 56ns만 절약했다. 이전 호출 분석의 파일당 2회 추가
조회에 적용해도 약 0.11µs에 불과하다. 전체 작은 파일 읽기의 향상률로 환산하지
않으며, 하드링크 기준과의 격차가 해결됐다고 주장하지 않는다. retained FD 수명,
fork/exec, close_range, FD 재사용 처리를 도입할 근거가 부족해 **이 후보는 미채택**이다.
다음 검토에서는 경로 조회 비용만 낮추는 접근보다 링크 분류 자체를 줄이는
저장 형식/런타임 협력을 우선한다. 파일 metadata를 무조건 캐시하는 변경은 하지 않는다.

빌드는 -Wall -Wextra -Werror로 통과했고, Android MCP의 모든 시험 호출은 경로 일치
검사를 통과했다. 시험 APK의 incremental 설치는 거부돼 streamed 설치를 사용했다.
사용자 앱과 rootfs는 변경하지 않았고, 시험 APK는 원래 bc39fb4 빌드로 복구했다.
생산 변경이 없어 Gradle 재빌드는 실행하지 않았다. 삼성 Android 17 실측도 미실행이다.
원본 수치는 [results.json](results.json), 코드와 실행 입력은 같은 디렉터리에 있다.
