# TERM 사용 가이드

**설정 → 앱 업데이트 → 업데이트 채널 → 업데이트 확인**에서 새 버전을 확인할 수 있습니다.
**정식 릴리스**는 origin/main, **개발 릴리스**는 origin/dev 갱신을 제공합니다.
채널 선택은 저장되며, 개발 릴리스에는 기능 불안정 경고를 표시합니다.
채널 선택은 화면 상단에 있습니다. 확인 전에는 최신 여부를 단정하지 않으며, **업데이트 확인** 결과에 따라 최신 상태나 새 업데이트를 표시합니다. 새 업데이트가 있으면 상태 카드에 새 버전만 표시하고, 다운로드 중에는 진행률과 받은 용량을 확인할 수 있습니다.
같은 앱·서명키를 사용하므로 더 새로운 버전이면 채널을 전환해 설치할 수 있습니다.
선택한 채널이 설치된 버전보다 오래됐으면 새 배포를 기다려야 합니다.
새 업데이트가 감지되면 해당 버전의 한국어 릴리즈노트가 화면에 자동으로 표시되며,
다운로드 중과 설치 준비 후에도 확인할 수 있습니다. 긴 노트는 화면을 스크롤해 읽습니다.
릴리즈노트의 제목·목록·강조·코드는 서식을 적용해 표시하며, 웹 링크를 누르면 브라우저로 엽니다.
노트를 불러오지 못해도 다운로드할 수 있으며, **업데이트 확인**을 다시 누르면 재시도합니다.
업데이트는 공개 [TERM 배포 저장소](https://github.com/nolbo/TERM)에서 내려받습니다.
선택한 채널에 아직 첫 버전이 배포되지 않았으면 해당 상태를 표시합니다. 다운로드 후 앱 정보와
서명을 검증한 APK만 설치할 수 있습니다. 필요하면 Android의 ‘알 수 없는 앱 설치’를
허용하고 돌아와 **설치**를 다시 누르세요. 마지막 설치 승인은 Android에서 진행합니다.
설치 시 Android가 런타임 프로세스를 종료할 수 있으므로 터미널 작업을 먼저 저장하세요.
정상 업데이트는 앱 데이터와 Linux 파일을 유지합니다. Debug 앱과 release 키가 다르면
업데이트가 차단되며, 앱이 자동으로 기존 앱을 삭제하지 않습니다.

저장된 원격 페어링 정보는 연결된 iPhone에서 유효성을 확인한 뒤 재사용합니다.
`RP_PAIRING`이 발생하면 기존 정보를 자동 삭제·재생성하지 않습니다. 설치나 Wi-Fi
디버깅 변경은 이미 완료됐을 수 있으므로 상태를 확인하고 반복 설치는 피하세요.

USB 안전성은 [자동 검사와 실기기 검증 절차](../tests/usb/DEVICE_SAFETY.md)로 나누어
확인합니다. 가상 테스트 통과는 실기기 무손상을 보장하지 않습니다. 실기기 검사에서는
작업 전후 설정·데이터·다른 세션·재연결을 비교하며, 예상 밖 변화가 있으면 중단합니다.

iPhone 검사 중 USB 구성을 자동 변경하지 않습니다. `USB_CONFIGURATION_REQUIRED`가
나오면 Native/Userspace Linux의 `terminal-usb configuration DEVICE_ID VALUE`로 별도 승인을
요청하고, 변경 후 다시 목록을 조회해 새 기기 ID를 사용하세요.
호스트 도구 화면과 CLI의 `changes`는 실패·취소 후에도 설치·설정 변경이 남았는지
표시합니다. `POSSIBLE`은 확인 필요, `CONFIRMED`는 완료 응답 확인, `UNCHANGED`는
기존 설정 유지입니다. 자동 앱 삭제·신뢰 해제·설정 초기화는 하지 않습니다.
페어링 파일은 임시 파일 검증 후 교체하며, 중단 시 임시 파일이 남을 수 있습니다.

개발용 [가상 iPhone 테스트](../tests/usb/VIRTUAL_IPHONE.md)는 테스트 APK에서만
연결 중단·Trust 거부·부분 전송 등을 재현합니다. 제품 앱에 가상 iPhone이나 권한
우회 기능을 제공하지 않으며, 실제 iOS 설치 성공을 검증하는 실행환경은 아닙니다.

USB 명령 실패 시 자동 재전송·기기 초기화를 하지 않습니다. 응답 시간 초과나
통신 오류가 난 연결은 재사용하지 마세요. `tooling` 작업이 FAILED이면 종료 코드
1, CANCELED이면 130을 반환하므로 `&&`로 연결한 다음 명령은 실행되지 않습니다.
단, `watch`에서 Ctrl-C는 관찰만 종료하며 호스트 작업은 계속됩니다.
이미 기기가 수락한 쓰기·설치·설정 변경은 실패나 취소로 되돌릴 수 없고, 업로드
중단 시 새 부분 파일이 남을 수 있습니다. 대상 상태를 확인한 뒤 재시도하세요.
사용자 스크립트·raw·시리얼·ADB 명령 자체의 부작용까지 방지하는 기능은 아닙니다.

Native와 Userspace Linux에서 `terminal-usb list`, `iphone pair|info|ls|get|put`,
`tooling list|check|start|status|watch|select|cancel`로 같은 iPhone 호스트 capability를 사용할 수 있습니다.
각 작업은 USB 화면에서 별도 승인해야 합니다. 앱은 전용 SideStore/IPA 설치
화면이 아닌 도구 실행 기반을 제공하며, USB FD·페어링·서명 비밀은 터미널에
전달하지 않습니다. `tooling start isideload DEVICE_ID`는 고정된 SideStore stable
작업을 수행하는 APK 도구를 호출합니다. 계정·암호·2FA는 **USB 디바이스 →
호스트 도구 입력**에서만 입력하세요. `tooling watch OPERATION_ID`를 종료하거나
화면을 나가도 작업은 계속되며, `tooling cancel OPERATION_ID`로 명시적으로
취소합니다. 임의 IPA URL이나 일반 usbmuxd는 제공하지 않습니다. 실제 iPhone
설치·첫 갱신은 아직 실기 검증하지 않았습니다. [iPhone 도구 실행환경](IPHONE_TOOLING.md)을 참고하세요.

**TERM**은 **Terminal Environments with Runtime Multiplexing**의 약자입니다.

USB Host 지원 기기에서는 새 Userspace Linux 세션의 `terminal-usb` 명령으로 USB 장치를
조회하고, 앱의 **설정 → 터미널 설정 → USB 디바이스**에서 접근 요청을 승인할 수
있습니다. Python 3가 필요하며, CDC ACM·FTDI·CP21xx·CH34x·PL2303 및 일부 모뎀의
시리얼 드라이버와 제한된 raw/HID 전송을 지원합니다. `terminal-usb list`의
`serialPorts`를 확인한 뒤 `terminal-usb serial DEVICE_ID --port 0 --baud 115200`으로
접속하세요. 여러 포트가 있으면 선택이 필수이며, 명확히 분리된 FTDI/CP21xx
구성에서만 다중 포트 동시 연결을 허용합니다. 다른 드라이버는 기기를 독점합니다.
`--cbreak`는 즉시 키 입력을 전송하고 종료 시 터미널 모드를 복구합니다.
초기화나 DTR/RTS 변경으로 보드가 리셋될 수 있으며, 쓰기 시간 초과는 자동 재전송하지
않습니다. `terminal-usb run SCRIPT.py`에서는 `terminal_usb`의 `SerialPort`와
`RawInterface`로 바이너리 프로토콜을 구현할 수 있습니다. ARM64 Android의 iPhone 경로는
`terminal-usb iphone pair|info|unpair DEVICE_ID`로 페어링·기본 정보 조회·페어링 해제를
요청하며 작업별 승인이 필요합니다. iPhone 잠금 해제와 신뢰 승인도 필요합니다.
페어링 후 `terminal-usb iphone ls DEVICE_ID /`로 표준 AFC 영역을 조회하고,
`get DEVICE_ID /원격경로 ./새파일`로 다운로드하거나
`put DEVICE_ID ./파일 --name import.txt`로 업로드할 수 있습니다(각 명령 앞에
`terminal-usb iphone` 필요). 파일당 64 MiB이며, 읽기는 경로별 승인,
쓰기는 `/TerminalImports`에 대한 별도 승인이 필요합니다. 업로드 파일명에는
앱이 생성한 UUID가 붙습니다. 연결이 끊기면 표시된 원격 경로에 일부 파일이
남을 수 있습니다. 다운로드는 기존 파일을 덮어쓰지 않으며 Userspace Linux 홈처럼
하드 링크를 지원하는 위치에 저장하세요. 실제 iPhone 전송 호환성은 아직 실기기
검증 전입니다. 기존 `idevice*` 명령이나 전체 파일시스템 접근을 제공하는 것은 아닙니다.
`apt install adb`로 설치한 ADB는 `terminal-usb adb DEVICE_ID` 중계와 함께
사용할 수 있습니다. 출력된 `ADB_SERVER_SOCKET=... adb devices` 명령을 별도
터미널에서 실행하세요. 기존 ADB 서버는 종료하지 않으며, 대상 Android의 USB
디버깅 승인도 필요합니다. 표준 MTP/PTP는 `terminal-usb mtp stores|ls|get|put`
명령으로 제공하며, 파일당 64 MiB 등 제한이 있습니다.

USB 설정은 **연결된 기기 · 접근 요청 · 허용된 접근 · 이동식 저장장치 · 호스트 도구 ·
도움말 및 진단**으로 구분됩니다. 대기 요청은 화면 위에 표시됩니다. 기기 행을
누르면 연결 ID와 인터페이스 정보를 확인할 수 있습니다. 세션 접근 해제와 폴더
제거는 확인 후 진행하며, 터미널 세션 자체나 저장된 파일은 삭제하지 않습니다.
화면을 닫거나 다시 열어도 승인된 작업은 계속 실행됩니다.

USB 설정에서 이동식 저장장치 폴더를 선택하면 `terminal-usb storage roots`와
`storage ls|get|put ROOT_ID`로 접근할 수 있습니다. Android가 마운트한 USB/SD
폴더만 대상이며 읽기/새 파일 업로드를 별도로 승인합니다. 파일 삭제·덮어쓰기나
디스크 포맷·마운트를 제공하지 않습니다. 분리 후에는 다시 승인해야 합니다.
`serial-pty`는 기존 프로그램용 PTY 바이트 스트림을 제공하지만, PTY ioctl이 실제
UART 설정을 바꾸지는 않습니다. `--save-profile ./uart.json`으로 설정을 저장하고
`--profile ./uart.json`으로 불러올 수 있습니다(권한이나 장치 ID는 저장하지 않음).
PyUSB는 apt의 `python3-usb`와 `terminal_usb.pyusb_backend()`를 명시적으로 사용합니다.
설정 화면에는 연결·승인 상태와 드라이버/인터페이스, 안전한 진단 정보가 표시됩니다.

모든 USB 기기의 자동 호환을 뜻하지는 않습니다. 커널 드라이버·FUSE/블록 마운트·
등시성 오디오/영상 및 수정 없는 libusb 프로그램은 지원하지 않습니다. ADB·MTP·
시리얼·저장장치의 실제 USB 호환성은 USB Host 지원 실기기에서 추가 검증이 필요합니다.
연결 절차와 제약은 [USB 가이드](USB.md)를 참고하세요.

페어링 오류 조사 시 APK 업데이트 후 새 세션에서 `terminal-usb tooling list`를
실행하면 서비스 수정 버전(`serviceRevision`)과 설치된 worker 해시를 확인할 수
있습니다. 수정 버전 2는 기존 기록 확인·Trust 대기·기록 저장·세션 검증을 따로
표시합니다. 기록이 손상되거나 읽기 실패한 경우 자동 재페어링하지 않습니다.
`tooling check`는 연결 검사이며 Trust나 설치를 시작하지 않습니다. 다른 작업의
응답이 오면 `TOOL_RESPONSE_MISMATCH`로 표시합니다. 이 변경만으로 iOS 27 베타의
실기기 호환성이 검증된 것은 아닙니다.

## 1. 시작하기

앱을 처음 열면 **초기 설정** 화면이 한 번 표시됩니다. 설정을 완료한 뒤부터는 앱을 열면 터미널로 바로 이동합니다. 기본 동작은 Native 모드이므로 별도 Debian 이미지 없이도 즉시 콘솔을 사용할 수 있습니다.

- **터미널 시작**: 앱 전용 홈·임시 디렉터리를 준비하고 Android Native 셸로 콘솔을 시작합니다.
- **AVF Debian 이미지 선택**: 기본 AVF 저장공간의 오프라인 개발·설치용 선택 사항입니다. 승인 이미지가 등록된 빌드에서는 새 실행환경을 사용하는 AVF 프로필을 저장한 뒤 설치 여부를 선택하면 별도 파일 준비 없이 이미지를 설치합니다.

초기 설정 화면은 Android Native, Userspace Linux, AVF Debian을 별도 카드로 표시하고 각 실행환경의 권한과 호환성 차이를 설명합니다. 앱 화면은 일관된 다크 테마만 사용하며, 터미널 팔레트는 설정에서 독립적으로 관리합니다.

Userspace Linux는 별도 파일을 준비할 필요가 없습니다. 새 세션에서 **Debian**, **Ubuntu 24.04 LTS**, **Arch Linux ARM** 중 하나를 고르면, 배포판이 설치되지 않은 경우 설치 여부를 먼저 묻습니다. **설치**를 선택하면 해당 실행환경을 내려받아 검증·설치하고 셸을 엽니다. **취소**하거나 확인창을 닫으면 다운로드와 세션 생성을 시작하지 않습니다. 이는 추가 Android 권한·ADB·root를 요구하지 않으며, 이미지 다운로드 실패는 다시 받고, 이미지 설치 뒤 패키지·실행환경 보완 실패는 기존 파일을 유지한 채 재시도합니다. 현재 자동 설치는 ARM64 기기를 지원합니다.

세션 툴과 빈 화면의 **새 세션** 메뉴에서 Userspace Linux·AVF 프로필별 **설치됨**, **미설치**, **설치 중** 상태를 확인할 수 있습니다. 같은 실행환경을 쓰는 프로필은 같은 상태를 표시합니다. 설치 상태를 확인하지 못하면 다시 시도하도록 안내하며 자동 설치하지 않습니다. 설치 중인 환경을 다시 선택하면 기존 설치를 이어서 표시합니다.

Userspace Linux 배포판이나 AVF Debian을 설치하는 동안에도 실행환경·프로필 정보를 확인하고 다른 실행환경의 새 세션을 열 수 있습니다. 설치 중인 실행환경을 사용하는 세션만 해당 설치가 끝날 때까지 기다립니다.

0.10.0부터 일반 디버그·배포 APK에 공개 Debian 이미지가 등록되어 있습니다. 새 실행환경을 사용하는 AVF 프로필을 저장하면 **AVF Debian 이미지를 설치할까요?**라고 묻습니다. **이미지 설치**를 선택하면 승인된 이미지를 내려받고 압축 해제·SHA-256 검증·설치를 처리합니다. **나중에 설치**를 선택해도 프로필은 저장되며 다운로드를 시작하지 않습니다. 나중에 해당 AVF 실행환경 설정에서 **이미지 설치**를 누를 수 있습니다. 기존 저장공간을 공유하는 프로필을 저장할 때는 다시 묻지 않습니다. 패키지 목록 초기화를 지원하는 새 이미지는 검증 후 VM을 한 번 실행해 최신 목록을 가져오며, 터미널 세션은 열지 않습니다. 이전 이미지는 파일 설치까지만 수행합니다. 화면을 닫아도 설치 작업은 유지됩니다. 네트워크 실패는 제한된 횟수로 재시도하며, 최종 실패 시 오류를 표시합니다. 최초 설치에는 인터넷 연결, 이미지용 저장공간 약 14GiB와 설치 임시 공간이 필요합니다. 이미 설치한 이미지와 작업 파일은 자동으로 교체하지 않습니다. APK에 포함된 AOSP AVF 드라이버를 사용하려면 기기의 호환 플랫폼 API와 실제 AVF 시스템 권한이 필요하며, APK 설치만으로 기기에 AVF 지원이나 권한을 추가할 수 없습니다.

이미지 설치 작업이 시작되면 해당 **AVF 실행환경 설정 → Debian 이미지**에서 **준비 → 설치 정보 확인 → 다운로드 및 압축 해제 → 무결성 검증 → 설치 및 최종 검증**을 확인합니다. 패키지 목록 초기화를 지원하는 이미지는 **Debian 초기 실행 준비 → 최신 패키지 목록 갱신**을 거쳐 **완료**로 표시합니다. 진행 상황은 설정 본문에 표시되며 같은 실행환경을 공유하는 모든 AVF 프로필에서 동일한 진행 상태를 확인할 수 있습니다. 현재 이미지의 순서, 다운로드 용량·진행률과 경과 시간을 표시하며, 전체량을 모르는 단계는 움직이는 진행 표시로 보여줍니다. 표시된 다운로드 비율은 현재 압축 이미지의 비율이며 전체 설치 비율은 아닙니다. 화면을 닫거나 다시 열어도 작업과 진행 상황이 유지됩니다. 터미널의 설치 진행 대화상자를 닫은 뒤에는 실행환경 설정에서 진행을 확인합니다. 터미널에는 별도의 **AVF Debian 이미지 설치 진행 보기** 버튼이 표시되지 않습니다. 프로필 목록과 설정은 실제 이미지 파일을 기준으로 **설치됨 / 미설치**를 보여주며, 초기 설정 완료 여부나 VM 실행 상태로 설치 여부를 판단하지 않습니다. **AVF Linux** 설정은 실행환경 관리로 이동하는 안내와 전달 포트 확인을 제공합니다.

AVF 프로필을 누르면 새 세션 탭을 바로 열고 선택하며, 이미지 확인·Debian 부팅·세션 준비가 끝날 때까지 본문 중앙에 움직이는 로딩 표시만 보여줍니다. 준비 화면에는 안내 텍스트나 배경 박스를 표시하지 않습니다. 이미 승인한 이미지 설치가 진행 중이면 완료를 기다린 뒤 세션을 시작합니다. 미설치 상태에서 설치를 요청하지 않았다면 실행환경 설정에서 Debian 이미지를 설치하라는 오류를 표시하며 임의로 다운로드하지 않습니다. 이미지가 설치되어 있으면 다시 내려받지 않습니다. 준비가 끝나면 같은 탭이 실제 터미널로 바뀝니다. 기다리는 동안 다른 탭으로 이동하면 완료 후에도 현재 선택을 유지하며, 화면을 닫거나 다시 열어도 서비스가 시작 작업을 계속 관리합니다. 준비 중인 탭에는 입력할 수 없습니다.

세션을 열지 못하면 로딩 표시를 멈추고 해당 탭과 **AVF 세션을 열 수 없습니다** 대화상자에 실제 실패 원인을 표시합니다. 대화상자를 닫아도 탭의 오류는 남습니다. 실패한 탭의 **닫기**는 시작 요청 표시만 지우며 이미지·작업 파일이나 다른 세션을 삭제하지 않습니다.

기본 AVF 프로필도 선택하면 바로 시작을 요청합니다. Native가 기본 런타임이거나 해당 AVF 가상 머신이 아직 시작되지 않았다는 이유로 Debian 설정 이동을 요구하지 않습니다. 시작 후의 AVF 준비 상태는 실제 AVF 런타임을 기준으로 표시합니다.

설치된 이미지로 첫 세션을 시작할 때는 이미지 무결성을 한 번 검사한 뒤 Debian을 부팅합니다. 같은 VM에 추가 세션을 열면 준비된 실행환경을 재사용합니다. 손상된 이미지는 시작을 차단하며 자동으로 교체하지 않습니다.

AVF 세션의 기본 시작 디렉터리는 로그인 사용자 `droid`의 홈인 `/home/droid`입니다. 업데이트 시 기존 AVF 프로필의 `/home/user` 기본 경로도 한 번 자동으로 바꾸며, 직접 지정한 다른 경로는 유지합니다. 이미지를 다시 설치할 필요가 없고 새 세션부터 적용됩니다. 기존 `/home/user` 파일은 그 자리에 남아 있으며, 업데이트 후 프로필에서 `/home/user`를 직접 지정하면 다시 사용할 수 있습니다.

수정된 초기 설정으로 새로 제작한 AVF 이미지에서는 일반 사용자 `droid`로 셸을 시작하며, VM 내부의 관리 명령은 비밀번호 없이 `sudo`로 실행합니다. 패키지 목록 갱신은 `sudo apt update`, 패키지 설치는 `sudo apt install 패키지명`을 사용합니다. 이 변경을 포함한 새 이미지의 온라인 설치는 검증 후 가상 머신을 한 번 실행해 설치 시점의 전체 패키지 목록을 가져옵니다. 설치 확인창에는 VM 실행과 인터넷 사용을 안내하며, 실행환경 상세에서 이미지 설치 여부와 패키지 목록 초기화 상태를 따로 확인할 수 있습니다. 갱신에 실패하거나 취소해도 설치된 디스크는 유지되며 **패키지 목록 갱신 재시도**로 갱신만 다시 수행합니다. 이후의 `sudo apt update`에는 기본 증분 설정을 사용합니다. 설치된 패키지를 자동 업그레이드하는 기능은 아니며, 기존 이미지에는 앱 업데이트만으로 초기화 서비스가 추가되지 않습니다. 비밀번호 로그인은 잠겨 있고 별도의 공통 초기 비밀번호는 없습니다. 이 설정은 새 이미지 릴리스가 배포·승인된 뒤 새 저장공간에 설치한 이미지부터 제공하며, 기존에 설치한 이미지에는 적용하지 않습니다. APK 업데이트만으로 기존 VM의 sudo 설정이 바뀌지는 않습니다.

AVF Debian의 기본 호스트 이름은 짧은 `localhost`이며 기본 Bash 프롬프트의 `사용자@호스트` 부분에도 이 이름이 표시됩니다. 이미 설치한 이미지에도 다음 VM 부팅부터 적용되므로 이미지를 다시 설치할 필요가 없습니다. 실행 중인 VM에 새 세션을 여는 것만으로는 호스트 이름이 바뀌지 않습니다. 사용자 파일과 저장공간별 VM 식별자는 유지됩니다.

두 AVF 권한을 ADB로 부여한 뒤에도 **맞춤 이미지 API가 호환되지 않거나 숨김 API 접근 정책에 의해 차단되었습니다**라는 오류가 표시될 수 있습니다. VM 권한과 Android의 숨김 API 접근 허용은 별개입니다. 앱은 이미지 설치 전에 생성자 접근을 검사하고 원래 오류를 함께 표시합니다. 이 경우 제품의 플랫폼 API 접근 정책 또는 실제 API 호환성을 확인해야 합니다.

오프라인 설치를 선택하는 경우에만 로컬 이미지 디렉터리에 아래 파일이 모두 있어야 합니다.

```text
manifest.properties
vmlinuz
initrd.img
system.img
home.img
config.img
```

앱은 파일명, 아키텍처(Debian ARM64), 각 파일의 SHA-256을 검증합니다. 검증에 실패한 이미지나 임의 URL은 실행하지 않습니다.

> Native 모드는 일반 Android 셸 실행환경이며 systemd나 완전한 Debian 패키지 호환을 제공하지 않습니다. 실제 Debian VM은 OEM/플랫폼 서명 AOSP 배포 실행환경에서 동작합니다.

## 세션 작업 알림

**설정 → 터미널 설정 → 셸 → 세션 작업 알림**에서 켜거나 끌 수 있습니다.
기본값은 꺼짐이며, Android 알림 권한과 **세션 작업 알림** 채널도 허용해야 합니다.
같은 화면의 **Android 알림 설정**에서 소리·표시 여부를 바꿀 수 있습니다.
이 옵션은 세션 유지용 상시 알림과 독립적입니다.

- 10초 이상 실행한 명령이 끝나면 완료 알림을 보냅니다. 기본 Native 셸과 Bash의
  새 세션에 완료 감지 신호를 연결합니다. 설치 이전부터 실행 중인 셸에는 소급 적용하지 않습니다.
- 터미널 앱이 활성 상태이고 해당 세션을 보고 있으면 완료 알림을 보내지 않습니다. 다른 탭을 보거나 앱을 벗어나면 완료 알림을 보냅니다. 보고 있는 동안 끝난 작업을 나중에 다시 알리지는 않습니다.
- 프로그램이 벨(BEL), OSC 9 또는 `OSC 777;notify`를 보내면 확인 요청을 알립니다.
  임의의 출력 문장이나 조용한 상태만으로 입력 대기를 추측하지 않습니다.
- UI를 닫아도 런타임이 살아 있으면 알림을 보냅니다. 알림을 누르면 해당 세션을
  선택하며, 세션이 사라졌다면 새 세션을 대신 만들지 않습니다.
- 동일 세션 알림은 10초에 한 번, 앱 전체는 1초에 한 번으로 제한합니다.
  스크롤백 복원·탭 전환은 과거 알림을 다시 보내지 않습니다. 끄면 현재 작업 알림도 지워집니다.
- 알림은 세션 이름·상태·가능한 경우 종료 코드만 표시하며 터미널 출력 본문을 노출하지 않습니다.

Bash 설정에서 `PS0`·`PROMPT_COMMAND`를 덮어쓰거나 Native의 `PS1`을 교체하면
자동 완료 감지가 중단될 수 있습니다. 다른 셸·원격 프로그램은 OSC 133의 C/D 명령
경계 신호를 직접 보내거나 다음처럼 확인 요청 신호를 보낼 수 있습니다.

```sh
printf '\033]777;notify;TERM;Attention needed\007'
```

일반 텍스트 프롬프트, 별도 백그라운드 작업의 완료, 임의의 TUI 입력 대기는 해당
프로그램이 신호를 보내지 않으면 감지하지 않습니다. Bash 연동이 게스트 환경 변수
한도를 넘는 경우에는 셸 실행을 우선하고 자동 연동을 생략합니다.

## 2. 콘솔 사용

터미널 하단 세션 툴의 **새 세션** `+` 버튼은 프로필 목록을 표시합니다. 세션이 없는 초기 화면에서도 같은 버튼을 사용합니다.
Native, Debian, Ubuntu, Arch, AVF 기본 프로필과 사용자 프로필을 이름·실행환경으로
구분합니다. 사용할 수 없는 실행환경도 표시하며 선택 시 기존 설치 또는 설정 안내로
연결합니다. 다른 실행환경으로 자동 전환하지 않습니다.

**설정 → Profiles**에서 프로필을 누르면 설정 화면이 열립니다. 기본 프로필도
같은 화면에서 수정·복제·삭제할 수 있습니다. 삭제는 확인 후 적용되며 앱을 다시
열어도 유지됩니다. 모두 삭제한 경우 **Add profile**로 새 프로필을 만들 수 있습니다.
프로필 관리 화면의 **편집** FAB를 누르면 순서 편집 모드로 전환됩니다. 왼쪽 핸들을 드래그해 순서를 바꾸고 **완료**로 편집 모드를 닫으세요. 드롭한 순서는 바로 저장되며 세션 툴과 빈 화면의 **새 세션** 목록에도 적용됩니다. 드래그를 취소하면 이전 순서를 유지하며 순서를 편집한 뒤 새로 만든 프로필은 목록 끝에 추가됩니다.
저장·복제·삭제는 화면 하단의 플로팅 툴바에서 제공합니다. 새 프로필을 만들 때는 저장 버튼만 표시합니다. 아이콘 위에 마우스를 올리거나 길게 누르면 버튼 이름이 툴팁으로 표시됩니다.
복제는 저장된 설정을 사용하므로 수정 중에는 먼저 저장하세요.
**+ → Add profile**과 **설정 → Profiles → Add profile**은
같은 편집 화면을 엽니다.
**프로필 아이콘**은 워크스페이스와 같은 기본 후보 33개를 모달로 제공합니다. 선택 화면과 설정 행은 아이콘 그림만 표시하고 선택된 후보를 강조합니다. **확인**은 프로필 초안에 반영하고 **취소**는 기존 선택을 유지합니다. 프로필 화면의 전체 **저장**을 눌러야 적용됩니다. 기본값인 자동 아이콘은 Native·배포판·AVF 선택을 따라갑니다.
직접 고른 아이콘은 실행환경을 바꿔도 유지되며, 프로필 복제 시 함께 복제됩니다.
새 사용자 지정 이미지 추가 기능은 제공하지 않습니다. 기존에 추가한 이미지는 계속 선택할 수 있습니다. 투명 배경의 단색 이미지는 탭·메뉴 색상을 따르고 여러 색상이나 불투명 배경의 이미지는 원래 색상으로 표시합니다.
아이콘 변경은 이후 생성한 세션에 적용됩니다. 기존 세션과 복제본을 위해 가져온 이미지가
자동 삭제되지는 않습니다. 추가한 아이콘의 휴지통 버튼을 누르고 확인하면 선택 목록에서
즉시 삭제됩니다. 기존 프로필·복제본·실행 중인 세션의 표시는 유지하도록 이미지 파일은
보존합니다. 삭제한 아이콘을 선택 중이었다면 선택 창의 초안은 **실행환경에 맞춤**으로 바뀌며, **확인** 후 프로필 화면의 전체 **저장**을 눌러야 적용됩니다.
**프로필 설정 → 컬러 팔레트**에서 프로필마다 전경·배경·커서·ANSI 16색을 지정할 수 있습니다.
새 프로필과 기존 팔레트 설정이 없는 프로필은 전역 팔레트를 따릅니다. 프로필 복제는
원본의 독립 팔레트 또는 전역 상속 설정을 그대로 복제합니다.
**전역 팔레트 복제**와 **다른 프로필에서 가져오기**는 현재 표시 색상을 독립 복사하며,
원본이 전역을 따르더라도 가져온 뒤에는 전역·원본 프로필 변경과 연계되지 않습니다.
**팔레트 초기화**는 전역 상속으로 되돌리므로 이후 전역 변경도 반영됩니다.
색상 견본을 누르면 사각형에서 가로로 채도, 세로로 밝기(위쪽이 밝음)를 조절할 수 있습니다.
아래 색조 막대에서 색조를 바꾸거나 HEX(6자리, # 생략 가능)·RGB(각 0–255)를 직접 입력합니다.
견본·선택 위치·숫자는 함께 갱신되며, 잘못된 입력은 수정해야 **색상 적용**을 누를 수 있습니다.
색상 편집·가져오기·초기화는 화면 하단에서 프로필을 저장해야 적용됩니다.
팔레트 변경은 해당 프로필의 실행 중인 세션에도 적용됩니다. 탭을 전환하면 터미널의
팔레트와 탭·단축키·세션 메뉴의 반응형 색상이 함께 부드럽게 전환됩니다.
빠르게 연속 전환해도 현재 보이는 색상에서 새 대상 색상으로 이어집니다.
프로필을 삭제한 세션은 생성 시의 팔레트 설정으로 돌아가며 세션 자체는 유지됩니다.

Native 셸의 별도 전역 설정은 제공하지 않습니다. 기본 Native 프로필의 셸은
`/system/bin/sh`이며 셸을 바꾸려면 **프로필 설정 → Shell**에서 지정합니다.
이전 전역 셸 경로는 적용하지 않으며, 이미 저장한 프로필의 셸 경로는 유지합니다.

프로필 목록은 오른쪽 `>` 화살표가 있는 설정 행으로 표시합니다. 추가·편집 화면의
텍스트 항목은 행을 눌러 입력 대화상자에서 수정합니다. **실행환경**에서는 새 프로필의 **새 실행환경 만들기 / 기존 실행환경 사용**, 편집 중인 프로필의 **현재 실행환경 유지 / 새 실행환경 만들기 / 기존 실행환경 사용**을 선택합니다. 실행환경 선택 대화상자의 **확인**은 초안에 반영하고 화면 전체 저장으로 영속화합니다. 취소는 기존 값을 유지하며 미저장 초안은 화면 재생성 뒤에도 보존합니다.

새 실행환경에서는 **실행 방식**을 Native / Userspace Linux / AVF로 선택합니다. Userspace Linux는 Debian·Ubuntu·Arch 배포판을 추가로 고릅니다. AVF는 현재 Debian ARM64 guest만 지원하며 두 AVF 특권이 모두 있을 때 새 실행환경의 실행 방식으로 선택할 수 있습니다. 실행환경의 실행 방식과 배포판은 그 실행환경의 정체성이므로 변경하려면 새 실행환경을 만들고 프로필을 연결합니다. **기존 실행환경 사용**은 새 실행환경의 선택값과 관계없이 모든 실행환경을 표시하며, 프로필 편집에서도 현재 실행환경을 포함한 같은 목록을 사용합니다. 실행환경을 선택하면 실행 방식·배포판이 자동으로 정해지고 기본 셸 설정도 맞춰집니다. 직접 지정한 셸 설정은 유지하며 선택한 환경의 정보는 목록에 한 번만 표시합니다.

Environment는 어디에서 실행되는가, Profile은 어떻게 들어갈 것인가, Session은 지금 실행 중인 것은 무엇인가, Storage는 실행환경 데이터를 어떻게 보존하는가를 나타냅니다. 하나의 실행환경을 여러 프로필에서 공유하면 rootfs·패키지·홈·설정·VM 디스크 및 런타임 상태를 함께 사용합니다. 새 프로필과 복제본은 기본적으로 새 독립 실행환경을 만들며 파일을 복사하지 않습니다. 실행환경 이름은 프로필 이름을 기본으로 쓰며 중복 시 숫자를 붙입니다. Native의 Android 시스템·APK 실행 파일은 공통 플랫폼 자원입니다.

기존 프로필과 저장 데이터는 같은 `(runtime, storageId)`를 기준으로 실행환경 UUID에 연결됩니다. Userspace Linux 배포판은 정확히 구분합니다. legacy 경로와 파일·inode·패키지·VM identity는 이동하지 않습니다. legacy 저장소 ID의 기존 adoption은 활성 세션이 없고 상태를 확인할 수 있을 때만 진행하며 실행환경 UUID는 그대로 유지합니다. 이름 변경과 프로필의 실행환경 변경은 기존 세션의 생성 snapshot 및 실행 위치를 바꾸지 않습니다. 프로필을 삭제해도 실행 중인 세션과 실행환경 데이터는 유지됩니다.

**설정 → 실행환경** 목록은 이름, 런타임, 용량만 표시합니다. 실행환경 상세에서 연결된 프로필·세션과 실행환경 ID를 확인하고 이름 변경, 실행환경 시작 및 세션이 없는 런타임 중지를 요청할 수 있습니다. AVF 실행환경에서는 VM ID와 영속 디스크, Debian 이미지 설치 여부·진행을 확인합니다. 화면을 닫거나 재생성해도 런타임과 세션을 종료하지 않습니다. 직접 시작한 실행환경은 세션 없이도 중지하거나 삭제할 때까지 백그라운드 실행 상태를 유지하며, 유휴 상태만으로 화면 꺼짐 방지 잠금을 잡지는 않습니다.

실행환경 삭제는 배포판 또는 Debian 이미지 제거 절차를 포함해 그 실행환경의 런타임과 모든 영속 데이터를 함께 정리합니다. Userspace Linux는 배포판 이미지·설치 캐시·패키지·홈·설정·작업 폴더를, AVF는 Debian 이미지·패키지·홈·설정·VM 영속 상태·공유 디렉토리를 삭제합니다. 배포판이나 Debian을 별도로 먼저 제거할 필요는 없습니다. 연결된 프로필을 먼저 삭제하거나 다른 실행환경으로 변경하고 활성 세션을 종료해야 합니다. 설치·관리 작업이나 legacy adoption이 진행 중이거나 런타임 중지를 확인할 수 없으면 삭제하지 않습니다. 실행하지 않았거나 호스트 재시작 후 연결하지 않은 AVF 환경도 특권 플랫폼에서 해당 VM이 중지되었거나 없음을 확인할 수 있으면 삭제할 수 있습니다. 다른 실행환경과 기존 Userspace Linux 공용 작업 폴더는 삭제하지 않으며 자동 정리는 없습니다.

저장 공간은 해당 실행환경 파일의 크기 합계이고 최대 1분 간격으로 갱신합니다. 파일이 없는 새 실행환경은 0B일 수 있습니다. 권한 제한 하위 폴더는 **최소 … (일부 확인)**으로 표시하고 루트 접근 실패·측정 오류는 이전 값 대신 **용량 확인 불가**로 표시합니다. Userspace Linux와 AVF Linux 설정은 엔진의 전역 지원·정책을 담당하며, instance 설치·데이터·런타임 관리는 실행환경 상세에서 수행합니다.

Userspace Linux 실행환경 상세의 **배포판 관리**에서 **배포판 설치**, 실패 시 **재시도**, 설치된 이미지의 **실행환경 보완**을 요청할 수 있습니다. 설치는 세션을 만들지 않으며 화면을 닫아도 서비스가 작업과 진행 상태를 유지합니다. **배포판 제거**는 해당 실행환경의 이미지와 이미지 내부 패키지·파일을 지우고 실행환경·연결된 프로필·작업 폴더를 유지합니다. 홈은 기본적으로 보존하고 확인창에서 홈 삭제를 선택할 수 있습니다. 제거한 실행환경은 같은 화면에서 다시 설치할 수 있습니다. 미설치 배포판의 프로필을 실행하면 먼저 설치 여부를 묻고, 승인한 경우에만 설치 후 세션을 시작합니다.

AVF 실행환경 상세의 **Debian 이미지**에서 설치 상태·진행을 확인하고 승인 설치 또는 **Debian 제거**를 요청합니다. 제거하면 해당 VM의 이미지·홈·패키지·설정과 VM 영속 상태를 삭제하며 실행환경·연결된 프로필·공유 디렉토리는 유지합니다. AVF 플랫폼이 VM 중지를 확인할 수 있어야 하고 진행 중 설치와 활성 세션이 있으면 제거할 수 없습니다. 미설치 AVF 프로필을 실행하면 Debian 이미지 설치 여부를 묻습니다. **설치**를 선택하면 이미지 설치를 기다린 뒤 세션을 열고, 취소하면 실행환경과 프로필만 유지합니다.

이름, 실행환경, 셸, 인수, 시작 디렉터리, 환경 변수, 시작 명령을 설정하고
**저장**합니다. 셸 인수는 JSON 문자열 배열(예: `["-l"]`,
`[]`, `["-l", "argument with spaces"]`), 환경 변수는 줄마다 `KEY=value`로 입력합니다.
디렉터리와 셸은 절대 경로를 사용합니다. Native의 빈 디렉터리는 앱 전용 홈입니다.
시작 명령은 POSIX 호환 셸에서 한 번 실행한 뒤 설정된 셸과 인수로 전환합니다.
`exit` 또는 `exec`를 직접 사용하면 이 전환을 생략할 수 있습니다.

팔레트를 제외한 프로필 변경·삭제는 이후 생성할 세션에만 영향을 줍니다. 실행 중인 세션은 생성 당시
설정을 유지하며 탭 전환이나 화면 재생성 때 시작 명령을 다시 실행하지 않습니다.
프로필 삭제는 세션 종료가 아닙니다. PID, 스크롤백, 현재 디렉터리, 실행 중인 작업,
터미널 크기는 프로필에 저장하지 않습니다.

사용자 글꼴 목록은 **일반 / 이탤릭** segmented button으로 전환합니다.
선택한 종류의 글꼴만 표시하며, 파일 추가·우선순위 변경·제거도 해당 종류에 적용됩니다.

**설정 → 터미널 설정 → 터미널 모양 → 화면 배치 → 쉘 화면 여백**에서 상하좌우 여백을
0~32dp로 조절합니다. 기본값은 화면 가장자리와 글자를 조금 띄우면서 표시 공간을
확보하는 4dp입니다. 저장 후 터미널로 돌아가면 적용되며, 줄·열 수가 새 크기에
맞게 갱신됩니다. 여백은 선택한 터미널 팔레트의 배경색을 따릅니다.
기본 Droid Dark 팔레트의 커서는 흰색입니다.

초기 설정을 마치면 **터미널**에서 다음을 수행합니다.
새 탭 생성이 완료되면 해당 탭이 자동 선택되고 터미널 입력 포커스도 이동합니다.

**설정 → 터미널 설정 → 셸 → 터미널 링크 열기**를 켜면 프로그램이 지정한 링크와 화면에 출력된 `http://`·`https://` 주소를 한 번 탭해 브라우저로 엽니다(기본 꺼짐). 프로그램이 OSC 8로 지정한 링크를 우선하며, 표시된 글자와 실제 주소는 다를 수 있습니다. 링크가 지정되지 않은 위치에서는 기존 주소 자동 감지를 사용합니다. `http`·`https`만 열며 `file:`·`content:`·`intent:` 등의 링크는 열지 않습니다. 줄바꿈·스크롤백·화면 크기 변경·체크포인트 복원 후에도 지정된 링크 범위를 유지합니다. 더블 탭 판정 후에
열리며, 스크롤·길게 누르기·더블 탭 중에는 열지 않습니다. 마우스 보고를 사용하는
터미널 프로그램에서는 해당 프로그램의 입력을 우선합니다.

마우스 입력을 지원하는 터미널 프로그램에서는 한 손가락으로 좌우로 밀어 긴 줄을 수평 스크롤할 수 있습니다. Neovim에서 `:set mouse=a`와 `:set nowrap`을 설정하면 왼쪽으로 밀 때 `<ScrollWheelRight>`, 오른쪽으로 밀 때 `<ScrollWheelLeft>`가 전달됩니다. 처음 감지한 수평·수직 방향은 손가락을 뗄 때까지 유지되며, 마우스 보고를 사용하지 않는 일반 셸에서는 좌우 swipe가 입력이나 세로 스크롤을 발생시키지 않습니다. 실제 마우스·트랙패드의 수평 휠도 지원합니다.

하단 Hotkeys에서 **Shift·Alt·Ctrl**을 켜면 터치 swipe와 마우스·트랙패드의 위·아래·좌·우 휠 입력에도 해당 보조 키나 조합이 적용됩니다. 휠 입력으로는 선택이 해제되지 않으므로 다시 눌러 끌 때까지 계속 사용할 수 있습니다. 일반 키 입력 후 해제되는 기존 동작은 유지됩니다. 예를 들어 Neovim의 `vim.keymap.set('n', '<S-ScrollWheelUp>', 'zH', { silent = true })`와 `vim.keymap.set('n', '<S-ScrollWheelDown>', 'zL', { silent = true })`를 설정하고 Shift를 켠 뒤 세로로 스크롤하면 긴 줄을 좌우로 이동할 수 있습니다.

터미널에서 두 손가락을 벌리거나 모으면 현재 세션의 글자 크기를 4–72sp 범위에서
조절합니다. 변경한 크기는 세션별로 저장되어 탭 전환·앱 재진입 때 복원됩니다.
아직 핀치로 조절하지 않은 세션은 터미널 모양 설정의 기본 글자 크기를 사용합니다.

1. 세션과 워크스페이스가 모두 없는 초기 화면에서도 하단 툴바와 핸들을 표시합니다. 빈 화면에는 안내만 표시하며 워크스페이스 선택·**새 세션**·**설정**은 툴바에서 사용합니다. 툴바를 숨긴 경우에는 하단 핸들로 다시 펼칠 수 있습니다. 현재 필터에 세션이 없으면 세션 툴만 표시하며, 새 세션도 같은 툴바 내부 프로필 선택 페이지에서 시작합니다.
2. **세션** 툴 상단의 **새 세션** `+` 버튼을 누르면 툴바가 확장되며 프로필 선택 목록이 표시됩니다. 기본 또는 사용자 프로필을 명시적으로 고릅니다. 프로필을 선택하면 새 세션으로 전환하고 툴바는 버튼을 누르기 전의 기본·확장 크기로 돌아갑니다. 설치되지 않은 Userspace Linux 배포판을 고르면 설치 여부를 묻고, 그 밖의 실행환경은 관련 설정 화면을 열지 묻습니다. 다른 실행환경으로 자동 전환하지 않습니다.
3. **세션** 툴은 기존 기본 높이를 유지하며 기본 상태에서는 헤더만 표시합니다. 헤더 왼쪽에는 워크스페이스 선택 아이콘이 있고 그 옆에는 기존 앱 바와 같은 가로 세션 탭이 표시됩니다. 좌우로 스크롤해 탭을 찾고 누르면 해당 셸로 전환하며, 사용자 지정 제목이 있으면 그 아래에 원래 제목도 함께 표시됩니다. 오른쪽의 **새 세션**·**설정** 버튼은 그대로 사용할 수 있습니다. 현재 필터에 세션이 없으면 기본 크기에서도 워크스페이스 아이콘 옆에 이름이 표시됩니다. 하단 핸들로 툴바를 확장하면 세션 유무와 관계없이 이름이 표시됩니다. 헤더와 탭 목록 사이에는 여백을 두며 버튼을 누를 수 있는 영역은 유지됩니다. 선택기는 가용 폭을 사용하며 메뉴는 이름 길이에 맞춰 넓어지고 긴 이름은 줄바꿈해 전체를 보여줍니다. 워크스페이스 선택기 오른쪽의 **모두 닫기**는 현재 워크스페이스에 표시된 세션을 종료하며, 미소속 필터에서는 미소속 세션에만 적용됩니다. 기존 탭 종료 확인 설정을 따르며 확인 중 새로 생기거나 다른 그룹으로 이동한 세션은 종료하지 않습니다. 비어 있는 임시 워크스페이스에서는 같은 버튼이 휴지통 모양의 **워크스페이스 삭제**로 바뀝니다. 준비 중인 세션이 있거나 실제 세션 상태를 확인할 수 없으면 삭제하지 않습니다. 삭제 후에는 미소속 세션으로 전환하며 다른 세션·실행환경·파일은 보존합니다. 세션 개수와 상태별 집계는 표시하지 않습니다. 헤더 아래에는 탭의 세로 목록이 나타나며, 탭을 누르면 해당 셸에 연결됩니다. 새 Native 탭은 `/`가 아닌 앱 전용 홈 디렉토리(`$HOME`)에서 시작합니다. Enter 입력 없이 초기 프롬프트를 표시하며, 홈 경로는 `~`, 홈 아래 경로는 `~/…`로 표시합니다. 선택된 탭은 둥근 배경으로 구분되며 긴 목록은 위아래로 스크롤합니다. 세로 목록을 스크롤하거나 탭을 전환해도 선택된 탭으로 자동 이동하지 않고 직접 이동한 위치를 유지하며, 기본 상태로 접었다가 다시 확장해도 목록 위치는 유지됩니다.
4. 기본 크기에서는 탭 본문을 길게 누르면 이름 변경·워크스페이스 이동 메뉴가 열리며 편집 버튼은 표시하지 않습니다. 비선택 탭의 이름을 편집해도 현재 세션은 바뀌지 않습니다. 닫기 버튼은 선택된 탭에만 표시하고, 비선택 탭이 연속되는 경계에는 세로 구분선을 표시합니다. 확장 크기에서는 선택된 탭의 케밥 버튼에서 이름 변경·워크스페이스 이동 메뉴를 열며 모든 탭에 닫기 버튼을 표시합니다. 확장된 세로 목록에서 탭 본문을 길게 누른 뒤 위아래로 드래그하면 순서를 바꿀 수 있습니다. 목록 가장자리에서는 자동으로 스크롤하며, 놓으면 순서가 저장됩니다. 드래그를 취소하면 기존 순서를 유지합니다. 순서는 탭 전환·상태 갱신·화면 재생성 뒤에도 유지됩니다. 탭 제목은 명시적으로 지정한 탭 이름을 우선하고, 없으면 셸/앱이 터미널에 지정한 제목, 마지막으로 초기·프로필 이름을 사용합니다. 새 이름은 공백을 제외한 1~64자이며 줄바꿈과 제어 문자는 사용할 수 없습니다.
   핫키를 짧게 누르거나 탭을 선택할 때는 가벼운 햅틱 피드백을, 이름 변경·세션 시작·저장 같은 완료 동작에는 확인 햅틱을 제공합니다. 핫키 반복 입력 중에는 진동을 반복하지 않습니다. **터미널 설정 → 햅틱 피드백**에서 전체 사용 여부와 밀도(낮음·표준·높음)를 정할 수 있으며, 스크롤백 촉각 틱은 별도로 켭니다. 틱 간격은 낮음 6행, 표준 3행, 높음 1행입니다.
5. 탭 앞 아이콘으로 실행환경을 구분합니다: Native는 로봇, Debian은 나선, Ubuntu는 원형, Arch는 아치, AVF는 칩입니다. 탭에는 실행환경 접두사 없이 제목만 표시합니다. 스크린 리더에서는 실행환경과 세션 상태를 함께 안내합니다.
터미널 배경색을 바꾸면 탭·새 탭 메뉴·단축키 버튼 배경과 글자·아이콘 색상도 읽기 쉬운 대비로 자동 조정됩니다.

6. 터미널 캔버스의 두 번 탭에는 별도 동작이 없습니다. 툴바를 숨기거나 펼치려면 하단 핸들을 사용합니다. 터미널 배경은 화면 상단까지 이어지며, 상태 표시줄 뒤에는 터미널 배경색에서 투명해지는 그라데이션이 표시됩니다. 기록의 맨 위에서는 첫 줄이 상태 표시줄 아래에 놓이고, 스크롤하면 위쪽 내용이 상태 표시줄 뒤를 통과하며 사라집니다.
7. 화면 키보드나 하드웨어 키보드로 명령을 입력합니다. 하단의 단축키 그리드에서 ESC, CTRL, ALT, 방향 키와 페이지 키도 사용할 수 있습니다.
8. 종료 아이콘은 모든 탭에 표시됩니다. 선택된 탭에는 제목 편집 아이콘도 표시됩니다. 종료 아이콘을 누른 뒤 확인하면 해당 세션과 실행 중인 작업이 종료됩니다. **탭 삭제 시 묻지 않기**를 켜면 종료 아이콘을 누르는 즉시 확인 없이 종료됩니다.

**터미널 설정 → 사용자 설정 → 툴바 설정 → 편집**에서 **명령 기록**을 추가할 수 있습니다. 기본 크기의 위·아래 화살표로 명령 위치를 탐색하며, 첫·마지막 명령에서는 기록의 맨 위·맨 아래로 이동하는 버튼으로 바뀝니다. 검색 범위를 **명령 / 출력 / 명령과 출력**으로 고르면 실제 터미널 화면과 보관 중인 스크롤백에서 해당 내용을 찾습니다. 검색어 입력·범위 변경 때 가장 최근 일치 글자로 이동하고 화면에 강조합니다. 위·아래 버튼과 검색 키로 일치 항목을 순환하며 현재 순번과 결과 수를 확인할 수 있습니다. 검색어를 지우면 화살표는 명령 이동으로 돌아갑니다. 검색해도 확장된 커밋 그래프의 명령 목록은 줄어들지 않습니다. 핸들로 툴바를 펼치면 최신 명령부터 연결선과 상태 도트가 있는 목록이 나타납니다. 행을 누르면 해당 명령으로 이동하며, 체크는 완료, 재생 심볼은 실행 중, 빗금 원은 실패를 뜻합니다. 상태 도트를 길게 누르면 상태·종료 코드를 볼 수 있습니다. 각 행 오른쪽 꺾쇠 버튼으로 명령의 출력을 펼치고 접을 수 있습니다. 꺾쇠 왼쪽 복사 아이콘은 출력을 펼치지 않아도 명령 전체를 복사합니다. 펼친 출력은 길게 눌러 필요한 내용을 선택·복사할 수 있습니다. 긴 출력은 필드 안에서 스크롤하며 실행 중인 출력도 갱신됩니다. 명령 범위는 셸 통합이 알려준 입력 경계를 사용하며 출력·전체 범위는 셸 통합 없는 일반 출력도 검색합니다. 오래된 기록이 삭제되면 관련 명령과 검색 결과도 사라집니다. Native 기본 셸과 Bash 기본 통합을 지원하며 사용자 프롬프트·rc가 통합을 덮어쓰는 경우에는 경계 보고가 필요합니다. Neovim·less·tmux 등 프로그램이 화면을 제어하는 동안은 명령 이동을 사용할 수 없습니다.

Rootless Debian·Ubuntu에서 `su`로 사용자를 전환하거나 SSH로 접속한 뒤에도 Bash가 기본 입력 경계 신호를 보내면 내부 명령을 개별 기록으로 표시합니다. 접속한 사용자의 설정이나 원격 서버 파일을 바꾸지 않습니다. 이 보조 감지는 다음 프롬프트에서 출력을 구분하지만 종료 코드를 알 수 없으므로 성공·실패를 판정하지 않습니다. 비밀번호처럼 화면에 표시되지 않는 입력은 기록하지 않습니다. Bash의 bracketed paste를 끄거나 인식할 수 없는 사용자 프롬프트를 쓰면 OSC 133 셸 통합이 필요합니다.

생성 시 기본 이름은 명시적 탭 이름이 아닙니다. 애플리케이션이 OSC 제목을 보내야
자동으로 바뀝니다. Vim/Neovim에서 제목이 그대로라면 `:set title`로 제목 전송을
켜세요. 항상 사용하려면 해당 편집기 설정에 `set title`을 추가합니다.
수동으로 지정한 탭 이름은 위쪽에 표시하고, 그 아래에는 애플리케이션 제목을
작게 계속 표시합니다. 애플리케이션 제목이 바뀌면 아래쪽 제목도 갱신되며,
제목을 보내지 않으면 초기·프로필 이름을 표시합니다. 사용자 지정 이름이 없으면
기존처럼 한 줄 제목을 표시합니다. 이름 변경 창의 입력 필드는 사용자 지정 제목이
없으면 비어 있고, 이미 지정한 제목이 있으면 해당 제목이 미리 입력됩니다.

터미널 텍스트를 길게 눌러 선택한 뒤 **복사**를 누르면 Android 클립보드에 저장됩니다. 선택 핸들을 여러 줄에 걸쳐 움직이면 첫 줄의 시작 위치부터 중간 줄 전체와 마지막 줄의 끝 위치까지 이어서 강조 표시됩니다. 선택 메뉴의 **붙여넣기**는 클립보드 텍스트를 현재 셸에 입력합니다. 여러 줄을 붙여넣으면 셸에서 명령이 실행될 수 있으므로 내용을 먼저 확인하세요.

키보드 앱의 여러 줄 붙여넣기, 선택 메뉴, 마우스 가운데 버튼, **Ctrl+Shift+V**, **Shift+Insert**, 붙여넣기 키는 같은 처리 경로를 사용합니다. 앱은 텍스트를 명령 단위로 나누거나 실행 완료를 기다리지 않으며, 마지막 줄바꿈·빈 줄을 제거하거나 Enter를 덧붙이지 않습니다. 여러 줄의 한 명령과 줄바꿈으로 구분된 여러 명령을 해석하고 실행하는 주체는 현재 셸이나 프로그램입니다.

현재 프로그램이 **Bracketed Paste Mode**를 켜면 전체 텍스트를 하나의 붙여넣기 프레임으로 전달하며 LF·CRLF, 탭, 마지막 줄바꿈까지 보존합니다. Bash/Zsh, Vim/Neovim, REPL, TUI별로 붙여넣기 후 처리나 실행 시점은 다를 수 있습니다. 이 모드가 꺼져 있으면 기존 터미널 입력 방식대로 LF·CRLF를 Enter(CR)로 전달하므로 명령이 즉시 실행될 수 있습니다. 어느 경우에도 줄바꿈의 유무와 줄 구조는 유지합니다. 기존 ESC·C1 제어 문자 필터는 유지합니다.

다른 앱에서 돌아오거나 UI가 다시 시작되어 화면을 복원할 때 과거 조회 요청에는 다시 응답하지 않습니다. 실행 중인 런타임은 화면이 없는 동안에도 커서 위치·색상 질의에 응답하므로, 복원 때문에 셸 입력란에 응답 문자열이 추가되거나 프로그램이 화면을 기다리며 멈추지 않습니다.

Codex CLI·Neovim처럼 프로그램이 자체 기록 화면을 사용하는 경우, 프로그램이 마우스 입력을 요청하면 손가락 스크롤과 마우스 휠을 해당 프로그램에 전달합니다. 마우스 입력을 요청하지 않은 대체 화면에서는 프로그램이 대체 스크롤을 켜 둔 경우 위·아래 커서 키를 전달합니다. 일반 화면에서는 터미널 기록을 스크롤합니다.

백그라운드 전환과 화면 재생성·재진입에서 터미널 버퍼와 입력 모드를 유지합니다. 짧은 앱 전환에서는 화면 미러를 5초간 유지합니다. 그 이후에는 중복 화면 처리를 중단하지만 런타임과 PTY는 계속 동작하며, 돌아오면 런타임 체크포인트로 화면을 복원합니다. Android가 UI 프로세스 자체를 종료해도 런타임 서비스와 PTY가 살아 있으면 기본·대체 화면, 설정 범위의 스크롤백, 커서·색상·이미지·입력 모드와 중간에 끊긴 제어 시퀀스까지 복원합니다. 각 탭에서 읽던 기록 위치도 이어집니다. 앱 전체 강제 종료나 실제 런타임·VM 종료로 사라진 작업을 되살리는 기능은 아닙니다.

새 Native 세션의 기본 Android 셸은 경로를 초록색·보통 굵기, `$`를 기본 글자색·보통 굵기로 표시합니다. 이어지는 입력 프롬프트는 노란색입니다. 색상은 선택한 터미널 팔레트를 따릅니다. 지원되는 `ls`·`grep`에는 `--color=auto` 별칭을 적용하므로 파일 저장과 파이프 출력에는 색상 코드가 섞이지 않습니다. 시작 시 `NO_COLOR`가 비어 있지 않거나 `TERM=dumb`이면 색상 기본값을 적용하지 않습니다. 다른 셸은 해당 셸의 프롬프트 설정을 사용합니다.

터미널 세션에 연결하면 화면 키보드를 요청합니다. 키보드를 숨겼다면 터미널
본문을 탭해 다시 열 수 있습니다. 시스템 뒤로가기는 키보드를 닫고, 셸에 ESC를
보내려면 하단 ESC 키를 사용합니다. 일반 화면 갱신은 숨긴 키보드를 다시 열지
않습니다. 하드웨어 키보드 연결 시 화면 키보드 표시 여부는 Android 설정을 따릅니다.

실행 중인 세션이 1개 이상이면 알림 제목에 앱 이름 없이 실행 중인 세션 수가 표시됩니다. Android 13 이상에서는 알림 권한을 허용해야 알림 창에 표시됩니다. 마지막 세션이 종료되고 진행 중인 생성·설치 작업도 없으면 알림과 포그라운드 서비스 유지가 해제됩니다. 빈 화면을 닫으면 유휴 서비스도 종료됩니다. 생성·설치 중에는 작업이 끝날 때까지만 임시 알림이 유지됩니다.

알림의 **모든 세션 종료**를 누르면 현재 모든 실행환경의 세션과 그 안의 작업을 즉시 종료합니다. 앱 화면이 닫혀 있어도 동작하며, 종료 후에는 세션 알림이 사라집니다. 종료에 실패한 세션은 유지되므로 다시 시도할 수 있습니다.

세션 유지 알림은 상시 알림으로 표시됩니다. Android 14 이상에서는 OS가 개별 스와이프 삭제를 허용하지만, 세션이나 진행 중인 작업이 남아 있으면 알림을 다시 표시합니다. 알림을 밀어도 세션은 종료되지 않습니다. Android 설정에서 알림을 차단하거나 앱을 강제 종료한 경우까지 표시를 보장하지는 않습니다.

각 탭은 독립적인 Linux PTY 세션입니다. 탭을 전환해도 백그라운드 작업은 계속 동작하며, 같은 화면에서 탭을 왕복하면 각 탭의 스크롤 위치가 유지됩니다. 기록이 지워졌거나 줄어든 경우에는 남아 있는 범위로 조정됩니다. Android 화면을 닫거나 최근 앱에서 UI 태스크를 제거해도, 런타임 정책과 시스템이 허용하는 한 VM과 세션은 종료되지 않습니다.

세션 화면을 처음 연결할 때도 실제 화면의 행·열 수를 셸에 전달합니다. 긴 한 줄 명령의 자동 줄바꿈과 커서 이동·삭제가 기본 80열이 아닌 현재 화면 폭을 기준으로 처리됩니다.

세션 종료가 확인되기 전에는 해당 탭이 유지되고 종료 버튼이 잠깁니다. 종료에
실패하면 다른 탭에 영향을 주지 않고 오류를 표시합니다. 마지막 세션을 종료하면
앱과 런타임은 열린 채로 빈 화면을 표시하며, **새 세션**에서 Native, Userspace Linux,
또는 사용 가능한 AVF를 명시적으로 선택할 수 있습니다. 화면 재생성이나 앱 복귀가
빈 상태에서 Native 세션을 자동으로 만들지는 않습니다.

예시:

```sh
while true; do date; sleep 5; done
```

앱을 다시 열고 같은 탭을 선택했을 때 시간이 계속 출력되면 세션 재연결이 정상 동작한 것입니다.

## 3. Android 연동 권한

콘솔 하단의 **Android 접근**에서 게스트가 사용할 기능을 허용할 수 있습니다.

- 클립보드: `droid clipboard get`, `droid clipboard set "텍스트"`
- 링크 열기: `droid open https://example.com`
- 알림: `droid notify --title "완료" --text "빌드가 끝났습니다"`

권한 허용은 Android 운영체제 권한과 별개입니다. 허용하지 않은 기능은 게스트에서 거부됩니다. 이 설계는 임의 Linux 프로그램이 Android Binder나 앱 비공개 데이터에 직접 접근하지 못하게 합니다.

## 4. 파일과 공유

### Linux → Android

**설정 → 공유 디렉토리**에서 폴더를 만들고 실행환경에 연결하세요. Userspace Linux와 직접 공유를 지원하는 AVF 이미지에서는 `/mnt/term-shares/폴더이름`으로 접근합니다. AVF는 호환 기기와 지원 이미지가 필요하며 VM을 중지한 뒤 다시 시작해야 연결 변경이 적용됩니다. 예를 들어 `Project` 폴더를 연결했다면 다음과 같이 파일을 만듭니다.

```sh
echo hello > /mnt/term-shares/Project/test.txt
```

공유 위치에서 `test.txt`를 확인할 수 있습니다.

### Android → Linux

Android 공유 시트에서 TERM을 선택하면 파일은 앱 안의 기존 `inbox` 위치에 사본으로 저장됩니다. 이 위치가 AVF의 직접 공유 폴더에 자동으로 연결되지는 않습니다. 원본 URI나 Android 앱 비공개 저장소가 게스트에 직접 노출되지는 않습니다.

## 5. 개발 서버 포트

게스트에서 서버를 실행합니다.

```sh
python -m http.server 8000
```

**설정 → 로컬 서비스**에서 대시보드를 엽니다. 로컬 서비스는 설정 홈의 **앱 언어** 바로 위에 독립 카테고리로 표시됩니다. 세션이나 AVF 권한이 없어도 사용할 수 있습니다. **설정 → AVF Linux → 전달 포트**는 같은 화면을 AVF 필터로 엽니다.

**전체 / Native / Userspace Linux / AVF**로 목록을 필터링하고 서비스를 선택해 원본 주소, Android 접속 주소, 관측·전달 상태와 출처를 확인하세요. 공유 Android 네트워크에 등록한 항목은 전체에 표시합니다. **새로고침**은 저장된 최신 관측 정보를 다시 읽을 뿐 실행환경·설치·세션을 시작하거나 중지하지 않습니다. 목록과 상세를 닫거나 화면을 회전해도 세션과 포트 전달은 유지됩니다.

Native·Userspace Linux는 **서비스 등록**에서 이름, TCP 포트(1~65535), 논리적으로 연결할 실행환경 또는 공유 Android 네트워크, 선택적인 HTTP/HTTPS를 입력하고 **저장**합니다. 선택한 항목의 상세에서 등록 정보를 수정하거나 삭제할 수 있습니다. 등록 삭제는 프로세스나 세션을 종료하지 않습니다. 이 실행환경들은 Android 네트워크를 공유하므로 등록된 주소는 실제 리스너 실행이나 소유 관계의 증거가 아니며 **리스너 확인되지 않음**으로 표시합니다.

AVF의 새 포트 에이전트가 보고한 리스너는 Android의 `127.0.0.1`에만 프록시를 엽니다. **포트 전달 활성**은 이 프록시가 생성되었다는 뜻이며 게스트 응답 성공을 보장하지 않습니다. 다른 앱이나 VM이 호스트 포트를 사용 중이면 **호스트 포트 충돌**로 표시합니다. 상세의 **호스트 포트 및 프로토콜 변경**에서 예를 들어 AVF 8000 → Android 18000으로 지정할 수 있습니다. 호스트 포트 범위는 1024~65535이며 실패한 변경은 기존 전달을 유지합니다. 서로 다른 실행환경의 같은 포트는 별개 서비스입니다. 보고 연결이 끊기면 해당 실행환경의 전달만 닫고 현재 리스너는 알 수 없음으로 표시하며, 종료 이벤트 또는 완성된 스냅샷에서 사라진 리스너는 **종료 확인됨**으로 표시합니다.

접속 주소가 있는 항목에서는 **Android 접속 주소 복사**와 **Android 포트 복사**를 사용할 수 있습니다. **HTTP 또는 HTTPS를 직접 지정한 경우에만** 브라우저 열기가 표시됩니다. 모든 TCP 포트를 웹 서버로 추정하지 않으므로 위 Python 예제도 상세에서 HTTP를 지정하세요. 프로토콜 선택은 헬스체크가 아닙니다.

이전 AVF 이미지의 에이전트는 포트 번호만 보고하며 TCP 프록시를 제공하지 않습니다. 이 경우 발견된 포트는 표시하지만 주소는 알 수 없음, 전달은 미지원으로 안내합니다. 새 게스트 소스가 포함된 이미지가 필요하며 이 화면은 기존 이미지를 자동 교체하지 않습니다. 일반 Android 전체 포트 자동 탐지, PID 식별·강제 종료, CLI 등록, LAN 공개, 트래픽 분석 및 HTTP 헬스체크는 제공하지 않습니다. TERM이 생성한 전달 포트는 외부 네트워크에 공개되지 않지만 Native·Userspace Linux 서비스 자체의 바인딩 주소는 해당 서버 설정을 따릅니다.

## 6. 설정

**세션** 툴 상단의 톱니바퀴 **설정** 버튼을 누르면 기존 설정 화면을 바로 엽니다. 세션과 워크스페이스가 모두 없어 툴바가 없는 초기 화면에서는 우측 상단의 같은 설정 버튼을 사용합니다. 로컬 서비스는 설정 홈에서 **앱 언어** 바로 위의 독립 카테고리로 제공합니다.

- **터미널 설정 → 터미널 모양**: 글꼴 크기, 사용자 글꼴과 터미널 팔레트를 관리합니다. 기본 고정폭 글꼴은 앱에 포함된 **Google Sans Code**로 통일했습니다. 별도의 **글꼴** 선택 항목은 제공하지 않으며, 이전 Sans 고정폭 선택값도 적용하지 않습니다. 앱의 일반 UI는 **Google Sans**를 사용하고, 한글·가나처럼 지원하지 않는 문자는 앱에 포함된 **Pretendard**를 먼저 사용합니다. 일부 한자처럼 두 글꼴 모두 지원하지 않는 문자는 시스템 글꼴로 대체합니다. **글꼴 파일 추가**에서 TTF, OTF 등의 일반 글꼴을, **이탤릭 글꼴 파일 추가**에서 이탤릭 전용 파일을 여러 개 선택할 수 있습니다. 터미널 프로그램이 이탤릭 속성을 요청하면 이탤릭 목록을 같은 스타일별 우선순위로 먼저 적용하며, 등록하지 않았거나 해당 문자를 지원하지 않으면 일반 글꼴의 합성 이탤릭으로 fallback합니다. 일반과 이탤릭 목록은 각각 화살표로 우선순위를 바꾸거나 삭제할 수 있습니다. 첫 번째로 사용할 수 있는 일반 사용자 글꼴이 셀 크기의 기준이 됩니다. 추가할 때 파일을 검증하고 앱 내부에 사본을 보관하므로, 앱 업데이트나 원본 문서의 이동·삭제·읽기 권한 변경 후에도 글꼴을 유지합니다. 같은 원본을 다시 선택하면 사본을 갱신하며, 일반·이탤릭 양쪽 목록에서 모두 제거하면 사본도 삭제합니다. 기존 버전에서 등록한 글꼴은 처음 읽을 수 있을 때 사본을 만듭니다. 이미 원본에 접근할 수 없고 사본도 없는 항목은 다음 사용자 글꼴 또는 기본 Google Sans Code로 대체하며, 다시 적용할 때 읽기를 재시도합니다. 이 경우 원본 글꼴을 다시 선택하면 복구할 수 있습니다. 올바르지 않거나 읽을 수 없는 새 파일은 등록하지 않습니다. 한글/CJK 등 Unicode 폭이 2인 글리프는 항상 원래 비율을 유지해 2셀 영역 중앙에 배치합니다. 단일 셀 글자는 셀 폭에 맞추고, 커서·선택·배경·줄바꿈은 셀 단위를 유지합니다. **자연스러운 넓은 글자**와 **고정 문자 폭** 설정은 제거되었으며, 이전에 저장한 값과 관계없이 이 표시 방식을 사용합니다. 글자 크기는 시스템 글꼴 배율을 따르는 실제 sp 단위이며, 터미널로 돌아오면 적용됩니다.
- **Userspace Linux**: **네트워크 → DNS**에서 전역 DNS 정책을 설정합니다. PRoot·아키텍처·가속과 엔진 상세는 **진단 및 리포트 → Userspace Linux**에서 확인합니다. Debian·Ubuntu·Arch 실행환경의 설치·삭제·초기화·저장 공간·rootfs·홈과 환경별 설정은 **설정 → 실행환경**에서 관리합니다. Profile은 실행환경에 진입하는 방법을, Session은 실제 실행 중인 터미널을 뜻합니다.
- **Userspace Linux DNS**: 기본값은 **Android 네트워크 설정 사용**입니다. **사용자 지정**을 고르면 서버 목록과 **DNS 서버 추가** 항목이 나타납니다. 추가 항목을 눌러 IPv4·IPv6 주소 한 개를 입력하고 **추가**를 누르세요. 최대 3개까지 추가할 수 있으며 3개가 되면 추가 항목이 비활성화됩니다. 주소 옆의 삭제 버튼으로 항목을 지우면 다시 추가할 수 있습니다. 잘못된 주소·여러 주소·중복 주소는 추가할 수 없습니다. **저장**을 누르면 목록의 변경 사항을 모든 Userspace Linux 실행환경의 새 세션과 설치·보완 작업에 적용합니다. **취소**나 뒤로가기는 기존 정책을 유지합니다. Android 모드는 시작 시 현재 네트워크가 제공하는 서버 목록을 사용하며 임의의 공용 DNS로 대체하지 않습니다. Android 비공개 DNS의 암호화 기능은 적용되지 않으며 실행 중인 프로그램은 DNS 정보를 캐시할 수 있습니다.
- **Userspace Linux 진단**: APK의 PRoot 실제 버전, Loader·가속 프로필·Faststat·기기의 지원 ABI와 저장 형식별 자동 링크 정책을 표시하고 확인할 수 없는 값은 명시합니다. 배포판 상태를 조회하지 않으며 PRoot 내부 옵션은 TERM이 자동으로 관리합니다. 진단 하단의 제한 안내처럼 실제 root·Linux namespace·cgroup·kernel mount·완전한 systemd boot는 제공하지 않으며 syscall/filesystem translation 오버헤드가 있습니다. 실제 Linux kernel이 필요한 기능은 AVF가 필요할 수 있습니다.
- **앱 정보**: 앱 버전, 실제 패키지명, 빌드 타입, 빌드 번호, 업데이트 채널과 빌드 리비전을 확인하고 값을 선택해 복사할 수 있습니다. **오픈소스 라이선스**에서 앱·라이브러리·글꼴·아이콘·런타임에 포함된 라이선스와 고지문 원문을 인터넷 연결 없이 읽을 수 있습니다.
- **AVF Linux**: 다음 시작에 적용할 메모리, vCPU, 보호 모드, 네트워크를 관리하고 전달 포트를 확인합니다. 특정 VM의 이미지 설치 여부·버전·진행, VM ID와 영속 디스크, 시작·중지·삭제는 **설정 → 실행환경**의 해당 실행환경 상세에서 관리합니다. 초기 설정의 오프라인 이미지 가져오기는 기존 기본 AVF 경로를 유지합니다.
- **Native 셸**: 새 Native 세션에 적용할 기본 셸을 관리합니다.
- **터미널 설정**: 공통 TERM·스크롤백, Native·Userspace Linux 로그인 셸, 공유 내부저장소, 백그라운드 실행과 앱 권한을 관리합니다. 로그인 셸 설정은 AVF에 적용되지 않으며, 공유 내부저장소는 지원 이미지의 비보호 AVF VM에서도 사용할 수 있습니다. **백그라운드 실행**의 절전 정책과 배터리 최적화 제외는 Native·Userspace Linux에서도 사용할 수 있습니다.
- **입력 설정 저장**: 숫자, 기본 셸 경로, 단일 선택은 입력 중에 저장되지 않습니다. 대화상자의 **저장**을 누를 때 전체 값을 검증하며, 숫자는 표시 범위 안이어야 하고 기본 셸은 앱이 실제로 실행할 수 있는 절대 경로여야 합니다. 입력 중 화면이 회전해도 대화상자와 초안은 유지됩니다.
- **런타임 반영 시점**: AVF 리소스는 다음 AVF 시작, TERM과 로그인 셸은 새 Native 세션에 적용됩니다. 절전 정책은 실행 중인 런타임 서비스에 즉시 전달됩니다.
- **절전 정책**
  - 배터리 최적화: 추가 wake lock을 잡지 않습니다.
  - 작업 중 유지: 화면 연결 여부와 무관하게 명령이 실제 실행 중이거나 설치·시작 작업 또는 게스트의 작업 신호가 있을 때 wake lock을 사용합니다. 셸이 확인된 프롬프트에서 기다리면 해제합니다. 작업 알림 설정을 꺼도 이 판단은 유지됩니다. 명령 경계 신호가 없는 셸은 생성 또는 마지막 실제 입력·출력 이후 최대 10분 동안 보수적으로 보호합니다. 이런 셸의 조용한 장시간 작업이나 별도 신호가 없는 백그라운드 셸 작업은 정확히 감지할 수 없으므로 정상 동작하는 셸 연동 또는 명시적인 항상 유지 정책이 필요합니다.
  - 런타임 실행 중 항상 유지: 기본값입니다. 살아 있는 세션이나 진행 중인 작업이 있으면 화면이 꺼지거나 출력이 없어도 wake lock을 계속 갱신하므로, SSH 연결·조용한 작업·별도 백그라운드 셸 작업에 유휴 시간 제한을 적용하지 않습니다. 마지막 세션과 작업이 끝나거나 런타임이 중지·실패하면 해제합니다. 이전 버전에서 절전 정책을 직접 선택하지 않았다면 새 기본값으로 전환하며, 직접 선택한 정책은 보존합니다. 배터리 사용량이 늘 수 있습니다.
- **배터리 최적화 제외**: **터미널 설정 → 백그라운드 실행**에서 눌러 Android의 허용 창에서 승인합니다. 화면이 꺼졌을 때 Doze가 네트워크와 CPU를 제한하는 것을 줄이기 위한 별도 설정이며, 현재 허용 상태는 화면으로 돌아오면 갱신됩니다. 항상 유지 정책만으로는 Android의 Doze 네트워크 제한이 해제되지 않습니다. 허용을 거부해도 세션은 사용할 수 있습니다.
- **Android 권한**: Android 시스템의 앱 권한 화면을 엽니다.
- **진단 및 리포트**: Android Native·Userspace Linux·AVF Linux·메모리·크래시 리포트를 각각 별도 화면에서 확인합니다. Native는 백엔드와 기본 셸, Userspace Linux는 PRoot·Loader·가속·Faststat·ABI·스토리지 링크 정책을 표시합니다. AVF는 Android 버전·시스템 기능·두 권한·Custom Image API·VirtualMachineManager·TERM 드라이버를 충족·미충족·확인 불가로 구분하며, VM을 만들거나 실행하지 않습니다. 필수 조건 충족이 VM 부팅 성공을 의미하지는 않습니다. 메모리는 장치 전체·사용·가용·비율과 UI·:vmhost의 PSS 합계 및 세부 영역을 표시하며 한 프로세스라도 측정 불가이면 합계도 확인 불가입니다. 화면을 사용하는 동안 5초마다 갱신하고 수동 새로고침을 지원합니다. 크래시 리포트는 기존 기록을 포함해 최근 20개를 최신순으로 표시하고 상세의 원문 복사를 제공합니다. 닫거나 뒤로 가도 기록은 유지됩니다. 개별 배포판·VM 상태는 **실행환경**에서, 로컬 서비스는 **로컬 서비스**에서 확인합니다.

Userspace Linux 데이터를 모두 제거하려면 **설정 → 실행환경**에서 해당 실행환경을 선택합니다. 연결된 프로필과 활성 세션을 먼저 제거한 뒤 **실행환경 삭제**를 확인하면 배포판 제거 절차를 거쳐 rootfs·설치 캐시·패키지·홈·설정·작업 폴더 등 실행환경의 모든 데이터를 함께 삭제합니다. 다른 실행환경과 legacy 공용 작업 폴더는 유지합니다. 실행환경과 프로필을 유지하고 배포판만 제거하려면 실행환경 상세의 **배포판 제거**를 사용합니다.

## 7. 종료와 복구

- 콘솔 화면을 닫는 것은 **세션 종료가 아니라 연결 해제**입니다.
- 세션을 끝내려면 해당 탭의 종료 아이콘을 누르고 **세션 종료**를 확인합니다. **탭 삭제 시 묻지 않기**를 켠 경우에는 확인 없이 종료됩니다. 이 동작만 해당 PTY의 실행 중인 작업을 종료합니다.
- 비정상 종료 뒤에는 앱을 열어 **진단 및 리포트 → 크래시 리포트**에서 오류 원문을 확인하고 해당 **실행환경** 상세에서 런타임·이미지 상태를 확인합니다.
- VM 소유 프로세스나 시스템이 실제로 VM을 종료한 경우, Linux 프로세스가 살아 있다고 표시하지 않습니다. VM을 다시 시작해야 합니다.

## 8. 자주 발생하는 문제

| 증상 | 확인 및 해결 |
| --- | --- |
| `AVF 실행환경 설정에서 Debian 이미지를 설치하세요.` | 해당 AVF 실행환경 상세에서 **이미지 설치**를 선택합니다. 기본 AVF 저장공간은 필수 여섯 파일이 있는 로컬 이미지 디렉터리로 오프라인 설치할 수도 있습니다. |
| `AVF custom VM access requires ...` | 일반 APK 제한입니다. OEM/플랫폼 서명 AOSP 배포와 AVF 시스템 드라이버가 필요합니다. |
| 다른 AVF 실행환경을 열 때 `avf_tap_fixed`·`TUNSETIFF`·`EACCES` 오류 | 기기가 AVF 네트워크의 고정 TAP 인터페이스를 공유하는 경우 여러 VM의 동시 네트워크 연결이 제한될 수 있습니다. 앱은 원래 원인과 함께 이 제한을 안내하고 기존 VM과 네트워크 설정을 유지합니다. 두 VM 모두 인터넷이 필요하면 Android 플랫폼의 VM별 TAP·브리지 지원이 필요하며, 현재 AVF API에서 VM 이름을 바꾸거나 앱 권한을 추가하는 것으로 고정 TAP을 분리할 수 없습니다. 같은 실행환경의 추가 세션은 기존 VM을 재사용합니다. |
| AVF에서 `apt update`가 `Temporary failure resolving 'deb.debian.org'`로 실패 | 게스트의 DHCP·DNS 설정과 Android의 VM 네트워크 연결을 확인합니다. 기존 이미지의 복구 방법은 아래 **AVF에서 APT가 DNS 오류로 실패할 때**를 참고하세요. 실패 뒤의 `All packages are up to date`는 저장소 갱신 성공을 뜻하지 않습니다. |
| 세션 탭이 보이지 않음 | 런타임 상태를 확인한 뒤 **세션** 툴 상단의 **새 세션**을 누릅니다. |
| 앱을 다시 열자 출력이 없음 | 같은 세션 탭을 다시 선택합니다. 해당 실행환경 상세에서 VM이 실제로 중지됐는지 확인합니다. |
| 백그라운드나 화면 꺼짐 뒤 SSH가 `broken pipe`로 끊김 | **터미널 설정 → 백그라운드 실행**에서 **런타임 실행 중 항상 유지**와 **배터리 최적화 제외**를 허용합니다. 제조사별 앱 배터리 설정에도 제한이 있다면 제한 없음을 선택합니다. 강제 종료·메모리 부족·통신망 변경이나 SSH 서버의 시간 제한까지 없애는 기능은 아닙니다. |
| 포트가 표시되지 않음 | 게스트 프로세스가 실제로 리스닝 중인지 확인하고, `droid-port-agent` 서비스 상태를 확인합니다. |
| Android 기능이 거부됨 | 콘솔의 Android 접근 권한과 Android 시스템 권한을 모두 확인합니다. |

### AVF에서 APT가 DNS 오류로 실패할 때

`avf-debian-20261005`부터 신규 설치 이미지에는 가상 네트워크 장치의 DHCP와 게스트 DNS 초기 설정이 포함됩니다. 앱 업데이트만으로 이미 설치한 이미지가 변경되지는 않으며, 기존 환경은 아래 절차로 복구할 수 있습니다.

기존 `avf-debian-20261004` 이미지에는 빌드 환경의 DNS인 `169.254.169.254`가 남아 있을 수 있습니다. `ip -br address`에서 실제 NIC인 `enp0s8` 등이 `DOWN`이고 `ip route`에 기본 경로가 없다면 DHCP 설정도 필요합니다. 아래 명령은 AVF 터미널 안에서 실행하며, NIC 이름 대신 `virtio_net` 드라이버에 맞춰 주소·경로·DNS를 받도록 설정합니다.

```sh
sudo install -d -m 0755 /etc/systemd/network
sudo tee /etc/systemd/network/10-term-virtio.network >/dev/null <<'EOF'
[Match]
Driver=virtio_net

[Network]
DHCP=yes

[DHCPv4]
UseDNS=yes
UseHostname=no

[DHCPv6]
UseDNS=yes
UseHostname=no
EOF
sudo ln -sfn /run/systemd/resolve/stub-resolv.conf /etc/resolv.conf
sudo systemctl enable systemd-networkd.service systemd-resolved.service
sudo systemctl restart systemd-networkd.service systemd-resolved.service
```

그다음 `ip -br address`, `ip route`, `resolvectl status`로 DHCP 주소·기본 경로·DNS가 생겼는지 확인하고 `getent hosts deb.debian.org`를 실행합니다. DHCP 협상이 끝나기 전에 확인하면 잠시 주소가 없을 수 있습니다. 이름 해석이 성공하면 `sudo apt-get -o APT::Update::Error-Mode=any update`로 저장소를 갱신합니다. 이 옵션은 일부 인덱스 다운로드가 실패해도 성공처럼 끝나는 것을 막습니다.

설정 후에도 주소나 기본 경로가 없다면 **설정 → AVF Linux → 네트워크**가 켜져 있는지 확인하고, 필요한 설정은 다음 VM 시작에 적용합니다. 이미 IP 연결이 있다면 `resolvectl status`의 DHCP DNS와 Android의 VM 테더링·외부 연결을 확인해야 합니다. Vsock으로 터미널을 열 수 있다는 사실만으로 인터넷 연결을 보장하지는 않습니다. 새 이미지 생성 과정에는 위 설정이 포함되지만 APK 업데이트만으로 기존 이미지나 실행 중인 VM이 변경되지는 않습니다.

## 9. 보안 주의사항

Linux 게스트는 신뢰하지 않는 코드도 실행할 수 있는 실행환경입니다. Android 권한은 필요한 기능만 허용하고, 공유 디렉터리에 민감한 앱 데이터나 비밀 키를 무분별하게 두지 마세요. 기본 **런타임 실행 중 항상 유지** 정책과 배터리 최적화 제외는 배터리 사용량을 늘릴 수 있으므로, 더 이상 필요 없는 세션은 종료하세요.

### 공유 내부저장소 접근

**설정 → 터미널 설정 → 내부저장소 접근 설정**에서 Android의
**모든 파일 접근 허용**을 켜거나 끌 수 있습니다. 기본값은 사용 안 함이며,
Native·Userspace Linux와 지원 이미지의 비보호 AVF VM에 공통으로 적용됩니다. Userspace Linux·AVF는 실행환경 상세의 **권한 → 내부저장소 접근**도 켜야 합니다. 새 환경 생성 시에도 선택할 수 있으며 기본은 꺼짐입니다. 기존 환경은 이전 동작을 유지합니다. 프로필 생성 화면의 기본 Native에도 내부저장소 접근 스위치가 표시됩니다. Native 스위치는 실제 Android 공통 권한 상태를 표시하며 누르면 권한 설정으로 이동합니다. 시스템 설정에서 변경한 권한은 프로필 저장과 관계없이 앱 전체에 적용되며 Native 환경별로 접근을 차단할 수는 없습니다. 거절하거나 뒤로 돌아오면 기존 권한 상태가 유지됩니다.

Android 권한을 허용하고 환경별 연결 선택을 적용한 새 세션에서 `cd /sdcard`로 이동하면 Download, Documents 등의 공유
파일을 읽고 쓸 수 있습니다. Native에서는 `/storage/emulated/0` 같은 Android
경로도 사용할 수 있고, Userspace Linux에서는 `/sdcard`로 연결됩니다. 기존 Userspace Linux
세션에는 연결이 추가되지 않으므로 필요한 경우 새 세션을 여세요. AVF는 내부저장소 공유를 지원하는 이미지와 호환 기기가 필요하며 해당 환경의 내부저장소 접근을 켜고 VM을 중지한 뒤 다시 시작하면 `/sdcard`에 연결됩니다. 실행 중 VM에 자동으로 마운트를 추가하지 않으며 이전 이미지와 보호 VM은 이 기능을 사용하지 않습니다.
다른 앱의 `/data/data/...`와 `Android/data` 등 Android 보호 경로는 열리지 않습니다.

환경별 선택을 끄면 Userspace Linux는 이후 새 세션에 저장소를 연결하지 않고 AVF는 다음 VM 부팅에 공유하지 않습니다. 기존 세션·VM의 마운트는 유지되므로 즉시 공유를 끝내려면 해당 세션 또는 VM을 중지하세요. Native·Userspace Linux의 환경 옵션은 Android 권한을 분리하거나 파일 접근을 격리하는 보안 기능이 아닙니다. 앱 전체의 넓은 접근을 해제하려면 Android 공통 권한을 끄세요. 백업으로 복원한 새 환경은 내부저장소 연결이 꺼진 상태로 생성됩니다.

끄려면 같은 항목에서 Android 권한을 해제하세요. 내부저장소를 공유하는 AVF VM을 중지하며 Android가 앱과 다른 실행 중인 세션도 종료할 수 있으므로 먼저 작업을 저장하세요. 권한을 사용하지 않아도
앱 전용 저장소와 공유 디렉토리는 계속 사용할 수 있습니다. 기존 `/workspace` 데이터는 공유 디렉토리 설정에서 복사하거나 내보낼 수 있습니다. 접근을 꺼도
Android가 기본적으로 허용하는 앱 소유 공유 파일 접근까지 없애는 것은 아닙니다.


### 툴바 설정

**설정 → 터미널 설정 → 사용자 설정 → 툴바 설정**에서 추가 툴을 켜거나 끕니다. **세션** 툴은 제거할 수 없습니다. 세션과 워크스페이스가 모두 없을 때는 툴바 전체가 숨겨집니다. 현재 워크스페이스가 비어 있어도 다른 세션이나 워크스페이스가 있으면 툴바를 유지합니다. 툴바 설정의 **세션** 항목에서 **탭 삭제 시 묻지 않기**를 선택할 수 있습니다. 기본값은 꺼짐이며, 켜면 탭의 닫기 버튼이 세션과 실행 중인 작업을 확인 없이 즉시 종료합니다. 설정은 저장되어 앱을 다시 열어도 유지됩니다.
핸들을 위아래로 드래그하여 **확장 / 기본 / 숨김** 상태로 바꿀 수 있습니다.
숨김 상태에서도 핸들은 남고, 탭하면 다시 펼쳐집니다. 핸들 탭은 기본 → 확장 → 숨김
순서로 전환합니다. 도구가 여러 개이면 기본·확장 상태에서 좌우로 쓸어 전환합니다.
기본 도구는 **세션**과 **터미널 단축키**입니다. **세션** 툴 상단에는 새 세션·설정 버튼이 표시됩니다. 기본 크기에서는 버튼 옆에 가로 탭 목록이, 확장 크기에서는 아래에 세로 탭 목록이 표시됩니다. 가로 탭 목록의 시작이나 끝까지 스크롤한 뒤 같은 방향으로 다시 쓸면 인접한 도구로 전환합니다. 선택된 탭과 선택되지 않은 탭 모두 제목·아이콘·여백·종료 버튼 등 어느 부분에서 시작해도 같은 방식으로 전환할 수 있습니다.

**세션 → 새 세션**을 누르면 툴바가 부드럽게 확장되고 같은 시트 안에서 프로필 선택 페이지로 이동합니다. 현재 세션 화면과 프로필 선택 화면은 들어가기와 뒤로가기 방향에 맞춰 슬라이드와 페이드로 전환합니다. 프로필의 아이콘·이름과 연결된 실행환경·런타임을 확인하고 목록을 위아래로 스크롤할 수 있습니다. 상단 뒤로가기나 Android 뒤로가기는 세션 목록으로 돌아갑니다. 프로필을 선택하면 해당 설정으로 새 세션을 열고 전환한 뒤 시트를 숨깁니다. 목록 끝의 **새 프로필 만들기**는 프로필 편집 화면을 엽니다.

편집에서 다음 도구도 추가할 수 있습니다.

- **명령 기록**: 터미널의 명령·출력을 검색하고 보관된 명령으로 이동합니다.
- 장치·앱 메모리는 **설정 → 진단 및 리포트 → 메모리**에서 확인합니다. 개별 세션의 메모리는 세션 탭의 길게 누르기 또는 확장 목록의 작업 메뉴에서 **세션 정보**를 엽니다. RSS는 접근 가능한 셸·하위 프로세스의 추정값이며 공유 페이지 중복·분리된 데몬 누락이 가능합니다. AVF·종료·접근 제한은 확인 불가로 표시하고 앱 PSS와 합산하지 않습니다. 이전 설정에 메모리 도구가 남아 있으면 그 도구만 제외하며 다른 도구의 순서·사용 여부와 저장 데이터는 유지합니다.
- 평소에는 추가한 도구만 보이며 `>`가 있는 항목을 누르면 도구 설정을 엽니다.
- **편집** FAB를 누르면 도구 추가·제거 버튼이 나타납니다. 추가된 도구의 핸들을
  드래그하면 순서가 바뀝니다. 세션 툴도 순서를 바꿀 수 있지만 제거할 수 없습니다. 추가되지 않은 도구에는 순서 핸들이 없습니다.
- 변경은 바로 저장됩니다. **완료**를 누르면 일반 목록으로 돌아옵니다.
- 도구를 제거하거나 툴바를 꺼도 단축키 배치는 보존됩니다. 추가 툴 사용을 꺼도 세션 툴과 핸들은 유지됩니다.
- 기존 단축키 사용 여부는 툴바 사용 여부로 이어받습니다.
- 이전 버전의 설정에 제거된 도구가 남아 있으면 목록에서 제외하며 다른 도구의 순서와 추가 툴 사용 여부는 유지됩니다.

### 터미널 단축키 편집

**설정 → 터미널 설정 → 툴바 설정 → 터미널 단축키**에서 배치와 단축키를 편집합니다.

- 툴바의 **드래그 핸들**로 높이를 조절하거나 숨깁니다. 터미널의 두 손가락 스와이프는 툴바를 변경하지 않습니다. 핀치 글자 크기 조절은 그대로 사용할 수 있습니다.
- 단축키 표시 여부는 **툴바 설정**에서 도구 추가·제거로 관리합니다. 단축키 편집 화면의 **저장**은 배치만 변경합니다.

- 미리보기의 키를 **꾹 누른 채 드래그**하면 원하는 빈 칸으로 옮길 수 있습니다. 끌고 있는 키는 격자에 묶이지 않고 손가락을 따라 자유롭게 움직이며, 놓을 위치만 점 격자에 맞춥니다. 키를 앞에서부터 채울 필요가 없으며, 서로 떨어진 위치와 행 사이의 빈 공간도 그대로 저장됩니다. 다른 키의 **중앙**에 겹치면 두 키의 위치를 교환합니다. **가장자리**로 가져가면 주변 키가 좌우 또는 위아래로 이동해 두 키 사이에 끼워 넣을 자리를 만듭니다. 같은 행이나 열의 빈 칸과 이동 전 자리를 우선 활용하고, 공간이 부족하면 인접 행이나 열도 활용합니다. 서로 크기가 다른 키는 두 위치에 안전하게 들어갈 때 교환합니다. 주변 키는 애니메이션으로 놓을 자리를 미리 보여줍니다. 손을 놓으면 배치가 확정되고, 끌던 키가 그리드 위치로 부드럽게 이동합니다. 드래그 취소나 보이는 편집 영역 밖에 놓기는 모든 키를 원래 배치로 되돌립니다. 빨간 테두리는 배치할 공간이 부족하거나 편집 영역 밖인 상태입니다.
- 키를 한 번 누르면 네 모서리에 조절점이 나타납니다. 모서리를 잡고 끌어 키의 **너비와 높이**를 한 칸씩 함께 바꾸며 손을 놓을 때 확정합니다. 옆이나 아래에 있는 키는 자리를 비우고 크기 변화와 주변 키의 이동에 애니메이션을 적용합니다. 키는 최소 1칸 너비·40dp 높이를 유지합니다. 선택한 키 이름 옆의 **편집 아이콘**에서 이름과 조합을 수정하고, 옆의 **삭제 아이콘**으로 키를 삭제합니다. 마지막 키의 삭제 아이콘은 비활성화됩니다. 키를 삭제해도 다른 키는 움직이지 않습니다.
- **배치 영역 가로 칸**으로 가로 공간을 늘리고 **키 글자 크기**를 조절할 수 있습니다. 키가 놓인 영역보다 작게 줄일 수는 없습니다. 좁은 화면에서는 좌우로 스크롤합니다. 아래쪽 빈 곳에 키를 옮기면 영역이 늘어나며, 화면 가장자리에 머무르면 자동으로 스크롤됩니다. 실제 툴바도 빈 공간과 키 높이를 유지하고 표시 영역을 넘으면 스크롤합니다. 접근성 동작도 네 방향 이동과 너비·높이 조절을 한 칸씩 수행합니다. 이전에 저장한 소수 좌표 배치는 해당 키를 이동하거나 크기를 조절할 때 격자에 맞춰집니다.
- **단축키 추가**에서 원하는 이름(1~32자)과 조합을 지정합니다. 예를 들어 이름을 `중단`, 조합을 `CTRL+C`로 저장하면 버튼 한 번으로 Ctrl+C를 보냅니다. 기존 키의 조합도 같은 방식으로 대체할 수 있습니다.
- CTRL, ALT, SHIFT와 영문자·숫자·기호 또는 TAB, ENTER, ESC, 방향 키(UP/DOWN/LEFT/RIGHT), HOME/END, PAGEUP/PAGEDOWN, BACKSPACE/DELETE/INSERT, F1~F12를 조합합니다. 공백은 SPACE, 더하기 기호는 PLUS로 입력합니다. `SPACE`, `CTRL+SPACE`, `ALT+SPACE`, `SHIFT+SPACE`, `CTRL+SHIFT+SPACE`처럼 직접 입력할 수 있습니다. 예: `CTRL+SHIFT+TAB`, `ALT+LEFT`.
- CTRL, ALT 또는 SHIFT만 지정한 버튼은 다음 키에 적용되고 입력 후 해제되는 보조 키입니다. 다시 누르면 선택을 취소합니다. 단독 SHIFT는 **단축키 추가**에서 조합에 `SHIFT`를 입력해 추가합니다. 조합 버튼은 미리 선택된 보조 키를 대체합니다. 이는 터미널 입력이며 Android 앱의 복사/붙여넣기 단축키나 여러 명령을 실행하는 매크로가 아닙니다.
- 화살표·Backspace·Delete·Page Up/Down 버튼은 길게 누르면 400ms 뒤부터 60ms 간격으로 반복 입력됩니다. 해당 키를 사용하는 조합 버튼도 반복됩니다. 짧게 누르면 한 번만 입력하며, 손을 떼거나 터치가 취소되거나 세션 탭·앱을 전환하면 반복이 멈춥니다. 설정 화면의 길게 누르기는 키 위치 이동 동작입니다.
- 설정 화면 하단의 플로팅 툴바에서 **최근 저장 상태로 돌아가기**, **단축키 추가**, **저장**을 사용할 수 있습니다. **저장**을 누르면 현재 배치가 적용되고 화면을 유지합니다. **최근 저장 상태로 돌아가기**는 저장 이후의 편집을 버리고 가장 최근 저장한 배치·글자 크기·가로 칸 수로 되돌립니다. 변경이 없으면 비활성화됩니다. 저장하지 않고 뒤로 나가면 변경사항 폐기를 확인합니다.
- 최대 48개까지 추가할 수 있으며 마지막 키는 삭제할 수 없습니다. 좁은 화면에서는 열 수와 키 위치를 유지하고 좌우로 스크롤하며, 긴 툴바는 위아래로 스크롤할 수 있습니다.

## 터미널 안에 이미지 표시

Sixel과 kitty 이미지 출력, 애니메이션, Unicode placeholder, 상대 배치와
잘라내기를 사용할 수 있습니다. Userspace Linux는 파일·임시 파일·`/dev/shm` 전송도
지원합니다. Native 파일 전송은 해당 런타임의 홈·임시 디렉터리를 포함한
Native 루트 안으로 제한되며 POSIX 공유 메모리는 지원하지 않습니다.
SSH 등 파일시스템이 다른 실행환경에서는 direct/stream 전송을 선택하세요.
UI 재연결은 살아 있는 런타임이 보관한 이미지·애니메이션·배치를 복원합니다.
이미지 저장 한도를 넘어서 삭제된 이미지나 실제 런타임 종료로 사라진 상태는
복원 대상에 포함되지 않습니다. 테스트 명령과 상세 범위는
[터미널 그래픽 문서](TERMINAL_GRAPHICS.md)를 참고하세요.

### Kitty 키보드와 창 관리

Kitty 키보드를 사용하는 프로그램은 협상 후 확장 키·키 해제·IME 입력을
받습니다. 설정 → 터미널 설정의 **Kitty 원격 제어**를 켜고 만든 새 세션에서는
같은 실행환경의 탭을 생성·선택·이름 변경·입력·종료할 수 있습니다.
기본값은 꺼짐이며, 끄면 기존 권한도 회수됩니다. 원격으로 만든 자식 탭에는
권한을 주지 않습니다. 이 권한은 해당 세션에서 실행하는 모든 프로그램에
적용되므로 신뢰하는 작업에만 켜세요. `close-window`는 프로세스도 종료합니다.
지원 명령과 데스크톱 기능과의 차이는 [Kitty 호환성 문서](KITTY_PROTOCOL.md)에 있습니다.

### Codex CLI에서 `/pet`이 지원되지 않는다고 나올 때

Codex CLI 0.153.4에서는 터미널이 Sixel 지원 응답을 보내도 기본
`TERM=xterm-256color` 실행환경에서 펫 사용을 거절하는 경우를 재현했습니다.
**kitty 그래픽 호환성**을 켠 뒤 새 Userspace Linux 세션에서 Codex를 실행하면
고유한 `KITTY_WINDOW_ID`로 이미지 지원을 감지할 수 있습니다. 별도 PTY에서
해당 버전의 PNG 전송을 확인했으며, Android에서 Codex 자체의 전체 동작을
검증했다는 뜻은 아닙니다. 그래픽 사용에 원격 제어 권한은 필요하지 않습니다.

기존 세션에서는 현재 Codex를 종료한 뒤 다음처럼 실행하는 방법도 있습니다.

```sh
TERM=xterm-sixel codex
```

이 설정은 해당 Codex 실행에 적용됩니다. tmux를 사용 중이라면 먼저 tmux
밖에서 확인하세요. Codex가 실행하는 자식 명령도 이 값을 상속하므로,
`unknown terminal` 오류가 나는 일반 터미널 프로그램은
`TERM=xterm-256color 명령어`로 실행할 수 있습니다. 상세 검증과 범위는
[Codex 펫 호환성 설명](TERMINAL_GRAPHICS.md#codex-cli-pets-capability-detection-compatibility)을
참고하세요.

### 출력이 계속되는 동안 이전 내용 읽기

**터미널 설정 → 터미널 기록 → 부드러운 스크롤**을 켜면 손가락 이동과
관성 스크롤을 한 줄보다 작은 픽셀 단위로 표시합니다. 기본값은 꺼짐이며
터미널로 돌아오면 적용됩니다. 마우스 보고나 대체 화면을 사용하는 터미널
프로그램은 기존 행 단위 입력을 유지합니다. 스크롤 햅틱은 별도 설정을 따릅니다.
기록의 맨 위·아래에 가까워져도 남은 거리 때문에 관성 스크롤이 느려지지 않습니다. 스와이프 세기에 맞춰 이동하다가 실제 끝에 도달하면 멈춥니다.

위로 스크롤하면 펫 애니메이션이나 새 출력이 와도 읽던 내용을 유지합니다.
맨 아래로 직접 내려가거나 키보드 입력·붙여넣기를 하면 최신 출력을 다시
따라갑니다. 다른 탭으로 전환했다가 돌아와도 읽던 위치를 유지하며, 기록
한도를 넘어 사라진 내용은 남아 있는 가장 오래된 위치까지만 유지됩니다.
설정 화면이나 다른 앱으로 잠시 이동했다가 돌아오는 동안에도 화면 쪽 터미널
모델을 유지하므로, 복귀할 때 전체 기록을 다시 재생하지 않고 최신 상태를 즉시
표시합니다. Android가 앱 프로세스를 종료한 경우에는 런타임에 다시 연결해
상태를 동기화합니다.

### 터미널 색상 팔레트

하단 툴바 시트는 **전체 화면 TUI 배경색 따르기** 설정과 관계없이 터미널 배경과 비슷한 색감을 유지하면서 밝기를 조금 다르게 표시합니다. 기본·확장·숨김 상태와 프로필 선택 페이지에서도 같은 시트 색상을 사용하며 터미널 배경이 바뀌면 함께 갱신됩니다.

**터미널 설정 → 사용자 설정 → 전체 화면 TUI 배경색 따르기**를 켜면 alternate screen을 사용하는 전체 화면 앱의 기본 배경색에 세션 툴·탭·툴바와 터미널 여백이 맞춰집니다. 앱이 알린 기본 배경을 우선하며, 화면 전체를 지울 때 사용한 배경이 화면에 남아 있으면 부분 강조색으로 주변 UI가 바뀌지 않습니다. 화면 전체를 다시 칠해 이전 배경이 사라지고 새 배경이 화면에 일관되게 나타나면, 전체 화면 지움 없이 바꾼 테마도 다음 출력 프레임에 반영합니다. 기본 배경으로 돌아가는 테마 변경도 같은 방식으로 반영합니다. 배경을 확인하기 어려운 분할 창 등에서는 이전 전체 지움 배경을 유지하거나 현재 세션의 팔레트 배경을 사용합니다. 화면 전체를 같은 강조색으로 덮는 경우는 테마 변경과 구별하기 어렵습니다. 글자·아이콘과 시스템 표시줄 아이콘도 배경에 맞는 대비로 바뀝니다. 기본값은 꺼짐이며, 앱을 종료하거나 옵션을 끄면 현재 세션의 팔레트 배경색으로 돌아옵니다. 일반 셸 화면에는 적용하지 않습니다.

TUI 배경색 따르기가 적용되는 동안에는 배경색을 기준으로 M3 Expressive 동적 색상을 생성합니다. 일반 단축키와 검색 필터 버튼은 배경과 가까운 차분한 색상 계열을 유지하면서 명도 차이로 버튼 형태를 분명히 구분합니다. 글자·아이콘은 보정된 버튼 표면에 맞춰 대비를 유지합니다. CTRL·ALT·SHIFT 활성 상태, 선택한 세션 탭과 진행 표시는 강조색으로 구분하며 글자·아이콘은 읽기 쉬운 대비를 유지합니다. 터미널 화면에서 여는 세션 종료·이름 변경·워크스페이스 이동·설치 안내 등의 모달과 팝업도 같은 동적 색상을 사용합니다. 모달이 열린 동안 TUI 안에서 테마를 바꾸면 모달 표면·글자·버튼·입력 필드를 포함한 색상들이 함께 갱신됩니다. 옵션을 끄거나 전체 화면 TUI를 종료하면 기존 터미널 UI 색상으로 돌아오며 모달과 팝업은 앱 기본 테마로 복원됩니다. 활성 세션이 없는 화면과 설정 화면은 기존 앱 테마를 유지합니다.

**터미널 설정 → 사용자 설정 → 터미널 모양 → 팔레트**에서 기본 팔레트를 고르거나
**팔레트 색상 편집**으로 전경·배경·커서와 표준/밝은 ANSI 16색(검정, 빨강, 초록,
노랑, 파랑, 마젠타, 시안, 흰색)을 `#RRGGBB` 값으로 직접 저장할 수 있습니다.
저장하면 사용자 지정 팔레트가 선택되고, 열려 있는 터미널에도 돌아올 때 적용됩니다.
미리보기의 명령 예시는 예시를 표시할 수 있는 일반 사용자 글꼴을 우선순위대로 사용하며, 사용할 수 있는 사용자 글꼴이 없으면 Google Sans Code로 표시합니다.

### Userspace Linux 기본 실행환경 보완

**실행환경 보완**은 설치된 배포판의 기본 패키지를 설치하고 필수 설정을 적용한 뒤 정상 동작을 확인하는 작업입니다.

Debian은 표준 우선순위 패키지, Ubuntu는 공식 Server 기본 메타패키지,
Arch Linux ARM은 `base`를 따릅니다. 세 배포판에 동일한 개발 도구 묶음을
강제로 설치하지 않습니다. 최초 준비에는 인터넷과 Debian/Arch 2 GiB,
Ubuntu 4 GiB 이상의 여유 공간이 필요합니다.

기존 이미지도 실행환경 상세에서 세션 없이 런타임을 중지한 뒤 **실행환경 시작**을 요청하면 패키지 설치·설정·검증을 진행합니다.
사용자가 만든 홈 설정과 기존 시간대·로케일을 보존하고, 없는 셸 설정은
해당 이미지의 원본에서 복원합니다. 실행 중인 해당 배포판 세션을 먼저
명시적으로 종료해야 하며, 다른 배포판의 세션은 계속 사용할 수 있습니다.
실패하면 원인을 확인하고 재시도하거나 실행환경 전체를 명시적으로 삭제할 수 있습니다.
준비가 끝난 뒤 새 셸을 열 때마다 패키지를 업데이트하지는 않습니다.
PRoot에서는 서버 패키지가 설치되어도 systemd 부팅이나 커널 권한을 얻지는 않습니다.

가속 통합 개발 채널 APK의 stdio 버퍼링 지원 조건과 명령별 켜기·끄기는
[Userspace Linux 파일 I/O 실험 옵션](ROOTLESS_IO_OPTIONS.ko.md)을 참조하세요.
공개 `v0.1.0-rootless.1`에는 이 옵션이 포함돼 있지 않습니다.

### 기존 Userspace Linux 설치의 가속 적용

하드링크 에뮬레이션 가속을 포함한 버전에서는 업데이트 후 **새 세션부터 기존 저장
형식 그대로 가속**합니다. 네이티브 하드링크 생성이나 별도 이전, 앱·배포판 재설치는
필요하지 않습니다. 기존 패키지·홈·작업 폴더와 링크 구조는 그대로 보존합니다.
이 변경 이전 버전 `0.1.0+dev.1000028.09afdf17440b`까지는 해당 동작이 없습니다.

이전 버전에서 실제 이전 작업이 중단되어 임시 상태가 남은 경우에만
**설정 → Userspace Linux → 해당 배포판 → 중단된 이전 복구**가 표시됩니다.
모든 세션과 공유 작업 폴더의 외부 쓰기를 끝낸 뒤 복구하세요. 새 하드링크를 만드는
변환을 다시 시작하지 않고 기존 트랜잭션만 복구합니다. 표시 파일을 직접 수정하지 마세요.

업데이트 전 진행 중인 작업을 저장하세요. Android가 앱 프로세스를 종료하면 기존
세션의 프로세스 상태를 복원할 수 없습니다. 성능과 시험 범위는
[하드링크 에뮬레이션 가속](ROOTLESS_EMULATED_ACCELERATION.md)을 참조하세요.

### Userspace Linux 설치 진행 확인

Debian·Ubuntu·Arch 모두 설정 화면과 설치 창에서 현재 작업을 확인할 수 있습니다.
이미지 다운로드 → 검증·압축 해제 → 패키지 목록 갱신·다운로드·설치 → 기본 설정
→ 최종 동작 검증 순서로 표시합니다. 기존 실행환경 보완에서는 이미지 단계를 건너뜁니다.

다운로드 용량이나 패키지 관리자가 알려주는 진행률이 있으면 프로그레스바와
**현재 단계 %**를 표시합니다. 전체량을 모르는 작업은 움직이는 진행 표시와
경과 시간을 보여줍니다. 100%는 해당 단계의 완료이며 전체 설치 완료는 **준비됨**으로
확인합니다. 오래 새 보고가 없으면 마지막 진행 보고 이후 시간도 표시합니다.
화면을 나갔다 돌아와도 같은 설치 단계와 경과 시간이 유지됩니다.

설치 중 실행환경 상세나 설치 창에서 **설치 취소**를 누르면 해당 배포판의 설치를 중단합니다. 임시 다운로드와 압축 해제 파일을 정리하며 이미 설치된 배포판 파일·홈·작업공간은 보존합니다. **다시 시도**로 중단된 패키지 작업을 복구하고 설치를 이어갈 수 있습니다. **닫기**나 뒤로가기로 화면만 닫으면 설치는 계속됩니다.

AVF Debian도 이미지 설치 진행 카드의 **설치 취소**로 대기·다운로드·검증·설치를 취소할 수 있습니다. 이미 설치 완료된 이미지와 실행 중인 세션은 유지합니다. 취소 후 해당 실행환경 상세에서 이미지 설치를 다시 요청할 수 있습니다.

### 설정 검색

설정 홈의 검색은 메뉴 이름뿐 아니라 하위 화면의 개별 설정 이름·설명·경로도
찾습니다. 예를 들어 **글꼴 크기**, **스크롤백**, **단축키**, **팔레트**를 검색하면
해당 항목과 상위 설정 경로가 표시됩니다. 공백으로 여러 검색어를 입력하면 모두
포함하는 결과를 찾으며, 영문 대소문자는 구분하지 않습니다.
결과를 누르면 관련 설정 화면으로 이동하고, 일반 설정은 해당 섹션부터 표시합니다.
프로필별 항목은 먼저 프로필 목록에서 편집할 프로필을 선택합니다. 검색 결과 선택만으로
설정값을 바꾸거나 권한 요청·설치·삭제를 실행하지 않습니다. 검색을 지우면 기존 홈 메뉴로 돌아갑니다.


## 환경 백업 및 복원

**설정 → 실행환경 → 환경 상세 → 백업 만들기**에서 Native/Userspace Linux의 Data Backup 또는 Userspace Linux의 Full Environment Backup을 선택합니다. Data는 홈과 설정 파일을, Full은 Debian·Ubuntu·Arch의 설치된 배포판과 패키지 데이터베이스까지 보관합니다. 프로필과 워크스페이스는 선택할 수 있습니다. 먼저 대상 환경의 세션을 닫고 Userspace Linux 실행환경을 중지하세요. 백업이 세션이나 프로세스를 강제로 종료하지는 않습니다.

워크스페이스는 기본적으로 제외합니다. 예전 배포판이 공유하는 Legacy 워크스페이스를 포함하면 다른 환경에서 만든 파일도 포함될 수 있으므로 별도 확인이 필요하며 공유하는 환경도 모두 유휴 상태여야 합니다. 복원할 때는 새 환경 전용 워크스페이스로 복사합니다. 임시 파일, 알려진 다운로드 캐시, 실행 중 프로세스, 세션 상태와 스크롤백은 보관하지 않습니다.

백업에는 SSH 키, 토큰, 셸 기록 등 민감정보가 들어갈 수 있습니다. 기본으로 켜진 비밀번호 암호화를 권장합니다. 비밀번호는 복구할 수 없으므로 별도로 안전하게 보관하세요. 저장 위치 선택기에서 `.termbackup` 파일 위치를 지정한 다음 **백업 시작**을 누릅니다.

**설정 → 실행환경 → 백업 및 복원 → 백업 가져오기**에서 독립된 백업 파일을 선택하고, 암호화된 파일이면 비밀번호를 입력합니다. **백업 정보 확인**의 메타데이터는 미리보기이며 전체 무결성은 복원 과정에서 검증합니다. 신뢰하는 출처인지 확인하고 새 이름과 프로필 가져오기 여부를 선택한 뒤 **새 실행환경으로 복원**을 누릅니다. 기존 환경을 덮어쓰지 않으며 새 Environment·Storage·Profile ID를 사용합니다. Data로 복원한 Userspace Linux는 배포판 설치를 별도로 실행해야 합니다. Full은 호환되는 ARM64 기기에 설치된 배포판 전체를 복원합니다. 다운로드 캐시와 APT 목록은 제외하므로 새 패키지를 설치하기 전에 배포판의 패키지 목록을 갱신하세요.

화면을 닫아도 작업은 계속되며 같은 화면의 작업 기록에서 단계·용량·결과를 확인하고 취소하거나 재시도할 수 있습니다. 최종 등록 중에는 취소할 수 없습니다. 실패·취소한 복원은 기존 환경을 변경하지 않습니다. 앱 프로세스가 종료되면 미완료 작업은 정리되며 비밀번호를 다시 입력해 재시도해야 합니다. 저장 제공자가 삭제를 거부하면 실패한 백업 파일이 남을 수 있으므로 직접 지우세요.

AVF 전체 디스크, 기존 환경 덮어쓰기, 자동·정기·증분 백업은 지원하지 않습니다. Android 시스템 자동 백업 비활성화 정책은 유지합니다. 백업 형식과 호환성·파일 보존 범위는 [환경 백업 설계](BACKUP_RESTORE.md)를 참고하세요.

## 워크스페이스와 공유 디렉토리

워크스페이스 설정 목록에서 **편집**을 누르면 프로필처럼 드래그 핸들이 나타납니다. 핸들을 끌어 순서를 바꾸고 **완료**로 편집 모드를 닫으세요. 순서는 이동을 마칠 때 바로 저장되며 워크스페이스 선택 메뉴와 세션 이동 창에도 적용됩니다. 이름을 바꾸거나 임시 워크스페이스를 영구 그룹으로 전환해도 위치는 유지되고, 새 그룹은 목록 끝에 추가됩니다.

세션 툴을 확장한 뒤 선택된 탭의 케밥 버튼을 누르면 **이름 변경 / 워크스페이스 이동** 메뉴가 열립니다. 기본 크기에서는 탭을 길게 눌러 같은 메뉴를 열 수 있습니다. 이동 창에서 현재 소속을 확인하고 미소속 또는 원하는 워크스페이스를 선택한 뒤 **이동**을 눌러 적용하세요. 선택만 하거나 취소하면 소속은 바뀌지 않습니다. 임시 워크스페이스 만들기는 별도 행에서 열며 생성창을 취소하면 이동 창의 선택으로 돌아옵니다.

이름을 지정한 워크스페이스 실행 구성으로 시작한 탭은 구성 이름을 **사용자 지정 탭 이름**으로 사용합니다. 수동 실행과 시작 시 자동 실행 모두 적용되며 AVF 준비 중에도 같은 이름이 보입니다. 셸이 보내는 제목은 아래 보조 제목으로 표시되고 탭 이름은 유지됩니다. 이후 탭 이름을 직접 변경할 수 있으며 원본 프로필 이름은 바뀌지 않습니다. 실행 구성 이름을 비우면 목록과 선택 창에는 프로필 이름을 표시하고 실행 시에는 기본 세션 제목을 사용합니다.

**설정 → 워크스페이스**에서 영구 워크스페이스를 만들고 이름·아이콘·실행 구성을 관리합니다. 만들기 화면에는 앱 언어와 관계없이 **Workspace**라는 기본 이름을 넣으며 같은 이름이 있으면 `(2)`부터 번호를 붙입니다. 원하는 이름으로 바꾸거나 기본 이름으로 바로 저장할 수 있습니다. 목록은 프로필 설정처럼 만들기와 등록된 워크스페이스 목록을 구분합니다. 각 워크스페이스를 열어 **기본 설정 → 아이콘**을 누르면 프로필 아이콘 설정과 같은 모달에서 기본 후보 33개 중 하나를 고를 수 있습니다. 구름·로켓·과학·책·게임·별 등 Material Symbols 14종을 추가했으며 이름 없이 그림을 고르고 선택 상태를 확인합니다. 기존 워크스페이스에는 팀 대시보드 아이콘이 기본 적용됩니다. 아이콘 모달의 **확인**과 실행 구성 화면의 저장은 워크스페이스 초안에 반영되며, 워크스페이스 화면의 전체 **저장**을 눌러야 적용됩니다. 아이콘 모달에서 **취소**하거나 닫으면 기존 선택을 유지합니다. 워크스페이스는 파일 폴더가 아닌 세션 그룹입니다. 세션 툴의 선택기에서 **미소속 세션** 또는 원하는 워크스페이스로 전환하거나 임시 워크스페이스를 바로 만들 수 있습니다. 앱을 다시 실행하거나 오래 백그라운드에 둔 뒤 돌아오면 마지막으로 선택한 워크스페이스와 해당 그룹의 활성 탭을 복원합니다. 화면 재생성·서비스 재연결도 현재 선택과 세션 소속을 유지합니다. 저장된 선택이 없는 첫 실행은 미소속 세션으로 시작하며, 실행 구성과 세션 알림으로 명시한 대상은 그 요청에 따라 열립니다. 저장된 빈 그룹을 복원하는 것만으로 시작 구성을 다시 실행하지 않습니다. 이전의 모든 세션 선택도 미소속으로 전환됩니다. 알림으로 세션을 열면 해당 세션의 워크스페이스로 이동합니다. 새 세션은 현재 그룹에 추가됩니다. 세션을 길게 누르거나 편집 버튼을 눌러 **워크스페이스 이동**을 선택하면 다른 그룹·미소속으로 옮길 수 있습니다. 전환·이동·삭제는 실행 중 프로세스를 종료하지 않습니다. 시작 구성을 선택하지 않은 빈 그룹에는 새 세션을 자동으로 만들지 않습니다.

**워크스페이스 설정 → 실행 구성 → 시작 시 실행**에서 바로 시작할 구성을 여러 개 선택할 수 있습니다. 선택 창에서 저장한 뒤 워크스페이스 화면의 전체 **저장**을 눌러 적용하세요. 기본값은 선택 없음입니다. 세션이 없는 워크스페이스를 직접 선택하면 선택한 구성을 목록 순서대로 시작합니다. 이미 세션이나 시작 요청이 있으면 중복 실행하지 않습니다. 설치가 필요한 구성은 기존 설치 확인을 거치며 취소하면 해당 구성만 건너뜁니다. 화면 재생성·서비스 재연결·세션 종료·모두 닫기는 자동 실행을 다시 요청하지 않습니다. 세션이 없는 영구 워크스페이스에서는 세션 툴바의 **기본 세션 실행** 버튼으로 선택한 시작 구성을 다시 열 수 있습니다. 시작 구성이 없으면 버튼은 비활성화됩니다.

임시 워크스페이스는 세션이 남아 있거나 선택 중이면 유지합니다. 마지막 세션이 종료되고 선택을 해제한 뒤 실제 세션 상태를 확인할 수 있을 때만 정리합니다. 설정에서 임시 워크스페이스를 저장하면 같은 그룹을 영구적으로 보관합니다. 실행 구성은 기존 프로필과 선택적인 절대 작업 디렉터리를 사용하며 원본 프로필을 수정하지 않습니다. 세션 툴 왼쪽의 워크스페이스 버튼은 그룹 전환 메뉴를 엽니다. 기본 크기에서는 아이콘만, 확장 크기에서는 아이콘과 이름을 함께 표시합니다. 등록한 실행 구성은 **새 세션 → 워크스페이스 이름 · 실행 구성**에서 선택하며 그 아래에는 기존 프로필 목록이 표시됩니다. 실행 구성 항목에는 구성 이름과 원본 프로필 이름만 표시하며 구성 이름을 비우면 프로필 이름만 표시합니다. 미소속을 선택했거나 현재 그룹에 실행 구성이 없으면 프로필 목록만 표시합니다. 참조 프로필이 삭제된 실행 구성은 워크스페이스 설정에서 프로필을 다시 선택해야 실행할 수 있습니다.

**설정 → 공유 디렉토리**에서 공유 디렉토리의 이름과 연결 환경을 관리합니다. **공유 디렉토리 만들기**와 기존 목록 항목은 각각 별도의 설정 화면을 엽니다. 이름 수정 창의 **확인**은 작성 중인 설정에만 반영하며, 전체 화면의 **저장**을 눌러야 이름과 연결 환경이 함께 적용됩니다. 저장하면 목록으로 돌아오며, 저장하지 않고 나갈 때는 초안 폐기를 확인합니다. 화면을 재생성해도 작성 중인 초안을 유지합니다. 데이터는 환경과 독립적으로 보관되며 환경이나 워크스페이스를 삭제해도 지워지지 않습니다. Native는 화면에 표시한 호스트 경로 또는 `TERM_SHARED_FOLDERS`의 JSON 경로 목록을 사용합니다. Userspace Linux는 `/mnt/term-shares/이름`을 사용합니다. 설정 변경은 새 세션부터 적용하고 기존 세션은 재시작하지 않습니다. 연결 설정은 Android UID 보안 격리가 아닙니다. 공유 디렉토리 자체와 데이터를 삭제하려면 모든 세션과 파일 작업을 먼저 마쳐야 합니다.

Rootless의 전용 `/workspace` 자동 생성과 자동 공유는 제거되었습니다. 사용자가 Linux 안에 직접 `/workspace`를 만드는 것은 가능합니다. 기존 UUID 환경의 작업 폴더와 Legacy 공용 폴더는 삭제하지 않으며 공유 디렉토리 설정의 기존 데이터에서 확인합니다. 해당 기존 폴더를 사용하는 실행환경을 중지하고 파일 쓰기를 마친 뒤 새 공유 디렉토리로 검증된 복사를 하거나 Android 파일 선택기로 ZIP을 내보낼 수 있습니다. 다른 독립 실행환경의 세션은 계속 사용할 수 있습니다. 성공·실패·취소 후에도 원본을 유지합니다. 일반 파일·디렉터리만 지원하고 링크·특수 파일은 실패로 표시합니다. 최대 2 GiB, 10만 항목이며 중단된 Rootless 저장 형식 이전이 있다면 먼저 기존 복구 절차를 마쳐야 합니다. 링크와 패키지 상태까지 보관하려면 **실행환경 → 해당 환경 → 백업 만들기 → Full**에서 워크스페이스를 포함하세요. 링크가 있는 기존 작업 폴더는 대상이 rootfs와 함께 없어질 위험 때문에 환경 삭제를 차단합니다. 링크 없는 UUID 작업 폴더는 환경을 삭제해도 원래 경로에 남으며 같은 설정 화면의 보존 데이터에서 다시 가져올 수 있습니다. 원본을 자동 이동하지 않습니다.

AVF의 직접 공유를 지원하는 새 이미지는 연결한 폴더를 `/mnt/term-shares/공유디렉토리이름`에 마운트합니다. 기기 쪽 공유 폴더와 VM 안에서 같은 파일을 읽고 쓰며 파일 복사의 64 MiB·2분 제한은 적용되지 않습니다. 호환 AVF 플랫폼과 비보호 VM이 필요합니다. 폴더 연결·이름 변경은 다음 VM 부팅부터 적용되고 기존 VM이나 세션을 자동으로 재시작하지 않습니다. 연결을 해제해도 실행 중인 VM의 접근은 유지되므로 VM을 중지한 뒤 다시 시작하세요. 마운트를 사용했던 VM이 중지되었거나 없음을 확인하기 전에는 폴더 데이터를 삭제하지 않습니다. 앱 업데이트만으로 기존 이미지를 바꾸지 않습니다. Download 같은 내부저장소 파일은 별도의 공통 내부저장소 접근 권한과 해당 기능을 지원하는 이미지가 있어야 `/sdcard`로 접근할 수 있습니다.

파일 사본 가져오기·내보내기도 별도로 유지합니다. 직접 공유를 지원하지 않는 이전 이미지는 파일 전송 기능이 있으면 이 방식을 사용합니다. 실행 중인 VM에 공유 디렉토리를 연결한 뒤 전송 방향과 상대 파일 경로를 선택하세요. VM 사본은 `/home/droid/term-transfers/공유디렉토리이름/상대경로`에 있습니다. 복사는 파일 하나당 64 MiB·2분 제한이고 경로 탈출·심볼릭 링크·기존 파일 덮어쓰기를 거부합니다. SHA-256을 확인한 뒤 반영하며 화면을 닫거나 재생성해도 작업은 계속됩니다. 취소는 해당 복사만 중단합니다. 원본과 기존 대상 파일을 보존하지만, 반영 직후 연결이 끊긴 경우 새 사본이 이미 존재할 수 있으므로 재시도 전 확인하세요.
