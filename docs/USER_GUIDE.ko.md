# Droid Terminal 사용 가이드

## 1. 시작하기

앱을 열면 **초기 설정** 화면이 표시됩니다. 기본 동작은 Native 모드이므로 별도 Debian 이미지 없이도 즉시 콘솔을 사용할 수 있습니다.

- **즉시 콘솔 시작**: 앱 전용 홈·임시 디렉터리를 준비하고 Android의 로컬 셸로 콘솔을 시작합니다.
- **Debian 이미지 선택 (선택 사항)**: 네트워크 없이 준비한 검증 이미지 디렉터리를 선택합니다. AVF 제품 빌드에서 실제 Debian VM으로 사용합니다.

Rootless Debian은 별도 파일을 준비할 필요가 없습니다. 새 세션에서 **Linux / Rootless Debian**을 고르면, 처음 한 번 앱이 검증된 Debian 환경을 자동으로 내려받아 설치하고 셸을 엽니다. 이는 추가 Android 권한·ADB·root를 요구하지 않으며, 설치 중 연결이 끊겨도 다음 선택에서 불완전한 설치를 자동으로 다시 받습니다. 현재 자동 설치는 ARM64 기기를 지원합니다.

로컬 이미지 디렉터리에는 아래 파일이 모두 있어야 합니다.

```text
manifest.properties
vmlinuz
initrd.img
system.img
home.img
config.img
```

앱은 파일명, 아키텍처(Debian ARM64), 각 파일의 SHA-256을 검증합니다. 검증에 실패한 이미지나 임의 URL은 실행하지 않습니다.

> Native 모드는 일반 Android 셸 환경이며 systemd나 완전한 Debian 패키지 호환을 제공하지 않습니다. 실제 Debian VM은 OEM/플랫폼 서명 AOSP 배포 환경에서 동작합니다.

## 2. 콘솔 사용

초기 설정을 마치면 **콘솔**에서 다음을 수행합니다.

1. **VM 시작**을 누릅니다.
2. 상태가 `READY`, `ACTIVE`, 또는 `IDLE`이 되면 **새 셸**을 누릅니다.
3. 생성된 세션 탭을 누르면 해당 셸에 연결됩니다.
4. 입력 상자에 명령을 입력하고 **전송**을 누릅니다.

각 탭은 독립적인 Linux PTY 세션입니다. 탭을 전환해도 백그라운드 작업은 계속 동작합니다. Android 화면을 닫거나 최근 앱에서 UI 태스크를 제거해도, 런타임 정책과 시스템이 허용하는 한 VM과 세션은 종료되지 않습니다.

예시:

```sh
while true; do date; sleep 5; done
```

앱을 다시 열고 같은 탭을 선택했을 때 시간이 계속 출력되면 세션 재연결이 정상 동작한 것입니다.

## 3. Android 연동 권한

콘솔 하단의 **Android 접근**에서 게스트가 사용할 기능을 허용할 수 있습니다.

- 클립보드: `droid clipboard get`, `droid clipboard set "텍스트"`
- 링크 열기: `droid open https://example.com`
- 알림: `droid notify --title "완료" --text "빌드가 끝났습니다"`

권한 허용은 Android 운영체제 권한과 별개입니다. 허용하지 않은 기능은 게스트에서 거부됩니다. 이 설계는 임의 Linux 프로그램이 Android Binder나 앱 비공개 데이터에 직접 접근하지 못하게 합니다.

## 4. 파일과 공유

### Linux → Android

게스트의 `/mnt/shared`는 런타임이 제공하는 고성능 공유 디렉터리입니다.

```sh
echo hello > /mnt/shared/test.txt
```

공유 위치에서 `test.txt`를 확인할 수 있습니다.

### Android → Linux

Android 공유 시트에서 Droid Terminal을 선택하면 파일은 런타임 공유 위치의 `inbox`로 안전하게 복사됩니다. 원본 URI나 Android 앱 비공개 저장소가 게스트에 직접 노출되지는 않습니다.

## 5. 개발 서버 포트

게스트에서 서버를 실행합니다.

```sh
python -m http.server 8000
```

`droid-port-agent`가 리스닝 포트를 보고하면 호스트는 `127.0.0.1:8000`에만 전달 포트를 엽니다. **설정 → 진단 및 전달 포트**에서 활성 포트를 확인할 수 있습니다.

포트는 외부 네트워크에 공개되지 않습니다. 다른 기기에서 접근하려면 별도 보안 정책과 명시적 기능이 필요합니다.

## 6. 설정

콘솔 상단 영역을 누르면 설정 화면을 엽니다.

- **글꼴 크기**: 14–22sp 사이를 순환하며 콘솔 표시 크기를 저장합니다.
- **절전 정책**
  - 배터리 최적화: 추가 wake lock을 잡지 않습니다.
  - 작업 중 유지: 게스트가 작업 중이라고 보고할 때만 wake lock을 사용합니다.
  - 항상 켜기: VM 실행 중 wake lock을 유지합니다. 배터리 사용량이 늘 수 있습니다.
- **앱 권한 관리**: Android 시스템의 앱 권한 화면을 엽니다.
- **진단 및 전달 포트**: 런타임·이미지·세션·절전·포트 상태를 읽기 전용으로 표시합니다.

## 7. 종료와 복구

- 콘솔 화면을 닫는 것은 **세션 종료가 아니라 연결 해제**입니다.
- VM을 끝내려면 콘솔의 **중지**를 사용합니다.
- 비정상 종료 뒤에는 앱을 열어 진단 화면의 런타임 상태와 이미지 검증 결과를 확인합니다.
- VM 소유 프로세스나 시스템이 실제로 VM을 종료한 경우, Linux 프로세스가 살아 있다고 표시하지 않습니다. VM을 다시 시작해야 합니다.

## 8. 자주 발생하는 문제

| 증상 | 확인 및 해결 |
| --- | --- |
| `Debian image directory is missing` | 자동 설치용 제품 카탈로그가 포함됐는지 확인하거나, 필수 여섯 파일이 있는 로컬 이미지 디렉터리를 선택합니다. |
| `AVF custom VM access requires ...` | 일반 APK 제한입니다. OEM/플랫폼 서명 AOSP 배포와 AVF 시스템 드라이버가 필요합니다. |
| 세션 탭이 보이지 않음 | VM 상태가 `READY`인지 확인한 뒤 **새 셸**을 누릅니다. |
| 앱을 다시 열자 출력이 없음 | 같은 세션 탭을 다시 선택합니다. 진단 화면에서 VM이 실제로 중지됐는지 확인합니다. |
| 포트가 표시되지 않음 | 게스트 프로세스가 실제로 리스닝 중인지 확인하고, `droid-port-agent` 서비스 상태를 확인합니다. |
| Android 기능이 거부됨 | 콘솔의 Android 접근 권한과 Android 시스템 권한을 모두 확인합니다. |

## 9. 보안 주의사항

Linux 게스트는 신뢰하지 않는 코드도 실행할 수 있는 환경입니다. Android 권한은 필요한 기능만 허용하고, 공유 디렉터리에 민감한 앱 데이터나 비밀 키를 무분별하게 두지 마세요. 특히 **항상 켜기** 절전 정책은 장시간 작업을 할 때만 사용하세요.
