# TERM 사용 가이드

**설정 → 앱 업데이트 → 업데이트 채널 → 업데이트 확인**에서 새 버전을 확인할 수 있습니다.
**정식 릴리스**는 origin/main, **개발 릴리스**는 origin/dev 갱신을 제공합니다.
채널 선택은 저장되며, 개발 릴리스에는 기능 불안정 경고를 표시합니다.
같은 앱·서명키를 사용하므로 더 새로운 버전이면 채널을 전환해 설치할 수 있습니다.
선택한 채널이 설치된 버전보다 오래됐으면 새 배포를 기다려야 합니다.
새 업데이트가 감지되면 해당 버전의 한국어 릴리즈노트가 화면에 자동으로 표시되며,
다운로드 중과 설치 준비 후에도 확인할 수 있습니다. 긴 노트는 화면을 스크롤해 읽습니다.
릴리즈노트의 제목·목록·강조·코드는 서식을 적용해 표시하며, 웹 링크를 누르면 브라우저로 엽니다.
노트를 불러오지 못해도 다운로드할 수 있으며, **업데이트 확인**을 다시 누르면 재시도합니다.
업데이트는 공개 [TERM 배포 저장소](https://github.com/nolbo/TERM)에서 내려받습니다.
선택한 채널에 아직 첫 버전이 배포되지 않았으면 해당 상태를 표시합니다. 다운로드 후 앱 정보와
서명을 검증한 APK만 설치할 수 있습니다. 필요하면 Android의 ‘알 수 없는 앱 설치’를
허용하고 돌아와 **설치**를 다시 누르세요. 마지막 설치 승인은 Android에서 진행합니다.
설치 시 Android가 런타임 프로세스를 종료할 수 있으므로 터미널 작업을 먼저 저장하세요.
정상 업데이트는 앱 데이터와 Linux 파일을 유지합니다. Debug 앱과 release 키가 다르면
업데이트가 차단되며, 앱이 자동으로 기존 앱을 삭제하지 않습니다.

저장된 원격 페어링 정보는 연결된 iPhone에서 유효성을 확인한 뒤 재사용합니다.
`RP_PAIRING`이 발생하면 기존 정보를 자동 삭제·재생성하지 않습니다. 설치나 Wi-Fi
디버깅 변경은 이미 완료됐을 수 있으므로 상태를 확인하고 반복 설치는 피하세요.

USB 안전성은 [자동 검사와 실기기 검증 절차](../tests/usb/DEVICE_SAFETY.md)로 나누어
확인합니다. 가상 테스트 통과는 실기기 무손상을 보장하지 않습니다. 실기기 검사에서는
작업 전후 설정·데이터·다른 세션·재연결을 비교하며, 예상 밖 변화가 있으면 중단합니다.

iPhone 검사 중 USB 구성을 자동 변경하지 않습니다. `USB_CONFIGURATION_REQUIRED`가
나오면 Native/Rootless의 `terminal-usb configuration DEVICE_ID VALUE`로 별도 승인을
요청하고, 변경 후 다시 목록을 조회해 새 기기 ID를 사용하세요.
호스트 도구 화면과 CLI의 `changes`는 실패·취소 후에도 설치·설정 변경이 남았는지
표시합니다. `POSSIBLE`은 확인 필요, `CONFIRMED`는 완료 응답 확인, `UNCHANGED`는
기존 설정 유지입니다. 자동 앱 삭제·신뢰 해제·설정 초기화는 하지 않습니다.
페어링 파일은 임시 파일 검증 후 교체하며, 중단 시 임시 파일이 남을 수 있습니다.

개발용 [가상 iPhone 테스트](../tests/usb/VIRTUAL_IPHONE.md)는 테스트 APK에서만
연결 중단·Trust 거부·부분 전송 등을 재현합니다. 제품 앱에 가상 iPhone이나 권한
우회 기능을 제공하지 않으며, 실제 iOS 설치 성공을 검증하는 환경은 아닙니다.

USB 명령 실패 시 자동 재전송·기기 초기화를 하지 않습니다. 응답 시간 초과나
통신 오류가 난 연결은 재사용하지 마세요. `tooling` 작업이 FAILED이면 종료 코드
1, CANCELED이면 130을 반환하므로 `&&`로 연결한 다음 명령은 실행되지 않습니다.
단, `watch`에서 Ctrl-C는 관찰만 종료하며 호스트 작업은 계속됩니다.
이미 기기가 수락한 쓰기·설치·설정 변경은 실패나 취소로 되돌릴 수 없고, 업로드
중단 시 새 부분 파일이 남을 수 있습니다. 대상 상태를 확인한 뒤 재시도하세요.
사용자 스크립트·raw·시리얼·ADB 명령 자체의 부작용까지 방지하는 기능은 아닙니다.

Native와 Rootless에서 `terminal-usb list`, `iphone pair|info|ls|get|put`,
`tooling list|check|start|status|watch|select|cancel`로 같은 iPhone 호스트 capability를 사용할 수 있습니다.
각 작업은 USB 화면에서 별도 승인해야 합니다. 앱은 전용 SideStore/IPA 설치
화면이 아닌 도구 실행 기반을 제공하며, USB FD·페어링·서명 비밀은 터미널에
전달하지 않습니다. `tooling start isideload DEVICE_ID`는 고정된 SideStore stable
작업을 수행하는 APK 도구를 호출합니다. 계정·암호·2FA는 **USB 디바이스 →
호스트 도구 입력**에서만 입력하세요. `tooling watch OPERATION_ID`를 종료하거나
화면을 나가도 작업은 계속되며, `tooling cancel OPERATION_ID`로 명시적으로
취소합니다. 임의 IPA URL이나 일반 usbmuxd는 제공하지 않습니다. 실제 iPhone
설치·첫 갱신은 아직 실기 검증하지 않았습니다. [iPhone 도구 환경](IPHONE_TOOLING.md)을 참고하세요.

**TERM**은 **Terminal Environments with Runtime Multiplexing**의 약자입니다.

USB Host 지원 기기에서는 새 Rootless 세션의 `terminal-usb` 명령으로 USB 장치를
조회하고, 앱의 **설정 → 터미널 설정 → USB 디바이스**에서 접근 요청을 승인할 수
있습니다. Python 3가 필요하며, CDC ACM·FTDI·CP21xx·CH34x·PL2303 및 일부 모뎀의
시리얼 드라이버와 제한된 raw/HID 전송을 지원합니다. `terminal-usb list`의
`serialPorts`를 확인한 뒤 `terminal-usb serial DEVICE_ID --port 0 --baud 115200`으로
접속하세요. 여러 포트가 있으면 선택이 필수이며, 명확히 분리된 FTDI/CP21xx
구성에서만 다중 포트 동시 연결을 허용합니다. 다른 드라이버는 기기를 독점합니다.
`--cbreak`는 즉시 키 입력을 전송하고 종료 시 터미널 모드를 복구합니다.
초기화나 DTR/RTS 변경으로 보드가 리셋될 수 있으며, 쓰기 시간 초과는 자동 재전송하지
않습니다. `terminal-usb run SCRIPT.py`에서는 `terminal_usb`의 `SerialPort`와
`RawInterface`로 바이너리 프로토콜을 구현할 수 있습니다. ARM64 Android의 iPhone 경로는
`terminal-usb iphone pair|info|unpair DEVICE_ID`로 페어링·기본 정보 조회·페어링 해제를
요청하며 작업별 승인이 필요합니다. iPhone 잠금 해제와 신뢰 승인도 필요합니다.
페어링 후 `terminal-usb iphone ls DEVICE_ID /`로 표준 AFC 영역을 조회하고,
`get DEVICE_ID /원격경로 ./새파일`로 다운로드하거나
`put DEVICE_ID ./파일 --name import.txt`로 업로드할 수 있습니다(각 명령 앞에
`terminal-usb iphone` 필요). 파일당 64 MiB이며, 읽기는 경로별 승인,
쓰기는 `/TerminalImports`에 대한 별도 승인이 필요합니다. 업로드 파일명에는
앱이 생성한 UUID가 붙습니다. 연결이 끊기면 표시된 원격 경로에 일부 파일이
남을 수 있습니다. 다운로드는 기존 파일을 덮어쓰지 않으며 Rootless 홈처럼
하드 링크를 지원하는 위치에 저장하세요. 실제 iPhone 전송 호환성은 아직 실기기
검증 전입니다. 기존 `idevice*` 명령이나 전체 파일시스템 접근을 제공하는 것은 아닙니다.
`apt install adb`로 설치한 ADB는 `terminal-usb adb DEVICE_ID` 중계와 함께
사용할 수 있습니다. 출력된 `ADB_SERVER_SOCKET=... adb devices` 명령을 별도
터미널에서 실행하세요. 기존 ADB 서버는 종료하지 않으며, 대상 Android의 USB
디버깅 승인도 필요합니다. 표준 MTP/PTP는 `terminal-usb mtp stores|ls|get|put`
명령으로 제공하며, 파일당 64 MiB 등 제한이 있습니다.

USB 설정은 **연결된 기기 · 접근 요청 · 허용된 접근 · 이동식 저장장치 · 호스트 도구 ·
도움말 및 진단**으로 구분됩니다. 대기 요청은 화면 위에 표시됩니다. 기기 행을
누르면 연결 ID와 인터페이스 정보를 확인할 수 있습니다. 세션 접근 해제와 폴더
제거는 확인 후 진행하며, 터미널 세션 자체나 저장된 파일은 삭제하지 않습니다.
화면을 닫거나 다시 열어도 승인된 작업은 계속 실행됩니다.

USB 설정에서 이동식 저장장치 폴더를 선택하면 `terminal-usb storage roots`와
`storage ls|get|put ROOT_ID`로 접근할 수 있습니다. Android가 마운트한 USB/SD
폴더만 대상이며 읽기/새 파일 업로드를 별도로 승인합니다. 파일 삭제·덮어쓰기나
디스크 포맷·마운트를 제공하지 않습니다. 분리 후에는 다시 승인해야 합니다.
`serial-pty`는 기존 프로그램용 PTY 바이트 스트림을 제공하지만, PTY ioctl이 실제
UART 설정을 바꾸지는 않습니다. `--save-profile ./uart.json`으로 설정을 저장하고
`--profile ./uart.json`으로 불러올 수 있습니다(권한이나 장치 ID는 저장하지 않음).
PyUSB는 apt의 `python3-usb`와 `terminal_usb.pyusb_backend()`를 명시적으로 사용합니다.
설정 화면에는 연결·승인 상태와 드라이버/인터페이스, 안전한 진단 정보가 표시됩니다.

모든 USB 기기의 자동 호환을 뜻하지는 않습니다. 커널 드라이버·FUSE/블록 마운트·
등시성 오디오/영상 및 수정 없는 libusb 프로그램은 지원하지 않습니다. ADB·MTP·
시리얼·저장장치의 실제 USB 호환성은 USB Host 지원 실기기에서 추가 검증이 필요합니다.
연결 절차와 제약은 [USB 가이드](USB.md)를 참고하세요.

페어링 오류 조사 시 APK 업데이트 후 새 세션에서 `terminal-usb tooling list`를
실행하면 서비스 수정 버전(`serviceRevision`)과 설치된 worker 해시를 확인할 수
있습니다. 수정 버전 2는 기존 기록 확인·Trust 대기·기록 저장·세션 검증을 따로
표시합니다. 기록이 손상되거나 읽기 실패한 경우 자동 재페어링하지 않습니다.
`tooling check`는 연결 검사이며 Trust나 설치를 시작하지 않습니다. 다른 작업의
응답이 오면 `TOOL_RESPONSE_MISMATCH`로 표시합니다. 이 변경만으로 iOS 27 베타의
실기기 호환성이 검증된 것은 아닙니다.

## 1. 시작하기

앱을 처음 열면 **초기 설정** 화면이 한 번 표시됩니다. 설정을 완료한 뒤부터는 앱을 열면 터미널로 바로 이동합니다. 기본 동작은 Native 모드이므로 별도 Debian 이미지 없이도 즉시 콘솔을 사용할 수 있습니다.

- **터미널 시작**: 앱 전용 홈·임시 디렉터리를 준비하고 Android Native 셸로 콘솔을 시작합니다.
- **AVF Debian 이미지 선택**: 네트워크 없이 준비한 검증 이미지 디렉터리를 선택합니다. AVF 제품 빌드에서만 실제 Debian VM으로 사용합니다.

초기 설정 화면은 Android Native, Rootless Linux, AVF Debian을 별도 카드로 표시하고 각 환경의 권한과 호환성 차이를 설명합니다. 앱 화면은 일관된 다크 테마만 사용하며, 터미널 팔레트는 설정에서 독립적으로 관리합니다.

Rootless Linux는 별도 파일을 준비할 필요가 없습니다. 새 세션에서 **Debian**, **Ubuntu 24.04 LTS**, **Arch Linux ARM** 중 하나를 고르면, 처음 한 번 앱이 해당 환경을 자동으로 내려받아 검증·설치하고 셸을 엽니다. 이는 추가 Android 권한·ADB·root를 요구하지 않으며, 이미지 다운로드 실패는 다시 받고, 이미지 설치 뒤 패키지·환경 보완 실패는 기존 파일을 유지한 채 재시도합니다. 현재 자동 설치는 ARM64 기기를 지원합니다.

로컬 이미지 디렉터리에는 아래 파일이 모두 있어야 합니다.

```text
manifest.properties
vmlinuz
initrd.img
system.img
home.img
config.img
```

앱은 파일명, 아키텍처(Debian ARM64), 각 파일의 SHA-256을 검증합니다. 검증에 실패한 이미지나 임의 URL은 실행하지 않습니다.

> Native 모드는 일반 Android 셸 환경이며 systemd나 완전한 Debian 패키지 호환을 제공하지 않습니다. 실제 Debian VM은 OEM/플랫폼 서명 AOSP 배포 환경에서 동작합니다.

## 세션 작업 알림

**설정 → 터미널 설정 → 셸 → 세션 작업 알림**에서 켜거나 끌 수 있습니다.
기본값은 꺼짐이며, Android 알림 권한과 **세션 작업 알림** 채널도 허용해야 합니다.
같은 화면의 **Android 알림 설정**에서 소리·표시 여부를 바꿀 수 있습니다.
이 옵션은 세션 유지용 상시 알림과 독립적입니다.

- 10초 이상 실행한 명령이 끝나면 완료 알림을 보냅니다. 기본 Native 셸과 Bash의
  새 세션에 완료 감지 신호를 연결합니다. 설치 이전부터 실행 중인 셸에는 소급 적용하지 않습니다.
- 프로그램이 벨(BEL), OSC 9 또는 `OSC 777;notify`를 보내면 확인 요청을 알립니다.
  임의의 출력 문장이나 조용한 상태만으로 입력 대기를 추측하지 않습니다.
- UI를 닫아도 런타임이 살아 있으면 알림을 보냅니다. 알림을 누르면 해당 세션을
  선택하며, 세션이 사라졌다면 새 세션을 대신 만들지 않습니다.
- 동일 세션 알림은 10초에 한 번, 앱 전체는 1초에 한 번으로 제한합니다.
  스크롤백 복원·탭 전환은 과거 알림을 다시 보내지 않습니다. 끄면 현재 작업 알림도 지워집니다.
- 알림은 세션 이름·상태·가능한 경우 종료 코드만 표시하며 터미널 출력 본문을 노출하지 않습니다.

Bash 설정에서 `PS0`·`PROMPT_COMMAND`를 덮어쓰거나 Native의 `PS1`을 교체하면
자동 완료 감지가 중단될 수 있습니다. 다른 셸·원격 프로그램은 OSC 133의 C/D 명령
경계 신호를 직접 보내거나 다음처럼 확인 요청 신호를 보낼 수 있습니다.

```sh
printf '\033]777;notify;TERM;Attention needed\007'
```

일반 텍스트 프롬프트, 별도 백그라운드 작업의 완료, 임의의 TUI 입력 대기는 해당
프로그램이 신호를 보내지 않으면 감지하지 않습니다. Bash 연동이 게스트 환경 변수
한도를 넘는 경우에는 셸 실행을 우선하고 자동 연동을 생략합니다.

## 2. 콘솔 사용

상단 **+** 메뉴와 빈 화면의 **새 세션**은 프로필 목록을 표시합니다.
Native, Debian, Ubuntu, Arch, AVF 기본 프로필과 사용자 프로필을 이름·실행 환경으로
구분합니다. 사용할 수 없는 환경도 표시하며 선택 시 기존 설치 또는 설정 안내로
연결합니다. 다른 실행 환경으로 자동 전환하지 않습니다.

**설정 → Profiles**에서 프로필을 누르면 설정 화면이 열립니다. 기본 프로필도
같은 화면에서 수정·복제·삭제할 수 있습니다. 삭제는 확인 후 적용되며 앱을 다시
열어도 유지됩니다. 모두 삭제한 경우 **Add profile**로 새 프로필을 만들 수 있습니다.
복제는 저장된 설정을 사용하므로 수정 중에는 먼저 저장하세요.
**+ → Add profile**과 **설정 → Profiles → Add profile**은
같은 편집 화면을 엽니다.
**프로필 아이콘**에서 실행 환경별 아이콘 또는 Material Symbols 아이콘을 선택할 수
있습니다. 기본값인 **실행 환경에 맞춤**은 Native·배포판·AVF 선택을 따라갑니다.
직접 고른 아이콘은 실행 환경을 바꿔도 유지되며, 프로필 복제 시 함께 복제됩니다.
**이미지 추가**는 PNG·WebP·JPEG를 앱 내부로 복사합니다(8MiB 이하, 16메가픽셀 이하,
한 변 8192px 이하). 원본 파일 접근 권한을 계속 유지할 필요는 없습니다.
투명 배경이 있고 모든 보이는 픽셀의 RGB가 동일한 단색 PNG/WebP는 탭·메뉴의 색상을
따릅니다. 알파값은 달라도 됩니다. 여러 색상이나 불투명 배경이 있으면 원래 색상으로
표시하며 선택 화면에서 적용 방식을 안내합니다. 투명 여백을 잘라내고 비율을 유지해
공통 아이콘 영역에 맞춥니다. 완전히 투명하거나 손상된 이미지는 사용할 수 없습니다.
아이콘 변경은 이후 생성한 세션에 적용됩니다. 기존 세션과 복제본을 위해 가져온 이미지가
자동 삭제되지는 않습니다. 추가한 아이콘의 휴지통 버튼을 누르고 확인하면 선택 목록에서
즉시 삭제됩니다. 기존 프로필·복제본·실행 중인 세션의 표시는 유지하도록 이미지 파일은
보존하며, 같은 이미지를 다시 가져오면 목록에 복원됩니다. 삭제한 아이콘을 선택 중이었다면
선택 창의 초안은 **실행 환경에 맞춤**으로 바뀌며, 프로필에 반영하려면 저장해야 합니다.
**프로필 설정 → 컬러 팔레트**에서 프로필마다 전경·배경·커서·ANSI 16색을 지정할 수 있습니다.
새 프로필과 기존 팔레트 설정이 없는 프로필은 전역 팔레트를 따릅니다. 프로필 복제는
원본의 독립 팔레트 또는 전역 상속 설정을 그대로 복제합니다.
**전역 팔레트 복제**와 **다른 프로필에서 가져오기**는 현재 표시 색상을 독립 복사하며,
원본이 전역을 따르더라도 가져온 뒤에는 전역·원본 프로필 변경과 연계되지 않습니다.
**팔레트 초기화**는 전역 상속으로 되돌리므로 이후 전역 변경도 반영됩니다.
색상 견본을 누르면 사각형에서 가로로 채도, 세로로 밝기(위쪽이 밝음)를 조절할 수 있습니다.
아래 색조 막대에서 색조를 바꾸거나 HEX(6자리, # 생략 가능)·RGB(각 0–255)를 직접 입력합니다.
견본·선택 위치·숫자는 함께 갱신되며, 잘못된 입력은 수정해야 **색상 적용**을 누를 수 있습니다.
색상 편집·가져오기·초기화는 화면 하단에서 프로필을 저장해야 적용됩니다.
팔레트 변경은 해당 프로필의 실행 중인 세션에도 적용됩니다. 탭을 전환하면 터미널의
팔레트와 탭·단축키·세션 메뉴의 반응형 색상이 함께 부드럽게 전환됩니다.
빠르게 연속 전환해도 현재 보이는 색상에서 새 대상 색상으로 이어집니다.
프로필을 삭제한 세션은 생성 시의 팔레트 설정으로 돌아가며 세션 자체는 유지됩니다.

프로필 목록은 오른쪽 `>` 화살표가 있는 설정 행으로 표시합니다. 추가·편집 화면의
텍스트 항목은 화살표 없는 행을 눌러 입력 대화상자에서 수정하고, 실행 환경·배포판·저장공간은 앱 언어 설정과 같은
라디오 선택 대화상자에서 고릅니다. 대화상자의 **저장**은 화면 초안에 반영하며,
화면 하단의 **저장**을 눌러 프로필 전체를 저장합니다. **취소**는 기존 값을 유지합니다.
실행 환경은 Native, Rootless Linux 중 선택하며, 앱에 AVF 특권 두 개가 모두 부여된
경우에만 프로필 추가·설정의 선택 목록에 AVF Debian이 표시됩니다. 기존 AVF 프로필의
저장된 실행 환경은 특권이 없어도 자동 변경하지 않습니다. Rootless Linux에서는
Debian·Ubuntu·Arch 배포판을 추가로 선택합니다. AVF 기본 프로필은 앱에
MANAGE_VIRTUAL_MACHINE과 USE_CUSTOM_VIRTUAL_MACHINE 특권이 모두 부여된
경우에만 목록에 나타납니다. **가상 머신** 설정과 해당 세부 설정의 검색 결과도
두 특권이 모두 부여된 경우에만 표시됩니다.
**저장공간**에서 새 독립 공간 또는 같은 기반의 다른 프로필과 공유를 선택합니다.
새 프로필과 복제한 프로필은 기본적으로 독립 공간을 사용합니다. 공유하면 홈·작업
폴더뿐 아니라 Rootless 설치 패키지·루트 파일시스템, AVF VM 디스크도 함께 사용합니다.
Rootless 공유 대상을 선택하면 배포판도 대상과 같아집니다. Native의 Android 시스템
실행 파일과 APK 내 실행 파일은 공통이며, 앱 전용 홈·임시 폴더는 분리됩니다.
기존 프로필은 업데이트 전 저장공간을 유지합니다. 저장공간 설정 변경은 이후 세션에만
적용하며 기존 파일을 이동하거나 복사하지 않습니다. 프로필을 삭제해도 공유 데이터와
실행 중인 세션은 유지되며, 사용하지 않는 저장공간도 자동 삭제하지 않습니다.
새 Rootless 공간은 첫 실행 때 배포판을 설치합니다. 설치 창을 닫고 다른 저장공간의
프로필로 세션을 열 수 있으며, 설치는 백그라운드에서 계속됩니다. 설치 중인 저장공간을
공유하는 프로필을 선택하면 진행 상태를 다시 표시합니다. 새 AVF 공간에는 별도 이미지
설치가 필요하며, 특권 제품의 이미지 카탈로그 또는 사전 설치된 검증 이미지가 필요합니다.
이름, 실행 환경, 셸, 인수, 시작 디렉터리, 환경 변수, 시작 명령을 설정하고
**저장**합니다. 셸 인수는 JSON 문자열 배열(예: `["-l"]`,
`[]`, `["-l", "argument with spaces"]`), 환경 변수는 줄마다 `KEY=value`로 입력합니다.
디렉터리와 셸은 절대 경로를 사용합니다. Native의 빈 디렉터리는 앱 전용 홈입니다.
시작 명령은 POSIX 호환 셸에서 한 번 실행한 뒤 설정된 셸과 인수로 전환합니다.
`exit` 또는 `exec`를 직접 사용하면 이 전환을 생략할 수 있습니다.

팔레트를 제외한 프로필 변경·삭제는 이후 생성할 세션에만 영향을 줍니다. 실행 중인 세션은 생성 당시
설정을 유지하며 탭 전환이나 화면 재생성 때 시작 명령을 다시 실행하지 않습니다.
프로필 삭제는 세션 종료가 아닙니다. PID, 스크롤백, 현재 디렉터리, 실행 중인 작업,
터미널 크기는 프로필에 저장하지 않습니다.

사용자 글꼴 목록은 **일반 / 이탤릭** segmented button으로 전환합니다.
선택한 종류의 글꼴만 표시하며, 파일 추가·우선순위 변경·제거도 해당 종류에 적용됩니다.

**설정 → 터미널 설정 → 터미널 모양 → 화면 배치 → 쉘 화면 여백**에서 상하좌우 여백을
0~32dp로 조절합니다. 기본값은 화면 가장자리와 글자를 조금 띄우면서 표시 공간을
확보하는 4dp입니다. 저장 후 터미널로 돌아가면 적용되며, 줄·열 수가 새 크기에
맞게 갱신됩니다. 여백은 선택한 터미널 팔레트의 배경색을 따릅니다.
기본 Droid Dark 팔레트의 커서는 흰색입니다.

초기 설정을 마치면 **터미널**에서 다음을 수행합니다.
새 탭 생성이 완료되면 해당 탭이 자동 선택되고 터미널 입력 포커스도 이동합니다.

**설정 → 터미널 설정 → 셸 → 웹 링크 열기**를 켜면 화면에 출력된 `http://`·
`https://` 주소를 한 번 탭해 브라우저로 엽니다(기본 꺼짐). 더블 탭 판정 후에
열리며, 스크롤·길게 누르기·더블 탭 중에는 열지 않습니다. 마우스 보고를 사용하는
터미널 프로그램에서는 해당 프로그램의 입력을 우선합니다.

터미널에서 두 손가락을 벌리거나 모으면 현재 세션의 글자 크기를 4–72sp 범위에서
조절합니다. 변경한 크기는 세션별로 저장되어 탭 전환·앱 재진입 때 복원됩니다.
아직 핀치로 조절하지 않은 세션은 터미널 모양 설정의 기본 글자 크기를 사용합니다.

1. 세션이 없으면 빈 화면의 **새 세션**을 누른 뒤, 하단 선택 창에서 원하는 프로필을 선택합니다.
2. 상단의 **새 세션** `+` 버튼을 누르면 간결한 드롭다운 메뉴가 열립니다. 기본 또는 사용자 프로필을 명시적으로 고릅니다. 설치되지 않은 Rootless 배포판을 고르면 설치 여부를 묻고, 그 밖의 환경은 관련 설정 화면을 열지 묻습니다. 다른 환경으로 자동 전환하지 않습니다.
3. 세션 탭을 누르면 해당 셸에 연결됩니다. 새 Native 탭은 `/`가 아닌 앱 전용 홈 디렉토리(`$HOME`)에서 시작합니다. Enter 입력 없이 초기 프롬프트를 표시하며, 홈 경로는 `~`, 홈 아래 경로는 `~/…`로 표시합니다. 선택된 탭은 둥근 캡슐 배경으로 구분됩니다. 비선택 탭은 앱 바와 배경을 공유하며 서로 세로 구분선으로 나뉩니다. 탭 위아래에는 여백이 있습니다.
4. 탭 본문을 길게 누르면 이름 변경 대화상자가 열립니다. 탭 제목은 명시적으로 지정한 탭 이름을 우선하고, 없으면 셸/앱이 터미널에 지정한 제목, 마지막으로 초기·프로필 이름을 사용합니다. 새 이름은 공백을 제외한 1~64자이며 줄바꿈과 제어 문자는 사용할 수 없습니다.
   핫키를 짧게 누르거나 탭을 선택할 때는 가벼운 햅틱 피드백을, 이름 변경·세션 시작·저장 같은 완료 동작에는 확인 햅틱을 제공합니다. 핫키 반복 입력 중에는 진동을 반복하지 않습니다. **터미널 설정 → 햅틱 피드백**에서 전체 사용 여부와 밀도(낮음·표준·높음)를 정할 수 있으며, 스크롤백 촉각 틱은 별도로 켭니다. 틱 간격은 낮음 6행, 표준 3행, 높음 1행입니다.
5. 탭 앞 아이콘으로 실행 환경을 구분합니다: Native는 로봇, Debian은 나선, Ubuntu는 원형, Arch는 아치, AVF는 칩입니다. 탭에는 환경 접두사 없이 제목만 표시합니다. 스크린 리더에서는 실행 환경과 세션 상태를 함께 안내합니다.
터미널 배경색을 바꾸면 탭·새 탭 메뉴·단축키 버튼 배경과 글자·아이콘 색상도 읽기 쉬운 대비로 자동 조정됩니다.

6. 터미널 캔버스를 두 번 탭하면 세션 탭·새 세션·설정이 있는 앱 바가 접히고 터미널 배경이 화면 상단까지 이어집니다. 상태 표시줄 뒤에는 터미널 배경색에서 투명해지는 그라데이션이 표시됩니다. 기록의 맨 위에서는 첫 줄이 상태 표시줄 아래에 놓이고, 스크롤하면 위쪽 내용이 상태 표시줄 뒤를 통과하며 사라집니다. 다시 두 번 탭하면 앱 바가 복원됩니다.
7. 화면 키보드나 하드웨어 키보드로 명령을 입력합니다. 하단의 단축키 그리드에서 ESC, CTRL, ALT, 방향 키와 페이지 키도 사용할 수 있습니다.
8. 종료 아이콘은 선택된 탭에만 표시됩니다. 해당 아이콘을 누른 뒤 확인하면 해당 세션과 실행 중인 작업이 종료됩니다.

생성 시 기본 이름은 명시적 탭 이름이 아닙니다. 애플리케이션이 OSC 제목을 보내야
자동으로 바뀝니다. Vim/Neovim에서 제목이 그대로라면 `:set title`로 제목 전송을
켜세요. 항상 사용하려면 해당 편집기 설정에 `set title`을 추가합니다.
수동으로 지정한 탭 이름은 위쪽에 표시하고, 그 아래에는 애플리케이션 제목을
작게 계속 표시합니다. 애플리케이션 제목이 바뀌면 아래쪽 제목도 갱신되며,
제목을 보내지 않으면 초기·프로필 이름을 표시합니다. 사용자 지정 이름이 없으면
기존처럼 한 줄 제목을 표시합니다. 이름 변경 창의 입력 필드는 사용자 지정 제목이
없으면 비어 있고, 이미 지정한 제목이 있으면 해당 제목이 미리 입력됩니다.

터미널 텍스트를 길게 눌러 선택한 뒤 **복사**를 누르면 Android 클립보드에 저장됩니다. 선택 핸들을 여러 줄에 걸쳐 움직이면 첫 줄의 시작 위치부터 중간 줄 전체와 마지막 줄의 끝 위치까지 이어서 강조 표시됩니다. 선택 메뉴의 **붙여넣기**는 클립보드 텍스트를 현재 셸에 입력합니다. 여러 줄을 붙여넣으면 셸에서 명령이 실행될 수 있으므로 내용을 먼저 확인하세요.

키보드 앱의 여러 줄 붙여넣기, 선택 메뉴, 마우스 가운데 버튼, **Ctrl+Shift+V**, **Shift+Insert**, 붙여넣기 키는 같은 처리 경로를 사용합니다. 앱은 텍스트를 명령 단위로 나누거나 실행 완료를 기다리지 않으며, 마지막 줄바꿈·빈 줄을 제거하거나 Enter를 덧붙이지 않습니다. 여러 줄의 한 명령과 줄바꿈으로 구분된 여러 명령을 해석하고 실행하는 주체는 현재 셸이나 프로그램입니다.

현재 프로그램이 **Bracketed Paste Mode**를 켜면 전체 텍스트를 하나의 붙여넣기 프레임으로 전달하며 LF·CRLF, 탭, 마지막 줄바꿈까지 보존합니다. Bash/Zsh, Vim/Neovim, REPL, TUI별로 붙여넣기 후 처리나 실행 시점은 다를 수 있습니다. 이 모드가 꺼져 있으면 기존 터미널 입력 방식대로 LF·CRLF를 Enter(CR)로 전달하므로 명령이 즉시 실행될 수 있습니다. 어느 경우에도 줄바꿈의 유무와 줄 구조는 유지합니다. 기존 ESC·C1 제어 문자 필터는 유지합니다.

다른 앱에서 돌아오거나 UI가 다시 시작되어 화면을 복원할 때 과거 조회 요청에는 다시 응답하지 않습니다. 실행 중인 런타임은 화면이 없는 동안에도 커서 위치·색상 질의에 응답하므로, 복원 때문에 셸 입력란에 응답 문자열이 추가되거나 프로그램이 화면을 기다리며 멈추지 않습니다.

Codex CLI·Neovim처럼 프로그램이 자체 기록 화면을 사용하는 경우, 프로그램이 마우스 입력을 요청하면 손가락 스크롤과 마우스 휠을 해당 프로그램에 전달합니다. 마우스 입력을 요청하지 않은 대체 화면에서는 프로그램이 대체 스크롤을 켜 둔 경우 위·아래 커서 키를 전달합니다. 일반 화면에서는 터미널 기록을 스크롤합니다.

백그라운드 전환과 화면 재생성·재진입에서 터미널 버퍼와 입력 모드를 유지합니다. Android가 UI 프로세스 자체를 종료해도 런타임 서비스와 PTY가 살아 있으면 기본·대체 화면, 설정 범위의 스크롤백, 커서·색상·이미지·입력 모드와 중간에 끊긴 제어 시퀀스까지 복원합니다. 각 탭에서 읽던 기록 위치도 이어집니다. 앱 전체 강제 종료나 실제 런타임·VM 종료로 사라진 작업을 되살리는 기능은 아닙니다.

새 Native 세션의 기본 Android 셸은 경로를 초록색·보통 굵기, `$`를 기본 글자색·보통 굵기로 표시합니다. 이어지는 입력 프롬프트는 노란색입니다. 색상은 선택한 터미널 팔레트를 따릅니다. 지원되는 `ls`·`grep`에는 `--color=auto` 별칭을 적용하므로 파일 저장과 파이프 출력에는 색상 코드가 섞이지 않습니다. 시작 시 `NO_COLOR`가 비어 있지 않거나 `TERM=dumb`이면 색상 기본값을 적용하지 않습니다. 다른 셸은 해당 셸의 프롬프트 설정을 사용합니다.

터미널 세션에 연결하면 화면 키보드를 요청합니다. 키보드를 숨겼다면 터미널
본문을 탭해 다시 열 수 있습니다. 시스템 뒤로가기는 키보드를 닫고, 셸에 ESC를
보내려면 하단 ESC 키를 사용합니다. 일반 화면 갱신은 숨긴 키보드를 다시 열지
않습니다. 하드웨어 키보드 연결 시 화면 키보드 표시 여부는 Android 설정을 따릅니다.

실행 중인 세션이 1개 이상이면 알림 제목에 앱 이름 없이 실행 중인 세션 수가 표시됩니다. Android 13 이상에서는 알림 권한을 허용해야 알림 창에 표시됩니다. 마지막 세션이 종료되고 진행 중인 생성·설치 작업도 없으면 알림과 포그라운드 서비스 유지가 해제됩니다. 빈 화면을 닫으면 유휴 서비스도 종료됩니다. 생성·설치 중에는 작업이 끝날 때까지만 임시 알림이 유지됩니다.

알림의 **모든 세션 종료**를 누르면 현재 모든 실행 환경의 세션과 그 안의 작업을 즉시 종료합니다. 앱 화면이 닫혀 있어도 동작하며, 종료 후에는 세션 알림이 사라집니다. 종료에 실패한 세션은 유지되므로 다시 시도할 수 있습니다.

세션 유지 알림은 상시 알림으로 표시됩니다. Android 14 이상에서는 OS가 개별 스와이프 삭제를 허용하지만, 세션이나 진행 중인 작업이 남아 있으면 알림을 다시 표시합니다. 알림을 밀어도 세션은 종료되지 않습니다. Android 설정에서 알림을 차단하거나 앱을 강제 종료한 경우까지 표시를 보장하지는 않습니다.

각 탭은 독립적인 Linux PTY 세션입니다. 탭을 전환해도 백그라운드 작업은 계속 동작하며, 같은 화면에서 탭을 왕복하면 각 탭의 스크롤 위치가 유지됩니다. 기록이 지워졌거나 줄어든 경우에는 남아 있는 범위로 조정됩니다. Android 화면을 닫거나 최근 앱에서 UI 태스크를 제거해도, 런타임 정책과 시스템이 허용하는 한 VM과 세션은 종료되지 않습니다.

세션 화면을 처음 연결할 때도 실제 화면의 행·열 수를 셸에 전달합니다. 긴 한 줄 명령의 자동 줄바꿈과 커서 이동·삭제가 기본 80열이 아닌 현재 화면 폭을 기준으로 처리됩니다.

세션 종료가 확인되기 전에는 해당 탭이 유지되고 종료 버튼이 잠깁니다. 종료에
실패하면 다른 탭에 영향을 주지 않고 오류를 표시합니다. 마지막 세션을 종료하면
앱과 런타임은 열린 채로 빈 화면을 표시하며, **새 세션**에서 Native, Rootless,
또는 사용 가능한 AVF를 명시적으로 선택할 수 있습니다. 화면 재생성이나 앱 복귀가
빈 상태에서 Native 세션을 자동으로 만들지는 않습니다.

예시:

```sh
while true; do date; sleep 5; done
```

앱을 다시 열고 같은 탭을 선택했을 때 시간이 계속 출력되면 세션 재연결이 정상 동작한 것입니다.

## 3. Android 연동 권한

콘솔 하단의 **Android 접근**에서 게스트가 사용할 기능을 허용할 수 있습니다.

- 클립보드: `droid clipboard get`, `droid clipboard set "텍스트"`
- 링크 열기: `droid open https://example.com`
- 알림: `droid notify --title "완료" --text "빌드가 끝났습니다"`

권한 허용은 Android 운영체제 권한과 별개입니다. 허용하지 않은 기능은 게스트에서 거부됩니다. 이 설계는 임의 Linux 프로그램이 Android Binder나 앱 비공개 데이터에 직접 접근하지 못하게 합니다.

## 4. 파일과 공유

### Linux → Android

게스트의 `/mnt/shared`는 런타임이 제공하는 고성능 공유 디렉터리입니다.

```sh
echo hello > /mnt/shared/test.txt
```

공유 위치에서 `test.txt`를 확인할 수 있습니다.

### Android → Linux

Android 공유 시트에서 TERM을 선택하면 파일은 런타임 공유 위치의 `inbox`로 안전하게 복사됩니다. 원본 URI나 Android 앱 비공개 저장소가 게스트에 직접 노출되지는 않습니다.

## 5. 개발 서버 포트

게스트에서 서버를 실행합니다.

```sh
python -m http.server 8000
```

`droid-port-agent`가 리스닝 포트를 보고하면 호스트는 `127.0.0.1:8000`에만 전달 포트를 엽니다. **설정 → 진단 및 전달 포트**에서 활성 포트를 확인할 수 있습니다.

포트는 외부 네트워크에 공개되지 않습니다. 다른 기기에서 접근하려면 별도 보안 정책과 명시적 기능이 필요합니다.

## 6. 설정

터미널 상단의 **설정** 아이콘을 누르면 범주별 설정 화면을 엽니다.

- **터미널 설정 → 터미널 모양**: 글꼴 크기, 기본 고정폭 글꼴, 문자 폭과 터미널 팔레트를 관리합니다. **글꼴 파일 추가**에서 TTF, OTF 등의 일반 글꼴을, **이탤릭 글꼴 파일 추가**에서 이탤릭 전용 파일을 여러 개 선택할 수 있습니다. 터미널 프로그램이 이탤릭 속성을 요청하면 이탤릭 목록을 같은 스타일별 우선순위로 먼저 적용하며, 등록하지 않았거나 해당 문자를 지원하지 않으면 일반 글꼴의 합성 이탤릭으로 fallback합니다. 일반과 이탤릭 목록은 각각 화살표로 우선순위를 바꾸거나 삭제할 수 있습니다. 첫 번째로 사용할 수 있는 일반 사용자 글꼴이 셀 크기의 기준이 됩니다. 선택한 문서에 대한 읽기 권한만 저장하며, 문서가 이동·삭제되어 열 수 없거나 올바른 글꼴이 아니면 해당 항목은 건너뛰고 다음 글꼴 또는 시스템 고정폭 글꼴을 사용합니다. **자연스러운 넓은 글자**는 기본적으로 꺼져 있으며, 켜면 한글/CJK 등 Unicode 폭이 2인 글리프를 가로로 늘리지 않고 원래 비율을 유지해 2셀 영역 중앙에 배치합니다. 커서, 선택, 배경과 줄바꿈은 이 옵션과 무관하게 셀 단위를 유지합니다. 글자 크기는 시스템 글꼴 배율을 따르는 실제 sp 단위이며, 터미널로 돌아오면 적용됩니다.
- **Rootless Linux**: 화면 상단에서 Debian, Ubuntu, Arch Linux ARM 각각의 설치 상태를 한 번에 확인합니다. **확인 중**, **설치 필요**, **환경 보완 필요**, **준비됨**, **오류** 상태와 상세 원인을 구분합니다. 각 배포판의 상태에 따라 **설치**, **환경 보완**, **다시 확인**, **재시도**를 개별 실행할 수 있습니다.
- **가상 머신**: 다음 AVF 시작에 적용할 메모리, vCPU, 보호 모드, 네트워크와 절전 정책을 관리하고 진단 화면으로 이동합니다.
- **Native 셸 설정**: 새 Native 세션에 적용할 기본 셸을 관리합니다.
- **터미널 설정**: 공통 TERM·스크롤백, Native·Rootless 로그인 셸, 공유 내부저장소와 앱 권한을 관리합니다. 로그인 셸과 직접 공유 저장소 접근은 AVF에 적용되지 않습니다.
- **입력 설정 저장**: 숫자, 기본 셸 경로, 단일 선택은 입력 중에 저장되지 않습니다. 대화상자의 **저장**을 누를 때 전체 값을 검증하며, 숫자는 표시 범위 안이어야 하고 기본 셸은 앱이 실제로 실행할 수 있는 절대 경로여야 합니다. 입력 중 화면이 회전해도 대화상자와 초안은 유지됩니다.
- **런타임 반영 시점**: AVF 리소스는 다음 AVF 시작, TERM과 로그인 셸은 새 Native 세션에 적용됩니다. 절전 정책은 실행 중인 런타임 서비스에 즉시 전달됩니다.
- **절전 정책**
  - 배터리 최적화: 추가 wake lock을 잡지 않습니다.
  - 작업 중 유지: 화면 연결 여부와 무관하게 실행 중인 세션, 설치·시작 작업이 있거나 게스트가 백그라운드 작업 중이라고 보고할 때 wake lock을 사용합니다.
  - 런타임 실행 중 항상 유지: 런타임이 중지되거나 실패할 때까지 wake lock을 유지합니다. 배터리 사용량이 늘 수 있습니다.
- **Android 권한**: Android 시스템의 앱 권한 화면을 엽니다.
- **진단 및 전달 포트**: 런타임·이미지·세션·절전·포트 상태를 읽기 전용으로 표시하며 상단 새로고침 버튼으로 현재 서비스 상태를 다시 읽습니다.

Rootless Linux 설정에서 이미지가 설치된 배포판의 **제거**를 누르면 확인 후 설치 이미지와 이미지 안의 패키지·파일을 삭제합니다. 실행 중인 해당 배포판 세션을 먼저 모두 종료해야 합니다. 기본값은 배포판 홈을 유지하는 것이며, 확인창의 **이 배포판의 홈 데이터도 삭제**를 선택하면 그 배포판의 홈 설정과 개인 파일도 함께 삭제합니다. 공유 작업 폴더와 다른 배포판은 항상 유지되며 제거 후 **설치**로 다시 설치할 수 있습니다.

## 7. 종료와 복구

- 콘솔 화면을 닫는 것은 **세션 종료가 아니라 연결 해제**입니다.
- 세션을 끝내려면 해당 탭을 선택한 뒤 종료 아이콘을 누르고 **세션 종료**를 확인합니다. 이 동작만 해당 PTY의 실행 중인 작업을 종료합니다.
- 비정상 종료 뒤에는 앱을 열어 진단 화면의 런타임 상태와 이미지 검증 결과를 확인합니다.
- VM 소유 프로세스나 시스템이 실제로 VM을 종료한 경우, Linux 프로세스가 살아 있다고 표시하지 않습니다. VM을 다시 시작해야 합니다.

## 8. 자주 발생하는 문제

| 증상 | 확인 및 해결 |
| --- | --- |
| `Debian image directory is missing` | 자동 설치용 제품 카탈로그가 포함됐는지 확인하거나, 필수 여섯 파일이 있는 로컬 이미지 디렉터리를 선택합니다. |
| `AVF custom VM access requires ...` | 일반 APK 제한입니다. OEM/플랫폼 서명 AOSP 배포와 AVF 시스템 드라이버가 필요합니다. |
| 세션 탭이 보이지 않음 | 런타임 상태를 확인한 뒤 상단의 **새 세션**을 누릅니다. |
| 앱을 다시 열자 출력이 없음 | 같은 세션 탭을 다시 선택합니다. 진단 화면에서 VM이 실제로 중지됐는지 확인합니다. |
| 포트가 표시되지 않음 | 게스트 프로세스가 실제로 리스닝 중인지 확인하고, `droid-port-agent` 서비스 상태를 확인합니다. |
| Android 기능이 거부됨 | 콘솔의 Android 접근 권한과 Android 시스템 권한을 모두 확인합니다. |

## 9. 보안 주의사항

Linux 게스트는 신뢰하지 않는 코드도 실행할 수 있는 환경입니다. Android 권한은 필요한 기능만 허용하고, 공유 디렉터리에 민감한 앱 데이터나 비밀 키를 무분별하게 두지 마세요. 특히 **항상 켜기** 절전 정책은 장시간 작업을 할 때만 사용하세요.

### 공유 내부저장소 접근

**설정 → 터미널 설정 → 내부저장소 접근 설정**에서 Android의
**모든 파일 접근 허용**을 켜거나 끌 수 있습니다. 기본값은 사용 안 함이며,
두 로컬 실행 환경에 공통으로 적용됩니다. 거절하거나 뒤로 돌아오면 기존
권한 상태가 유지됩니다. AVF에는 적용되지 않습니다.

허용 후 새 세션에서 `cd /sdcard`로 이동하면 Download, Documents 등의 공유
파일을 읽고 쓸 수 있습니다. Native에서는 `/storage/emulated/0` 같은 Android
경로도 사용할 수 있고, Rootless에서는 `/sdcard`로 연결됩니다. 기존 Rootless
세션에는 연결이 추가되지 않으므로 필요한 경우 새 세션을 여세요.
다른 앱의 `/data/data/...`와 `Android/data` 등 Android 보호 경로는 열리지 않습니다.

끄려면 같은 항목에서 Android 권한을 해제하세요. Android가 앱과 실행 중인
세션을 종료할 수 있으므로 먼저 작업을 저장하세요. 권한을 사용하지 않아도
기존 앱 전용 저장소와 `/workspace`는 계속 사용할 수 있습니다. 접근을 꺼도
Android가 기본적으로 허용하는 앱 소유 공유 파일 접근까지 없애는 것은 아닙니다.


### 툴바 설정

**설정 → 터미널 설정 → 사용자 설정 → 툴바 설정**에서 하단 툴바를 켜거나 끕니다.
핸들을 위아래로 드래그하여 **확장 / 기본 / 숨김** 상태로 바꿀 수 있습니다.
숨김 상태에서도 핸들은 남고, 탭하면 다시 펼쳐집니다. 핸들 탭은 기본 → 확장 → 숨김
순서로 전환합니다. 도구가 여러 개이면 기본·확장 상태에서 좌우로 쓸어 전환합니다.
기본 도구는 **터미널 단축키**입니다. 편집에서 다음 도구도 추가할 수 있습니다.

- **메모리 사용량**: 기기 전체 사용량, 앱 사용량과 세부 영역, 세션별 RSS 추정치를 표시합니다.
  도구 설정에서 **기기 전체 / 앱 사용 메모리 / 세션별 사용량**을 각각 켜고 끕니다. 앱 수치는
  UI와 런타임 서비스 프로세스의 PSS 합계이며 Java·네이티브 힙, 코드, 스택, 그래픽, 기타 전용,
  공유 및 시스템 영역으로 나눕니다. 셸·게스트 메모리는 세션 항목과 별도로 해석합니다. 세션 행을 누르면
  해당 터미널 세션으로 전환하고 입력에 포커스합니다. 도구 설정에서
  갱신 간격을 2·5·10·30초로 선택합니다. 공유 페이지는 중복 집계되고 분리된 데몬은
  누락될 수 있습니다. AVF·접근 제한·종료된 세션은 측정 불가로 표시합니다.
- **명령어셋**: 설정에서 이름과 여러 줄 명령을 추가·수정·삭제합니다. 최대 64개,
  항목당 8,192자를 저장합니다. 툴바에서 이름과 고정폭 명령 미리보기가 표시된 행을 누르고 대상 세션과 내용을 확인한 뒤
  **실행**하면 현재 셸 또는 실행 중인 프로그램에 붙여넣고 Enter를 보냅니다.
  행 오른쪽의 편집 아이콘으로 해당 명령을 바로 수정할 수 있습니다.

- 평소에는 추가한 도구만 보이며 `>`가 있는 항목을 누르면 도구 설정을 엽니다.
- **편집** FAB를 누르면 도구 추가·제거 버튼이 나타납니다. 추가된 도구의 핸들을
  드래그하면 순서가 바뀝니다. 추가되지 않은 도구에는 순서 핸들이 없습니다.
- 변경은 바로 저장됩니다. **완료**를 누르면 일반 목록으로 돌아옵니다.
- 도구를 제거하거나 툴바를 꺼도 단축키 배치는 보존됩니다. 전체 사용을 끄면 핸들도 숨깁니다.
- 기존 단축키 사용 여부는 툴바 사용 여부로 이어받습니다.

### 터미널 단축키 편집

**설정 → 터미널 설정 → 툴바 설정 → 터미널 단축키**에서 배치와 단축키를 편집합니다.

- 툴바의 **드래그 핸들**로 높이를 조절하거나 숨깁니다. 터미널의 두 손가락 스와이프는 툴바를 변경하지 않습니다. 핀치 글자 크기 조절은 그대로 사용할 수 있습니다.
- 단축키 표시 여부는 **툴바 설정**에서 도구 추가·제거로 관리합니다. 단축키 편집 화면의 **저장**은 배치만 변경합니다.

- 미리보기의 단축키를 **꾹 누른 채 드래그**하면 삽입 위치가 선으로 표시되고, 대상이 바뀔 때 진동합니다. 원하는 위치의 선에 놓으면 순서가 바뀝니다. 화면 위아래 가장자리에 머무르면 자동으로 스크롤됩니다. 그리드 밖에 놓으면 이동을 취소합니다. 순서 변경도 아래 **저장**을 눌러야 적용됩니다.
- 키 높이는 40dp로 고정되며, 최대 열 수와 글자 크기를 조절합니다. 툴바는 기본 상태에서 두 줄까지 표시하며, 펼치면 확장된 영역을 사용하여 더 많은 행을 표시합니다. 표시 영역을 넘는 행은 세로 스크롤합니다. 단축키 영역의 위아래 스크롤 경계에는 그라데이션을 표시하지 않습니다. 미리보기의 키를 누르면 이름과 개별 너비(1~4칸)를 변경하고 **앞으로/뒤로** 이동하거나 삭제할 수 있습니다.
- **단축키 추가**에서 원하는 이름(1~32자)과 조합을 지정합니다. 예를 들어 이름을 `중단`, 조합을 `CTRL+C`로 저장하면 버튼 한 번으로 Ctrl+C를 보냅니다. 기존 키의 조합도 같은 방식으로 대체할 수 있습니다.
- CTRL, ALT, SHIFT와 영문자·숫자·기호 또는 TAB, ENTER, ESC, 방향 키(UP/DOWN/LEFT/RIGHT), HOME/END, PAGEUP/PAGEDOWN, BACKSPACE/DELETE/INSERT, F1~F12를 조합합니다. 공백은 SPACE, 더하기 기호는 PLUS로 입력합니다. 예: `CTRL+SHIFT+TAB`, `ALT+LEFT`.
- CTRL 또는 ALT만 지정한 버튼은 다음 키에 적용되는 보조 키입니다. 조합 버튼은 미리 선택된 보조 키를 대체합니다. 이는 터미널 입력이며 Android 앱의 복사/붙여넣기 단축키나 여러 명령을 실행하는 매크로가 아닙니다.
- 화살표·Backspace·Delete·Page Up/Down 버튼은 길게 누르면 400ms 뒤부터 60ms 간격으로 반복 입력됩니다. 해당 키를 사용하는 조합 버튼도 반복됩니다. 짧게 누르면 한 번만 입력하며, 손을 떼거나 터치가 취소되거나 세션 탭·앱을 전환하면 반복이 멈춥니다. 설정 화면의 길게 누르기는 기존 순서 변경 동작입니다.
- 설정 화면 아래 **저장**을 누르면 적용됩니다. 취소하면 저장된 툴바가 유지됩니다. **기본 배치 복원**도 저장해야 적용됩니다.
- 최대 48개까지 추가할 수 있으며 마지막 키는 삭제할 수 없습니다. 좁은 화면에서는 터치 크기를 유지하도록 열 수가 줄어들고, 긴 툴바는 위아래로 스크롤할 수 있습니다.

## 터미널 안에 이미지 표시

Sixel과 kitty 이미지 출력, 애니메이션, Unicode placeholder, 상대 배치와
잘라내기를 사용할 수 있습니다. Rootless는 파일·임시 파일·`/dev/shm` 전송도
지원합니다. Native 파일 전송은 해당 런타임의 홈·임시 디렉터리를 포함한
Native 루트 안으로 제한되며 POSIX 공유 메모리는 지원하지 않습니다.
SSH 등 파일시스템이 다른 환경에서는 direct/stream 전송을 선택하세요.
UI 재연결은 살아 있는 런타임이 보관한 이미지·애니메이션·배치를 복원합니다.
이미지 저장 한도를 넘어서 삭제된 이미지나 실제 런타임 종료로 사라진 상태는
복원 대상에 포함되지 않습니다. 테스트 명령과 상세 범위는
[터미널 그래픽 문서](TERMINAL_GRAPHICS.md)를 참고하세요.

### Kitty 키보드와 창 관리

Kitty 키보드를 사용하는 프로그램은 협상 후 확장 키·키 해제·IME 입력을
받습니다. 설정 → 터미널 설정의 **Kitty 원격 제어**를 켜고 만든 새 세션에서는
같은 실행 환경의 탭을 생성·선택·이름 변경·입력·종료할 수 있습니다.
기본값은 꺼짐이며, 끄면 기존 권한도 회수됩니다. 원격으로 만든 자식 탭에는
권한을 주지 않습니다. 이 권한은 해당 세션에서 실행하는 모든 프로그램에
적용되므로 신뢰하는 작업에만 켜세요. `close-window`는 프로세스도 종료합니다.
지원 명령과 데스크톱 기능과의 차이는 [Kitty 호환성 문서](KITTY_PROTOCOL.md)에 있습니다.

### Codex CLI에서 `/pet`이 지원되지 않는다고 나올 때

Codex CLI 0.153.4에서는 터미널이 Sixel 지원 응답을 보내도 기본
`TERM=xterm-256color` 환경에서 펫 사용을 거절하는 경우를 재현했습니다.
**kitty 그래픽 호환성**을 켠 뒤 새 Rootless 세션에서 Codex를 실행하면
고유한 `KITTY_WINDOW_ID`로 이미지 지원을 감지할 수 있습니다. 별도 PTY에서
해당 버전의 PNG 전송을 확인했으며, Android에서 Codex 자체의 전체 동작을
검증했다는 뜻은 아닙니다. 그래픽 사용에 원격 제어 권한은 필요하지 않습니다.

기존 세션에서는 현재 Codex를 종료한 뒤 다음처럼 실행하는 방법도 있습니다.

```sh
TERM=xterm-sixel codex
```

이 설정은 해당 Codex 실행에 적용됩니다. tmux를 사용 중이라면 먼저 tmux
밖에서 확인하세요. Codex가 실행하는 자식 명령도 이 값을 상속하므로,
`unknown terminal` 오류가 나는 일반 터미널 프로그램은
`TERM=xterm-256color 명령어`로 실행할 수 있습니다. 상세 검증과 범위는
[Codex 펫 호환성 설명](TERMINAL_GRAPHICS.md#codex-cli-pets-capability-detection-compatibility)을
참고하세요.

### 출력이 계속되는 동안 이전 내용 읽기

**터미널 설정 → 터미널 기록 → 부드러운 스크롤**을 켜면 손가락 이동과
관성 스크롤을 한 줄보다 작은 픽셀 단위로 표시합니다. 기본값은 꺼짐이며
터미널로 돌아오면 적용됩니다. 마우스 보고나 대체 화면을 사용하는 터미널
프로그램은 기존 행 단위 입력을 유지합니다. 스크롤 햅틱은 별도 설정을 따릅니다.
기록의 맨 위·아래에 가까워져도 남은 거리 때문에 관성 스크롤이 느려지지 않습니다. 스와이프 세기에 맞춰 이동하다가 실제 끝에 도달하면 멈춥니다.

위로 스크롤하면 펫 애니메이션이나 새 출력이 와도 읽던 내용을 유지합니다.
맨 아래로 직접 내려가거나 키보드 입력·붙여넣기를 하면 최신 출력을 다시
따라갑니다. 다른 탭으로 전환했다가 돌아와도 읽던 위치를 유지하며, 기록
한도를 넘어 사라진 내용은 남아 있는 가장 오래된 위치까지만 유지됩니다.
설정 화면이나 다른 앱으로 잠시 이동했다가 돌아오는 동안에도 화면 쪽 터미널
모델을 유지하므로, 복귀할 때 전체 기록을 다시 재생하지 않고 최신 상태를 즉시
표시합니다. Android가 앱 프로세스를 종료한 경우에는 런타임에 다시 연결해
상태를 동기화합니다.

### 터미널 색상 팔레트

**터미널 설정 → 사용자 설정 → 전체 화면 TUI 배경색 따르기**를 켜면 Neovim처럼 alternate screen을 사용하는 전체 화면 앱의 주 배경색에 앱 바·탭·툴바와 터미널 여백이 맞춰집니다. 글자·아이콘과 시스템 표시줄 아이콘도 배경에 맞는 대비로 바뀝니다. 기본값은 꺼짐이며, 앱을 종료하거나 옵션을 끄면 현재 세션의 팔레트 배경색으로 돌아옵니다. 여러 색의 분할 창에서는 가장 넓게 쓰이는 배경색을 따르며, 일반 셸 화면에는 적용하지 않습니다.

**터미널 설정 → 사용자 설정 → 터미널 모양 → 팔레트**에서 기본 팔레트를 고르거나
**팔레트 색상 편집**으로 전경·배경·커서와 표준/밝은 ANSI 16색(검정, 빨강, 초록,
노랑, 파랑, 마젠타, 시안, 흰색)을 `#RRGGBB` 값으로 직접 저장할 수 있습니다.
저장하면 사용자 지정 팔레트가 선택되고, 열려 있는 터미널에도 돌아올 때 적용됩니다.

### Rootless 기본 환경 보완

Debian은 표준 우선순위 패키지, Ubuntu는 공식 Server 기본 메타패키지,
Arch Linux ARM은 `base`를 따릅니다. 세 배포판에 동일한 개발 도구 묶음을
강제로 설치하지 않습니다. 최초 준비에는 인터넷과 Debian/Arch 2 GiB,
Ubuntu 4 GiB 이상의 여유 공간이 필요합니다.

기존 이미지도 **환경 보완**으로 패키지 설치·설정·검증을 진행합니다.
사용자가 만든 홈 설정과 기존 시간대·로케일을 보존하고, 없는 셸 설정은
해당 이미지의 원본에서 복원합니다. 실행 중인 해당 배포판 세션을 먼저
명시적으로 종료해야 하며, 다른 배포판의 세션은 계속 사용할 수 있습니다.
실패하면 원인을 확인하고 재시도하거나 이미지를 제거할 수 있습니다.
준비가 끝난 뒤 새 셸을 열 때마다 패키지를 업데이트하지는 않습니다.
PRoot에서는 서버 패키지가 설치되어도 systemd 부팅이나 커널 권한을 얻지는 않습니다.

가속 통합 개발 채널 APK의 stdio 버퍼링 지원 조건과 명령별 켜기·끄기는
[Rootless 파일 I/O 실험 옵션](ROOTLESS_IO_OPTIONS.ko.md)을 참조하세요.
공개 `v0.1.0-rootless.1`에는 이 옵션이 포함돼 있지 않습니다.

### 기존 Rootless 설치의 가속 적용

하드링크 에뮬레이션 가속을 포함한 버전에서는 업데이트 후 **새 세션부터 기존 저장
형식 그대로 가속**합니다. 네이티브 하드링크 생성이나 별도 이전, 앱·배포판 재설치는
필요하지 않습니다. 기존 패키지·홈·작업 폴더와 링크 구조는 그대로 보존합니다.
이 변경 이전 버전 `0.1.0+dev.1000028.09afdf17440b`까지는 해당 동작이 없습니다.

이전 버전에서 실제 이전 작업이 중단되어 임시 상태가 남은 경우에만
**설정 → Rootless Linux → 해당 배포판 → 중단된 이전 복구**가 표시됩니다.
모든 세션과 공유 작업 폴더의 외부 쓰기를 끝낸 뒤 복구하세요. 새 하드링크를 만드는
변환을 다시 시작하지 않고 기존 트랜잭션만 복구합니다. 표시 파일을 직접 수정하지 마세요.

업데이트 전 진행 중인 작업을 저장하세요. Android가 앱 프로세스를 종료하면 기존
세션의 프로세스 상태를 복원할 수 없습니다. 성능과 시험 범위는
[하드링크 에뮬레이션 가속](ROOTLESS_EMULATED_ACCELERATION.md)을 참조하세요.

### Rootless 설치 진행 확인

Debian·Ubuntu·Arch 모두 설정 화면과 설치 창에서 현재 작업을 확인할 수 있습니다.
이미지 다운로드 → 검증·압축 해제 → 패키지 목록 갱신·다운로드·설치 → 기본 설정
→ 최종 동작 검증 순서로 표시합니다. 기존 환경 보완에서는 이미지 단계를 건너뜁니다.

다운로드 용량이나 패키지 관리자가 알려주는 진행률이 있으면 프로그레스바와
**현재 단계 %**를 표시합니다. 전체량을 모르는 작업은 움직이는 진행 표시와
경과 시간을 보여줍니다. 100%는 해당 단계의 완료이며 전체 설치 완료는 **준비됨**으로
확인합니다. 오래 새 보고가 없으면 마지막 진행 보고 이후 시간도 표시합니다.
화면을 나갔다 돌아와도 같은 설치 단계와 경과 시간이 유지됩니다.

### 설정 검색

설정 홈의 검색은 메뉴 이름뿐 아니라 하위 화면의 개별 설정 이름·설명·경로도
찾습니다. 예를 들어 **글꼴 크기**, **스크롤백**, **단축키**, **팔레트**를 검색하면
해당 항목과 상위 설정 경로가 표시됩니다. 공백으로 여러 검색어를 입력하면 모두
포함하는 결과를 찾으며, 영문 대소문자는 구분하지 않습니다.
결과를 누르면 관련 설정 화면으로 이동하고, 일반 설정은 해당 섹션부터 표시합니다.
프로필별 항목은 먼저 프로필 목록에서 편집할 프로필을 선택합니다. 검색 결과 선택만으로
설정값을 바꾸거나 권한 요청·설치·삭제를 실행하지 않습니다. 검색을 지우면 기존 홈 메뉴로 돌아갑니다.
