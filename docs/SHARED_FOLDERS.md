# Shared Directory

## Ownership and compatibility

Workspace Manager owns logical session groups. Environment owns runtime identity and private storage. Shared directories own explicit file sharing at `files/shared-folders/<UUID>`, independent of both. Names are bounded ASCII mount components; renaming never moves the UUID directory. One folder can connect to several Environment UUIDs. Settings → Shared Directory manages names, connections and explicit data deletion through the existing UI-authorized `:vmhost` service. Connections apply to new sessions; Workspace creation, selection and deletion never change filesystem bindings.

The settings list opens separate non-exported `SharedFolderCreateActivity` and `SharedFolderEditActivity` screens for creation and existing entries. Editing addresses the original folder UUID and initializes its draft once from the runtime projection. The common editor retains that UUID, name, connection selection and field dialog across Activity recreation; reconnecting only refreshes access information. The name dialog uses Confirm to update the draft; whole-page Save alone applies it through the existing `saveSharedFolder` Binder API and returns to the list on success. The edit Activity also owns the AVF copy dialog and submits the same bounded runtime operation before returning to the list for progress/cancellation. Missing directories cannot be recreated implicitly by the editor. Each Activity detaches only its own service binding when stopped; folder data, sessions and runtime-owned file operations remain owned by the service.

Native receives a JSON name-to-host-path map in `TERM_SHARED_FOLDERS`. Rootless snapshots connected folders for each launch and retains directory FDs for bindings at `/mnt/term-shares/<name>`. Native and Rootless see the same files. Existing sessions retain their launch paths after rename/disconnection. The connection list is convenience and AVF transfer authorization, not Android UID isolation: Native and PRoot share the app UID. No entire app-private directory is added as a shared binding. Scoped file-copy APIs walk pinned directory descriptors with `openat` and `O_NOFOLLOW`, reject special files and hardlinked leaves, and publish with `RENAME_NOREPLACE`.

The old special `/workspace` binding and automatic host `workspace/` creation are retired. A user-created guest `/workspace` is an ordinary rootfs directory. Fixed legacy paths remain only for existing data, backup compatibility and storage-migration recovery. Originals are never automatically moved or removed. Environment deletion retains an old UUID workspace **in place**, tombstones its Environment/Storage and exposes the remaining directory as retained data. Pending Environment restore reservations are excluded from retained-data discovery, including after staged files have been promoted but before registration commits. Workspace symlinks can depend on rootfs or emulated-link backing files, so deletion fails before removing software/home when such links or an interrupted migration exist. Previously retained folders under `retained-workspaces` remain discoverable without another relocation. Legacy common and legacy AVF host folders also remain intact.

Historic migration journals retain their distribution, phase and three root indices. Layouts without old workspace data use an additional `NO_WORKSPACE` marker; recovery handles both forms and never creates a missing workspace. Existing shared-directory metadata and `.termbackup` v1 workspace components remain readable. Restored old workspace data is a legacy source, not a restored automatic mount. Profiles and ordinary links using retired guest paths may need explicit adjustment. Full backups include a user-created rootfs `/workspace`; independent shared directory files and logical Workspace groups are excluded from Environment archives.

## Explicit legacy copies

The settings screen lists environment, common and retained sources separately. Import creates a new unconnected shared directory; export writes a compressed ZIP through Android's document picker. Both stream regular files/directories, retain originals and reject links/special files instead of silently flattening them. Limits are 2 GiB of file data, 100,000 entries and 64 directory levels. Copy permissions use private host defaults; executable bits/link relationships require Full environment backup or an explicit user adjustment. The selected source's actual Environment users must be stopped, with verified idle sessions and no pending storage conversion. A same-UID writer probe supplements the existing preparation leases. Unrelated environments remain usable.

Imports hash the source tree while copying, re-hash it before activation and serialize metadata validation/publication with folder edits. No existing folder or file is overwritten. File jobs belong to the runtime service and publish persisted status/bytes/errors; leaving or recreating the Activity only detaches observation. A pending SAF export retains its selected document/source and request UUID across Activity recreation, then submits after service reconnection; opening the picker cannot silently drop the copy request. Cancellation checks streaming chunks and closes only the job's own connection/document. Raw vsock closure shuts down both socket directions before releasing the descriptor, so blocked kernel I/O wakes promptly. Runtime restart marks interrupted jobs for explicit retry and removes unpublished job-owned temporary data. A completed metadata commit protects its imported folder from cleanup. Shared directory data deletion is a separate explicit confirmation and conservatively requires all session owners idle, no active file jobs and no detected host writers.

## AVF copies, not mounts

Virtiofs is not implemented as a supported live mount. AVF offers explicit single-file import/export through the existing selected VM driver and the guest `droid-agent --file-transfer` endpoint on vsock 40505. `droid-file-transfer.service` runs as non-root `droid`, accepts only host CID 2 and permits paths under `/home/droid/term-transfers/<directory-name>/<relative-path>`. Host requests must have a current folder connection to that Environment UUID. The storage preparation lease excludes deletion/installation of that VM during its transfer. Permission revocation cancels that folder's transfers; host publication rechecks the connection under the registry lock. Guest messages never contain host paths or select another VM.

TFT1 framing, streaming SHA-256, no-follow directory/file opens, fsync and atomic no-replace publication are specified in [PROTOCOL.md](PROTOCOL.md#explicit-guest-file-copies-tft1). Files are limited to 64 MiB, host jobs to 120 seconds, guest socket I/O to 30 seconds and concurrent jobs to two. Traversal, symlinks, hardlinks, special files, oversized/truncated/corrupted streams and existing destinations fail. Cancellation/disconnection preserves originals and existing destination files. A verified new copy can remain if acknowledgement fails after commit; retry never overwrites it. Rename or disconnection does not rename/delete previous guest copies. There is no automatic synchronization, VM startup or image replacement. Older installed images without TFT1 report unsupported connection/protocol behavior; use a newly provisioned image with this guest service.

## Validation boundaries

JVM tests cover registry isolation, path/name validation, deletion preservation before software removal, ordinary guest workspace backup, framing and legacy migration recovery. Rust tests exercise the guest's actual framed copy/extraction paths, integrity, hardlink/symlink rejection, limits and no-overwrite publication. Android instrumentation exercises real JNI directory capabilities, Native/PRoot access to identical bytes, launch-snapshot bindings, UI recreation, legacy copy/deletion retention and simulated guest cancellation/corruption/revocation. Image-factory tests check installation/enabling of the non-root guest service. A provisioned privileged AOSP/ARM64 target is still required to validate an actual AVF vsock transfer; a stock Android emulator cannot establish that result.
