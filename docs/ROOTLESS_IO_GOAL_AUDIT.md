# Rootless I/O 2배 목표의 현재 증거와 설계 선택

작성일: 2026-09-19. 목표는 미달성이다. 이 문서는 완료 조건을 완화하거나
새 목표를 대신 설정하지 않는다. 추가 성능 측정 없이 저장소의 검증 결과를
검토한 기록이다.

## 완료 조건과 증거

| 요구 | 현재 증거 | 판단 |
| --- | --- | --- |
| 순차 읽기 2배 | 동일 64KiB raw read에서 후보와 기존 PRoot 차이가 작음 | 미달성 |
| 순차 쓰기 2배 | 동일 64KiB raw write에서 후보와 기존 PRoot 차이가 작음 | 미달성 |
| 동기 쓰기 의미 유지 | fflush/fsync와 내용 검증 통과, fsync를 생략하지 않음 | 정확성 확인, 속도 목표 미달성 |
| 실제 파일 작업의 큰 개선 | 작은 파일 조회 등은 기존 가속 효과가 있으나 최신 rename 추가 이득은 원래 mutations 작업에서 약 1.6% | 전체 2배의 증거 아님 |
| 실제 런타임 적용 | stdio는 명시적 APK 옵션, 새 Ubuntu/Debian 설치·유지보수·PTY 검사 통과 | 제한된 통합 검증 통과, 기본 활성화 아님 |
| 일반 기기 적용 | API35 ARM64 redroid/ext4에서 검증 | 실제 휴대폰·cold I/O·모든 앱 보장은 미검증 |

근거: [순차 I/O 원시 결과](../tools/rootless/io/sequential-headroom-2026-09-19.json),
[stdio 구현·프로그램·새 설치 검사](../tools/rootless/io/STDIO.md),

## 추적 비용 제거만으로 설명할 수 없는 차이

동일 바이너리·동일 UID·64MiB 파일·64KiB 요청의 기존 기록에서 중앙값을
다시 계산했다. 이 검사는 host root `/`를 사용해 엔진 비용을 분리한 것으로,
완전한 배포판 실행이나 실제 휴대폰의 하한을 입증하는 검사는 아니다.

| 동작 | 네이티브 ms | 기존 PRoot ms | 기존 시간의 절반 ms |
| --- | ---: | ---: | ---: |
| 읽기 | 7.590 | 7.787 | 3.893 |
| 쓰기 | 12.565 | 12.637 | 6.319 |
| 마지막 fsync | 1234.580 | 1248.643 | 624.321 |

네이티브 비용을 그대로 둔다는 가정에서 기존 PRoot/네이티브 비는 각각
1.026, 1.006, 1.011이다. 따라서 이 자료에는 **추적 비용 제거만으로 2배를
달성할 여유가 나타나지 않는다**. 측정 변동과 구현 변경 가능성이 있으므로
이 비율을 물리적 상한이나 모든 재설계의 불가능성 증명으로 쓰지 않는다.

4KiB stdio 전송의 2배 이상 결과를 원래 64KiB raw 작업에 대입하지 않는다.
실제 프로그램 비교에서 추가 버퍼 효과는 sed 약 1.13배, wc/gzip 거의 동일이었다.
경로 읽기 묶음 후보도 원격 읽기를 줄였지만 원래 작업이 빨라지지 않아
빌드 경로에서 제외했다. 같은 조건의 측정을 계속 반복하는 것은 남은 목표를
해결하는 구현 전략이 아니다.

## 현재 범위와 다음 검증

2026-09-20 사용자 지시에 따라 배포판 내부를 변경하지 않는 개선을 우선한다.
내부 수정이 유의미한 성능 향상을 보일 경우에만 선택 기능으로 검토하고,
배포판 내부·외부 호환성을 별도로 검증한다. 프로그램 수정이나 전용 API
허용을 작업 진행의 필수 조건으로 삼았던 이전 설명은 철회한다.
기존 API를 유지하는 개선도 계속할 수 있으며, 현재 자료는 모든 재설계의
불가능성을 증명하지 않는다. 다만 전체 2배를 약속할 근거도 아직 없다.

기존 stdio 옵션은 배포판 패키지를 교체하지 않고 앱이 제공하는 DSO를
게스트에 주입한다. 이 방식도 관찰 가능한 버퍼링 동작을 바꾸므로 호환성
검증 대상이다. 2026-09-20 추가 동작 검사는 Ubuntu와 Debian에서 옵션
꺼짐/켜짐 모두 통과했다. 범위와 미검증 항목은
[stdio 검증 기록](../tools/rootless/io/STDIO.md#behavioral-compatibility-gate-2026-09-20)에 기록한다.
이 검사는 새로운 성능 결과가 아니며, 원래 raw 순차 I/O 기준을 대체하지 않는다.

어느 경우에도 기존 데이터의 무결성을 훼손하거나, fsync를 생략하거나,
완료하지 않은 작업을 성공으로 응답해 수치를 맞추지 않는다. 새로운 저장
방식이나 의미 변경이 필요하면 구체적인 동작과 영향을 별도로 제시한다.

최초 2026-09-19 검토는 로컬 원시 결과와 현재 소스를 사용했다. 기기 상태·외부 API·UI를
새로 검증할 작업이 아니므로 MCP 호출이나 Android 빌드, 성능 재측정은 하지 않았다.
