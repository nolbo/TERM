## 설치·호환성 개선

- 새 Rootless 설치에서 실제 하드링크를 사용할 수 있으면 해당 저장 형식으로 준비합니다.
- Android가 하드링크 생성을 거부하는 경우 심볼릭 링크 기반 호환 형식으로 설치합니다. Ubuntu 설치 중 `.native-link-probe`의 `linked -> original` 단계에서 실패하던 경우를 처리합니다.
- 저장 형식 표시가 없는 기존 배포판은 기존 링크 에뮬레이션을 유지합니다. 업데이트만으로 배포판 데이터나 패키지 DB를 강제로 변환하지 않습니다.
- 손상됐거나 알 수 없는 저장 형식 표시는 오류로 알리며 임의 덮어쓰기를 하지 않습니다.

## 가속 형식 이전과 빌드 차이

기존 패키지·홈·작업 폴더를 유지하며 에뮬레이션 링크를 실제 하드링크로 바꾸는 수동 이전 기능과 중단 복구 처리가 추가됐습니다. 모든 터미널 세션이 종료된 상태에서만 실행하며, 디렉터리 권한·수정 시각을 보존합니다.

**이 개발 채널의 일반 자동 빌드는 실험적 가속 프로필과 stdio 버퍼링을 활성화하지 않습니다.** 따라서 일반 dev APK에는 ‘가속 형식으로 이전’ 버튼이 표시되지 않습니다. 이 기능을 사용하려면 가속 기능을 포함해 빌드·검증한 별도 APK가 필요합니다. 이번 일반 dev APK를 설치한 것만으로 가속 실험에서 측정한 성능을 얻는다고 해석하지 마세요.

이미 가속 형식을 사용하는 배포판의 파일 형식은 유지되지만, 일반 dev APK에서는 전용 가속 라이브러리가 적용되지 않습니다. 공개된 `v0.1.0-rootless.1` APK에는 이후의 Ubuntu 설치 오류 수정과 수동 이전 기능이 포함되지 않습니다.

## 업데이트 방법과 제한

- 앱을 업데이트하기 전에 실행 중인 작업을 저장하세요. Android가 업데이트 과정에서 프로세스를 종료할 수 있으며, 종료된 세션을 복원하는 기능은 아닙니다.
- 일반 호환 실행을 위해 앱이나 배포판을 삭제할 필요는 없습니다. 저장 형식 표시 파일을 직접 수정하지 마세요.
- 가속 형식 이전에는 기기의 실제 하드링크 지원이 필요합니다. 지원하지 않거나 링크 구조가 불명확하면 기존 설치를 보존하고 실패를 알립니다.
- PRoot의 커널·systemd·mount·namespace 제한은 유지됩니다. 새 Android 특권이나 권한은 요구하지 않습니다.
