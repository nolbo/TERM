# rootless-runtime-20260920-emulated.1

- 준비일: 2026-09-20
- 공개일: 미정 — 로컬 검증 완료, 아직 게시하지 않은 런타임 입력
- 대상: ARM64 Rootless PRoot, loader, faststat/stdio DSO 및 재현 소스. APK 출시와는 별도다.

기존 저장 형식을 유지한 채 가속을 적용하도록 변경했다. 일반 Android에서 금지되는
실제 하드링크 생성을 가속의 필수 조건에서 제거했다. 앱 통합 변경을 포함한 새 APK로
업데이트하면 기존 패키지와 파일을 변환하지 않고 새 세션에 적용할 수 있다.

- 에뮬레이션 하드링크의 링크 수와 열린 파일 처리를 유지하면서 일반 파일 조회·열기·
  생성·닫기를 가속한다. 마지막 링크 삭제 뒤 열린 FD의 fstat 실패도 수정했다.
- Android에서 차단될 수 있는 openat2를 제거하고 요소별 no-follow openat로 경로를 검사한다.
- unlink 진입 처리와 rename 경로 복사를 최적화했다. 지원하지 않는 경로는 기존 처리로 돌아간다.
- 공유 프로토콜 버전 5에 맞는 엔진/DSO를 함께 고정한다. 과거 파일과 혼용하지 않는다.
- Android 권한·SELinux·seccomp를 해제하거나 우회하는 설정 변경은 없다.
- 앱의 기존 이전 IPC는 중단된 변환 복구만 수행하도록 변경한다. 재설치/새 변환은 필요 없다.

검증: 앱 빌드, runtime 160개·app 74개·image 4개 테스트, Python 입력/업데이트 테스트
19개 통과. 선택적 외부 압축 파일 테스트 1개는 입력 미지정으로 미실행.
API 35 redroid에서 Debian/Ubuntu 하드링크 생성 거부 주입 설치, 기존 형식 보존,
가속 카운터·PTY·패키지 설치/업그레이드/삭제·openat2 금지·파일 회귀 시험을 통과했다.
별도 앱에서 복구 버튼 표시와 복구 후 저장 형식 미변경을 확인했다.

측정상 가속 전 대비 파일 정보 조회 2.96배, 작은 파일 읽기 3.52배. 이전 네이티브
가속보다 파일 변경 묶음은 약 30%, tar는 약 16% 느리다. 순차 I/O 개선은 없다.
삼성 SM-S947N Android 17 실기기와 enforcing SELinux 환경은 아직 검증하지 않았다.
기존 PRoot의 에뮬레이션 backing 파일이 디렉터리 재포장에 노출되는 문제는 남는다.
자세한 조건·결과·재현은 [검증 보고서](../ROOTLESS_EMULATED_ACCELERATION.md)를 참조한다.

게시 전 로컬 입력은 `package-runtime.py`로 생성하고 `prepare-release-runtime.py
--assets-directory`로 검증한다. 공개 입력 게시 전에는 이를 다운로드하는 채널 CI를
실행할 수 없다. 사용자 앱 업데이트를 제공하려면 이 입력 게시와 APK 릴리스가 필요하다.
