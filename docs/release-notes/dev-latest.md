- 대상: TERM Android ARM64 APK, Rootless Debian·Ubuntu
- 변경 범위: 일반 dev 배포 `951bc7b1bf71` 이후. 이전 일반 dev 배포의 노트는 별도 보존합니다.

## 이번 APK에서 활성화한 기능

- 검증된 PRoot 엔진과 guest glibc 가속 라이브러리를 실제 APK에 포함하고, 새 세션·패키지 준비에 가속 프로필을 적용합니다.
- stat, open, 파일 생성·삭제, 제한된 close, identity, TCGETS, 권한 처리 가속과 최종 rename 중복 경로 복사 제거를 함께 사용합니다.
- Debian의 서비스 소유 NSS 캐시를 사용합니다. 데몬 실패 시 직접 조회로 돌아갑니다.
- 일반 파일용 stdio 버퍼링을 활성화합니다. 명시적 flush/fsync를 대체하지 않으며, 모든 프로그램이나 순차 I/O에서 같은 성능 향상을 보장하지 않습니다. 필요한 명령에서는 `PROOT_STDIO_BUFFER=0 명령`으로 끌 수 있습니다.
- 기존 배포판의 **가속 형식으로 이전** 기능을 활성화합니다. 패키지·홈·작업 폴더를 유지하며 에뮬레이션 링크를 실제 하드링크로 변환합니다. 실패·중단 복구와 디렉터리 권한(sticky/setgid 포함) 보존 처리가 포함됩니다.
- Ubuntu에서 하드링크 지원 검사 실패 시 호환 형식으로 설치하는 수정도 유지합니다.

## 기존 설치에서 사용하는 방법

1. 실행 중인 작업을 저장하고 앱을 업데이트합니다.
2. 앱의 모든 터미널 세션과 작업 폴더의 외부 파일 작업을 종료합니다.
3. **설정 → Rootless Linux → 해당 배포판 → 가속 형식으로 이전**을 선택합니다.
4. 완료 후 새 세션을 시작합니다. 이미 가속 형식인 설치에는 별도 이전이 필요하지 않습니다.

앱이나 배포판을 삭제할 필요는 없습니다. 업데이트만 하면 기존 호환 형식을 유지하므로 수동 이전이 필요합니다. 기기가 실제 하드링크 생성을 허용하지 않으면 기존 설치를 보존하고 오류를 알립니다. 지원하지 않는 기기에서는 호환 실행을 유지하며 전용 가속은 적용하지 않습니다.

## 배포 검증과 보안

CI가 고정된 SHA-256으로 엔진·로더·결합 DSO와 재현 소스를 확인합니다. 이 세 파일은 재차 심볼을 제거하지 않고 검증된 바이트 그대로 패키징합니다. 가속 또는 stdio 옵션이 누락되거나 서명 APK의 런타임 파일이 다르면 배포를 실패시킵니다. 런타임은 APK에 포함되며 설치된 앱이 실행 파일을 외부에서 내려받지 않습니다. 한국어 노트와 Rootless 재현 소스를 APK 릴리즈에 함께 제공합니다.

새 Android 특권은 요구하지 않으며 syscall의 seccomp 제한과 기존 세션 수명 정책을 유지합니다. ptrace·fake-root·systemd·mount·namespace 제약은 그대로입니다.

## 검증 범위와 제한

- 최종 가속+stdio+rename 구성으로 APK 빌드, 앱·runtime·image 단위 검사 통과.
- 이전 단계에서 Debian·Ubuntu의 패키지 DB 보존·마이그레이션·PTY, Android의 권한 보존·중단 복구, 설정 버튼 동작을 검증했습니다.
- `terminal-usb` Python 48개·USB 런타임 46개 검사 통과. 최종 조합의 격리된 Android Debian에서 Native 및 Rootless 이전 전·후 모의 통신과 마이그레이션 복구를 재검증해 `OK (2 tests)`로 통과했습니다.
- 실제 휴대폰 전체, Arch, 전원 차단, 실제 USB 주변기기 전송은 미검증입니다. 가속 수치는 특정 시험 환경의 결과이며 전체 앱이나 모든 I/O의 2배 향상을 보장하지 않습니다.

첫 가속 CI에서는 빌드·USB 검사가 통과했지만 최종 APK의 런타임 해시 차이로 게시를 차단했습니다. 패키징 중 심볼 제거를 방지하고 디버그 APK에서도 같은 해시 검사를 실행하도록 보완했습니다. 수정 후 로컬 디버그·서명 전 Release APK의 세 런타임 파일 해시가 모두 검증 입력과 일치했습니다.
