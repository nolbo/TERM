# TERM 개발 채널 — 하드링크 전환 없이 Rootless 가속

- 릴리즈 ID: `dev-latest` (APK는 `dev-<빌드 커밋 SHA>`의 고정 릴리즈에 게시)
- 출시일: 2026-09-20
- 대상: TERM Android ARM64 APK, Rootless Debian/Ubuntu, PRoot/faststat/stdio 런타임
- 변경 범위: 이전 공개 개발판 `dev-09afdf17440bed2e3925b52be694dbf07699abc9` 이후
- 런타임 입력: `rootless-runtime-20260920-emulated.1`, 엔진/DSO 공유 ABI 8

## 변경 사항

- 실제 하드링크를 만들 수 없는 기기에서도 기존 에뮬레이션 저장 형식을 유지하며 파일 작업을 가속합니다. 가속을 위한 별도 하드링크 전환은 필요 없습니다.
- 신규 Debian/Ubuntu 설치의 하드링크 시험이 거부되면 심볼릭 링크 기반 저장 형식을 사용합니다. 기존 설치의 패키지와 파일을 다시 쓰지 않습니다.
- 일반 파일 조회·열기·생성·닫기, statx 및 디렉터리 FD 기준 상대 경로 조회를 개선했습니다. ls/du 등 파일 목록 작업에도 적용됩니다.
- 경로 복사, 반복 파일시스템 검사, 경로 규칙 재게시, rename/unlink의 불필요한 처리를 줄였습니다.
- 조건을 충족하는 단독 FD 테이블에서는 fstat의 실제 경로 확인을 한 번으로 줄입니다. 신호, FD 공유, 비동기 작업, 게스트 필터 등의 조건 변화에는 보수적인 처리로 돌아갑니다.
- Android에서 거부될 수 있는 openat2 의존성을 제거했습니다. 기존 stdio 버퍼링과 하드링크 에뮬레이션의 링크 수·열린 파일 처리를 유지합니다.
- 가속 전환 기능은 중단된 이전 작업의 복구 용도로 정리했습니다. 운영체제 권한이나 SELinux/seccomp 정책을 해제하지 않습니다.

## 업데이트 방법

기존 앱에 업데이트 설치한 뒤 새 Rootless 세션을 시작하세요. 앱 삭제, 배포판 재설치, 새 저장 형식으로의 이전은 필요 없습니다. 설치 프로그램이 앱을 종료할 수 있으므로 업데이트 전 진행 중인 작업을 저장하세요. 이전에 중단된 전환 기록이 있는 경우 복구 안내를 따르세요.

## 성능과 알려진 제한

API 35 ARM64 redroid·Ubuntu·warm cache 조건의 최종 빌드에서 작은 파일 5,000개 읽기 중앙값은 216.92ms였습니다. 이전 하드링크 가속 기준 168.30ms보다 28.9% 더 걸립니다. 전체 동등 성능 목표는 아직 달성하지 못했습니다.

최종 경계 조건 수정 직전 후보의 전체 비교에서는 ls/du가 이전 하드링크 기준보다 빨랐지만 조회·읽기·변경·tar·find는 느렸습니다. 이를 최종 APK 전체 실측으로 해석하지 마세요. 삼성 SM-S947N·Android 17과 enforcing SELinux 환경의 실기기 검증은 아직 하지 못했습니다. 기존 PRoot 에뮬레이션 backing 파일이 디렉터리 재포장에 노출되는 제한도 남습니다.

개발 과정의 계측기, 신호 주입 코드, 미채택 캐시/세대 실험은 생산 런타임에 적용하지 않았습니다. 이 릴리즈는 검증된 구현만 포함합니다.

## 검증

- 로컬 canonical 앱 빌드/runtime/image 검증 성공. 최종 수행에서 변경 없는 단위 검사는 UP-TO-DATE로 재사용했습니다. 앞선 앱·runtime 단위 검사에서 app 74개, runtime 160개 통과 및 선택적 검사 1개 생략을 확인했습니다.
- 업데이트/런타임 입력 Python 검사 19개 통과. 런타임 아카이브 및 APK의 엔진·로더·combined DSO 해시 검증 통과.
- API 35 Android 시험 환경에서 두 저장 형식의 파일·FD·신호·스레드·fork/exec·메모리 경계·별도 dpkg 설치/업그레이드/삭제 검증 통과. 일부 statx/dirfd/storage 검사는 마지막 prctl 정수 폭 보완 전 후보에서 수행했습니다.
- 개발 중 하드링크 거부를 주입한 Debian/Ubuntu 설치와 기존 형식 보존 검증을 수행했습니다. 사용자의 실제 Android 17 기기에 대한 검증을 대신하지는 않습니다.
- 게시 CI는 앱·runtime·image·업데이트 검사, USB 호스트 안전성 회귀 검사, 서명 APK 생성 및 런타임 해시 검사를 통과해야 공개합니다. 실제 USB 장치·AVF 검사는 이번 릴리즈에서 수행하지 않습니다.
