# Environment backup and restore

## Supported scope and ownership

Data Backup contains Native or Rootless home (including dotfiles), optional Profiles and an optional Workspace. Rootless Full Environment Backup additionally contains the matching Debian, Ubuntu or Arch Linux ARM rootfs and package database. Data restore creates an uninstalled Rootless Environment; installing its distribution remains an explicit operation. Full restore does not download or execute anything during validation. AVF, overwriting existing Environments, schedules, incremental backups and live snapshots are excluded. Android system automatic backup remains disabled.

`EnvironmentBackupJobs` belongs to the existing `:vmhost` runtime service. UI Activities observe persisted operation summaries and submit explicit requests over host-UI-authorized Binder methods. Closing or recreating an Activity does not cancel work. Passwords exist only in memory and are cleared after use; interrupted work is not automatically resumed. Progress reports the current stage, uncompressed bytes and entry count. Cancellation, errors and manual retry are explicit; the final activation commit cannot be cancelled halfway through.

Exports use `SessionStorage` paths and the same `StoragePreparationLocks` admission as preparation, session creation and deletion. The target must have no live sessions; Rootless must be stopped, with no active installation or pending storage migration. Before reading and again before completing the archive, bounded same-UID `/proc` checks reject processes whose mappings, environment, working directory or open descriptors reference the selected storage. Unverifiable live processes fail closed. The operation never signals a process. This is a quiescent backup contract under the app's ownership rules, not a filesystem snapshot against privileged or malicious same-UID writers.

The archive's optional `workspace` component refers only to pre-existing filesystem data, not logical Workspace Manager groups or independent Shared Folders. It is excluded by default; new Rootless Environments do not create that directory or bind it to guest `/workspace`. Including the old app-level common directory requires explicit shared-data acknowledgement and leases/checks for its legacy Rootless users. Restore preserves this v1 component as a private legacy data source; use Settings → Shared Folders to copy/export it. Restore never reinstates the retired `/workspace` binding. Old guest paths in Profiles or ordinary cross-component symlinks may require explicit adjustment after migration. A user-created ordinary guest `/workspace` belongs to rootfs and is included in Full backups, with links mapped to that rootfs path. Shared Folders are excluded from Environment archives. Unrelated independent Environment sessions and installations remain admitted.

## TERM format v1

All integers are big-endian. `.termbackup` is a streamed container, not an arbitrary tar import. The outer header is 41 bytes: ASCII `TERMBACKUP\r\n` (12), version `1` (4), flags (1: plain `0`, encrypted `1`), random salt (16), and random nonce prefix (8). Unknown versions and flags are rejected.

Frames contain a four-byte plaintext length, at most 65,536 bytes of content, and, when encrypted, a 16-byte AES-GCM tag. An empty final frame is mandatory and trailing source bytes are rejected. Password encryption derives a 256-bit AES key with PBKDF2-HMAC-SHA256, 210,000 iterations and the header salt. Each frame's 12-byte nonce is the random prefix followed by its four-byte sequence number; associated data binds the entire header, sequence and frame length. Even the empty final frame is authenticated. The UI defaults to encryption and requires matching passwords of at least eight characters. Plain backups provide corruption detection, not authenticity or confidentiality.

The framed content is exactly one gzip member. Header flags, gzip CRC/length, truncation, concatenated members and trailing compressed data are checked. Expanded content begins with a four-byte length and a UTF-8 JSON manifest (at most 1 MiB). Metadata includes format/version/compression, kind, source Environment/runtime/distribution/storage identity, a legacy-layout flag (including adopted UUIDs), ABI, TERM version, Rootless link storage format, Workspace scope, optional Profiles, creation time, regular-file byte total and entry count. TERM version is informational; format version, ABI, supported runtime/distribution and storage semantics control compatibility. Rootless v1 requires `arm64-v8a`.

Each record starts with a type byte: directory `1`, file `2`, symlink `3`, hardlink `4`, end `0`. Non-end records contain a length-prefixed UTF-8 component path, four-byte Unix permission bits and eight-byte modification time in milliseconds. Files add an eight-byte size and exactly that many bytes. Link records add a length-prefixed component target. Hardlinks reference a preceding regular-file record with identical metadata. After the end byte, a 32-byte SHA-256 digest covers the header fingerprint and all preceding expanded content, including the end byte. Strict EOF checks cover every layer. Manifest inspection is provisional and does not claim full integrity; restoration verifies the entire file before registration.

## Filesystem semantics and extraction boundary

Only fixed `home`, `rootfs` and `workspace` component roots may enter the archive. Global preferences, capability grants, session checkpoints, processes and scrollback are outside these roots. Temporary/runtime pseudo-filesystems (`tmp`, `var/tmp`, `run`, `proc`, `sys`, `dev`), rootfs `var/cache` and APT lists, home `.cache`, npm/Cargo/Gradle download caches and Trash contents are excluded. Empty directory placeholders retain the original directory metadata. Other application-specific caches cannot be identified automatically.

Regular files stream through bounded buffers; native inode relationships, permission bits and regular-file/directory modification times are preserved. Android's NIO provider cannot set a symlink's own modification time without following it, so link timestamps are best effort; their targets are never modified as a fallback. UID/GID become the destination Android app identity; ACLs, extended attributes and SELinux labels are not imported. Ordinary internal symbolic links are relocated into the new roots without following them during extraction. Guest absolute paths are mapped to their selected component; external host links are rejected. Selecting too little data to preserve a PRoot hardlink group fails explicitly rather than silently changing its meaning.

Rootless native and emulated hardlink storage formats are retained, never converted during import. PRoot `.l2s` backing files, intermediate links, aliases and reference counts are validated as complete groups. Valid bookkeeping links are rebased to the final new UUID host path before activation. Ordinary links within one component remain relative; links across Rootless bind components retain guest absolute paths (`/root`, `/workspace`, `/`) so they work inside PRoot. Relative guest links are interpreted at their original guest location. A separate app-owned data-format pin makes a later base installation retain imported home's link semantics. A destination lacking required native hardlink support fails instead of copying aliases independently.

Extraction rejects absolute/traversing/empty/duplicate paths, symbolic-link parents, unsupported special files, unsafe hardlink targets, inconsistent manifest totals and excessive expansion. Limits are 256 GiB regular-file data, 500,000 entries, 128 path components, 4,096 UTF-8 bytes per path/text and 256 Profiles within the manifest limit. A separate 64 MiB metadata budget charges 512 bytes per entry and four bytes per retained path/link UTF-16 unit, bounding identity/link maps even for highly compressible archives with long names. The same budget applies to export. At least 32 MiB free-space reserve is checked before and during extraction. Provider/device storage exhaustion still produces a normal failed operation. These ceilings are safety limits rather than a promise that every device can restore their maximum.

## New-only activation and recovery

Restoration extracts into a private, operation-UUID staging directory. It verifies checksums, compatibility, component structure and, for Full backups, storage marker, distribution identity, package database and ARM64 ELF headers for the shell/package executable. No imported program runs during these checks. Only then does it allocate fresh Environment and Storage UUIDs; imported Profiles receive new UUIDs and references. Recognized Native host path prefixes in profile launch fields are remapped; arbitrary script contents and startup command text are not rewritten. Imported image icons fall back to the built-in icon because image assets are not archived. Profile import is off by default and requires trusting the source.

The process-shared registry manifest records a pending restore before promotion. Pending storage is excluded from discovery and connection validation. Under the same manifest lock, an atomic rename publishes the tree and one metadata commit registers the Environment, storage, Profiles and completion receipt. Data and containing directories are synced at publication boundaries. A crash before the commit leaves a hidden reservation that the next runtime owner removes; a crash after the commit is recognized from its receipt. A late cancellation or reporting error cannot delete a committed Environment. Cleanup follows no symlinks and touches only operation-owned staging or reserved destination paths.

This retains the existing registry manifest as the single identity source instead of introducing a second catalog. Staging needs space for a complete uncompressed copy; an in-place restore would violate the isolation and failure guarantees. Copying a matching Full rootfs/database is distinct from logical package reprovisioning: package databases are never transplanted alone into an unrelated rootfs.

## SAF and user workflow

Create: **설정 → 실행환경 → 환경 상세 → 백업 만들기**. Choose Data/Full, optional Profiles/Workspace and encryption, then select an independent document with `ACTION_CREATE_DOCUMENT` and explicitly start. Import: **설정 → 백업 및 복원 → 백업 가져오기** uses `ACTION_OPEN_DOCUMENT`, optionally accepts a password, inspects metadata, then explicitly restores a new named Environment. Persistable URI grants allow the runtime owner to continue across UI detach. All paths use `content:` URIs; no broad storage permission is requested.

Backups can contain SSH keys, tokens, shell history and credentials. Users must protect both the file and password; passwords cannot be recovered. Imported configurations can run commands when later launched, so source trust is required. Failed/cancelled exports attempt to delete the incomplete SAF document. A provider may refuse deletion and leave an invalid file that the user must remove. Export retry chooses a new document. Process death marks unfinished operations interrupted and clears their staging; manual retry requests the password again.

## Validation

Runtime unit tests cover encrypted/plain round trips, permissions, native and emulated hardlinks, symlinks, three distribution package databases, profile references, shared Workspace selection, storage-format pins, source isolation, incompatible/corrupt/truncated archives, insufficient space, cancellation, promotion failure and registry crash-window recovery. Adversarial archives exercise path/link attacks, duplicates, special entries, expansion bounds and strict compression/framing checks. Storage-lock tests verify that selected/shared users are excluded while unrelated storage remains usable.

`EnvironmentBackupDeviceTest` validates Android filesystem/provider semantics in an isolated test APK. Its explicit `backupRealRootless=true` mode installs the catalog-pinned Debian base into test-owned storage, installs a local fixture package, round-trips a Full encrypted backup, then exercises the restored shell, `apt-get check`, dpkg query/removal and mutable hardlinks while asserting source isolation. This does not validate Ubuntu/Arch package execution or AVF. UI instrumentation covers the settings entry, independent SAF picker and Activity recreation; live interaction evidence is reported with the task's test results.
