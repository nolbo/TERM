# Rootless 파일 I/O 실험 옵션

2026-09-20 기준 개발용 기능이다. 공개된 `v0.1.0-rootless.1`에는 이 stdio
버퍼링 기능이 포함돼 있지 않다. 환경 변수만 추가해 해당 릴리스에서 활성화할
수는 없다. 앱 설정 화면에 전환 스위치는 아직 없다.

## 지원 조건

stdio 기능이 포함된 실험 APK와 네이티브 하드링크 사용이 검증된 Rootless
설치가 필요하다. Ubuntu·Debian에서 검증했으며 Arch는 미검증이다.
하드링크 에뮬레이션으로 설치된 환경에서는 가속 라이브러리를 주입하지 않는다.
지원 여부를 바꾸려고 설치 형식 표시 파일을 직접 수정하면 안 된다.

이 기능은 배포판의 glibc나 패키지 파일을 교체하지 않는다. 앱이 제공하는
라이브러리를 게스트 실행 시 연결하며, 해당 실험 APK는 새 세션과 설치·유지보수
명령에 버퍼링을 켜서 시작한다. **명령별 선택은 이미 열린 Rootless 셸 안에서
아래처럼 새 프로그램을 실행할 때 적용한다.** 세션 생성 요청의 환경 변수는
앱이 정한 가속 프로필을 덮어쓰지 못한다.

빌드 담당자를 위한 정확한 옵션·라이브러리 검증 조건은
[stdio 빌드 및 검증 기록](../tools/rootless/io/STDIO.md)에 있다.

## 명령별 사용과 복귀

`program arguments`를 실제로 실행할 명령과 인자로 바꾼다.

```sh
# 버퍼링 가속을 끄고 새 프로그램 실행
PROOT_STDIO_BUFFER=0 program arguments

# 버퍼링 가속을 켜고 새 프로그램 실행
PROOT_STDIO_BUFFER=1 program arguments
```

여러 명령이나 파이프라인 전체에 적용하려면 새 셸을 사용한다.

```sh
PROOT_STDIO_BUFFER=0 /bin/sh -c 'command_a | command_b'
```

이 변수만 끄면 다른 PRoot 가속 기능은 그대로 유지된다. `LD_PRELOAD` 전체를
삭제하는 방식은 다른 가속까지 바꾸므로 버퍼링 비교·복귀 방법으로 사용하지 않는다.
명령 앞의 변수 지정은 호출한 셸의 설정을 바꾸지 않으며, 실행한 프로그램의
자식들은 값을 상속한다. 자식이 환경 변수를 제거하거나 다시 지정하면 달라진다.

옵션은 프로세스별 초기화 때 읽는다. 이미 실행 중인 프로그램이나 이미 열린
파일 스트림의 동작을 소급해 바꾸지 않는다. 프로그램 내부에서 환경 변수를
고치는 것만으로 전환됐다고 판단하면 안 된다. 꺼진 상태로 다시 실행할 때는
해당 작업을 정상 종료하고, 위의 `PROOT_STDIO_BUFFER=0` 방식으로 실행한다.
앱 전체나 다른 세션을 종료할 필요는 없다.

## 효과와 호환성 범위

대상은 일부 `fopen/fopen64` 기반 일반 파일 스트림이다. `read/write`를 직접
사용하는 프로그램 전체를 가속하지 않는다. 최대 32개 스트림에 각각 64KiB
버퍼를 제공하며, 파이프·장치·표준 스트림·추가 쓰기 모드·읽기쓰기 혼합 모드
등은 해당 조정 대상에서 제외한다. 정적 링크 프로그램에도 적용되지 않는다.

명시적으로 flush하지 않은 데이터가 다른 프로세스에 보이는 시점은 달라질 수
있다. `fflush/fsync`를 생략하거나 저장 완료를 앞당겨 보고하는 기능은 아니다.
호환성 문제를 의심하면 해당 명령만 옵션을 꺼서 실행한다.

호스트와 Android의 Ubuntu·Debian에서 파일 내용, fflush/fsync, 위치 복원,
EOF 이후 추가 읽기, 큰 파일 오프셋 등 지정된 검사는 통과했다. 전체 패키지,
모든 Android 연동 기능, 실제 휴대폰 전체의 호환성을 입증한 것은 아니다.

기존 특정 4KiB stdio 시험에서는 2배 이상 결과가 있었지만, 실제 프로그램은
sed 약 1.13배, wc/gzip은 거의 차이가 없었다. **전체 순차 읽기·쓰기와 파일 I/O
2배 목표는 아직 달성하지 못했다.** 이 옵션을 켰다는 이유로 모든 작업이
빨라진다고 가정하지 않는다. 자세한 조건과 원시 결과는 위 검증 기록을 참조한다.
