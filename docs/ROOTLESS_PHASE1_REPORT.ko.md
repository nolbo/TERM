## 조건과 재현 자료

- Android API 35, ARM64 redroid, Linux 6.17, ext4, 앱 UID에서 같은 Debian rootfs 사용.
- 기존→개선→개선→기존→기존→개선 순서. 각 작업은 새 Python 프로세스로 실행.
- 파일 1,000개, 순차 I/O 64 MiB, 캐시가 따뜻한 상태. 성능 진단 카운터는 끔.
- 기존: 원본 PRoot와 `--link2symlink`, 가속 DSO 및 nscd 없음.
- 개선: 누적 가속 프로필, native hardlink, 공유 경로/자격 정보, guest DSO,
  별도 tracer에서 nscd 2.41-12+deb13u4 실행. 실제 rootfs의 계정 파일 사용.
- 데몬 시작·종료, 시험 파일 준비·내용 검증·정리 시간은 작업 시간에서 제외.
  guest CPU 값에는 tracer와 데몬 CPU가 포함되지 않는다.
- 48개 작업 실행의 파일 내용 검증 및 종료 상태가 모두 통과했다.
- 원시 측정과 바이너리 SHA-256:
  [phase1-final-2026-09-18.json](../tools/rootless/faststat/results/phase1-final-2026-09-18.json).
- 작업 구현: [workloads.py](../tools/rootless/workloads.py).

초기 예비 측정은 nscd와 모든 작업을 같은 tracer에 넣어 fork가 fastclose를
해제했다. 제품의 별도 데몬 소유 구조와 달라 최종 통계에서 제외했다.
최종 측정은 데몬을 분리하고 작업마다 exec했다. 따라서 fork/스레드 생성 이후
exec하지 않는 장기 프로세스의 성능을 이 결과로 일반화하면 안 된다.

## 개선 내용과 한계

PRoot의 경로 변환과 syscall 왕복을 줄이고, 검증 가능한 경로/FD에는 커널 처리를
활용한다. stat 결과 자체를 오래 캐시하지 않고 공유 경로·자격 정보를 사용한다.
일반 파일/디렉터리 close 가속은 exec로 FD 테이블이 분리된 조건에 한정하며,
fork·스레드 생성 시 다음 exec까지 해제된다. 심볼릭 링크, 지원하지 않는 경로,
seccomp 제한 등은 기존 처리로 돌아간다.

공식 Debian nscd의 passwd/group 공유 캐시로 반복 계정 조회를 줄였다.
서비스가 데몬을 소유하며 소유 파이프 단절 시 tracer와 자식이 정리된다.
데몬 부재 시 직접 NSS 조회를 사용하고, 종료된 데몬은 다음 세션 생성 시 재시작한다.
ARM64 fchmodat2 변환도 수정해 GNU tar의 디렉터리 권한 복원을 검증했다.

실제 휴대전화/F2FS, 차가운 캐시, 전체 앱 시작 시간, 배터리와 장시간 혼합 부하는
이번 최종 측정 범위에 없다. ptrace/fake-root 및 mount·namespace·cgroup·systemd
제약은 남는다. 1차 작업은 여기서 마무리하고 추가 최적화는 별도 단계로 다룬다.
